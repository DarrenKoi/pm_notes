# 03. 제로샷과 퓨샷

## 이 글에서 답할 질문

- Zero-shot과 Few-shot의 `shot`은 무엇을 뜻하나요?
- 설명을 길게 쓰는 것과 예시를 주는 것은 무엇이 다른가요?
- 어떤 업무에 어떤 방식을 사용하면 좋을까요?

## 먼저 한 문장으로 정리해 보겠습니다

> `Shot`은 프롬프트 안에 넣어 주는 **완성 예시의 수**이며, Zero-shot은 예시 없이 지시하고 Few-shot은 몇 개의 예시로 원하는 패턴을 보여 줍니다.

## Zero-shot: 설명만으로 요청하기

Zero-shot(제로샷)은 완성 예시를 제공하지 않고 지시문만으로 작업을 요청하는 방식입니다.

```text
다음 고객 의견을 긍정, 중립, 부정 중 하나로 분류해 주세요.

고객 의견: 배송은 빨랐지만 포장이 조금 찌그러졌습니다.
```

일반적인 요약, 번역, 아이디어 정리처럼 모델이 이미 익숙한 작업은 제로샷으로 먼저 시도하는 편이 효율적입니다.

## One-shot: 예시 하나 보여 주기

One-shot(원샷)은 원하는 입력과 출력의 예시를 하나 제공합니다.

```text
예시
입력: 설명이 친절해서 쉽게 설치했습니다.
출력: 긍정

분류할 내용
입력: 배송은 빨랐지만 포장이 조금 찌그러졌습니다.
출력:
```

예시 하나만으로도 출력 형식이나 말투를 보여 줄 수 있지만 모델이 그 예시의 우연한 특징까지 규칙으로 오해할 수 있습니다.

## Few-shot: 서로 다른 예시를 몇 개 보여 주기

Few-shot(퓨샷)은 보통 두 개 이상의 완성 예시를 제공합니다.

```text
입력: 설명이 친절해서 쉽게 설치했습니다.
출력: 긍정

입력: 제품은 정상적으로 도착했습니다.
출력: 중립

입력: 두 번 사용했는데 전원이 켜지지 않습니다.
출력: 부정

입력: 배송은 빨랐지만 포장이 조금 찌그러졌습니다.
출력:
```

모델은 예시에서 분류 기준과 출력 형식을 함께 파악합니다. 경계가 애매한 업무일수록 대표 사례와 예외 사례를 나란히 보여 주면 좋습니다.

## 세 방식을 비교해 보겠습니다

| 방식 | 프롬프트 안의 예시 | 장점 | 주의점 |
|---|---:|---|---|
| Zero-shot | 0개 | 빠르고 간단함 | 기준이 모호하면 결과가 흔들림 |
| One-shot | 1개 | 형식을 쉽게 전달 | 하나의 예시에 과도하게 맞출 수 있음 |
| Few-shot | 여러 개 | 기준과 예외를 구체적으로 전달 | 프롬프트가 길어지고 예시 품질의 영향을 받음 |

## Few-shot은 모델 학습이 아닙니다

퓨샷 예시는 현재 요청의 컨텍스트 안에서만 참고됩니다. 모델의 파라미터를 바꾸는 Fine-tuning(파인튜닝)이나 Distillation(증류)과는 다릅니다.

```text
Few-shot       현재 요청에 예시를 넣음       모델 자체는 그대로
Fine-tuning    데이터로 모델을 추가 학습     모델 파라미터가 바뀜
Distillation   큰 모델을 따라 작은 모델 학습 새로운 학생 모델을 만듦
```

## 언제 무엇을 사용하면 좋을까요?

### 먼저 Zero-shot으로 시작해 보세요

- 회의 내용 요약
- 일반적인 번역
- 초안 아이디어 정리
- 이미 형식이 명확한 간단한 질문

### 다음 경우에는 Few-shot을 고려해 보세요

- 사내 고유 분류 기준이 있습니다.
- 출력 형식을 정확히 맞춰야 합니다.
- 같은 표현도 업무 맥락에 따라 의미가 달라집니다.
- 좋은 답과 나쁜 답의 경계를 설명만으로 전달하기 어렵습니다.

### 제조 현장 예시

설비 이상 사유를 `부품`, `조건`, `오조작`, `미분류`로 나누고 싶다면 각 범주의 대표 예시를 실제 기록에서 뽑아 쓸 수 있습니다. 이때 개인정보와 민감 정보는 미리 지워야 합니다. 다만 예시가 한 설비나 한 교대조에만 치우치면 다른 상황에서 잘못 분류할 수 있습니다.

## 좋은 Few-shot 예시를 고르는 방법

1. 실제 업무에서 자주 나타나는 사례를 포함합니다.
2. 서로 비슷한 예시만 반복하지 않습니다.
3. 헷갈리기 쉬운 경계 사례를 포함합니다.
4. 입력과 기대 출력의 형식을 일관되게 유지합니다.
5. 개인정보·영업비밀·보안 정보를 제거합니다.
6. 예시만 주지 말고 작업 지시와 판단 기준도 함께 씁니다.

## 자주 생기는 오해

- 예시가 많다고 항상 좋아지는 것은 아닙니다. 불필요한 예시는 비용과 혼란을 늘립니다.
- 잘못된 예시는 모델도 잘못된 방향으로 이끕니다.
- 한 번 잘 나온 프롬프트가 모든 모델과 모든 버전에서 같은 결과를 보장하지는 않습니다.
- 중요한 자동화에는 프롬프트 예시뿐 아니라 평가 데이터와 검증 절차가 필요합니다.

## 핵심 요약

- Shot은 현재 프롬프트에 넣은 완성 예시의 수입니다.
- 간단한 작업은 Zero-shot부터 시작하고, 기준과 형식이 중요하면 Few-shot을 사용합니다.
- Few-shot은 모델을 다시 학습하는 방법이 아닙니다.
- 예시의 수보다 다양성, 정확성, 보안이 더 중요합니다.
