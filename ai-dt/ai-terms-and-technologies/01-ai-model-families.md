# 01. AI 모델의 종류: LLM, SLM, VLM, VLA

## 이 글에서 답할 질문

- LLM, SLM, VLM, VLA는 무엇이 다른가요?
- 추론 모델은 일반 모델과 무엇이 다른가요?
- 모델이 크면 언제나 더 좋은가요?
- 지식 증류는 모델을 어떻게 작게 만드나요?

## 먼저 한 문장으로 정리해 보겠습니다

> 모델 이름에 붙는 글자는 주로 **무엇을 입력받고, 무엇을 출력하며, 어느 규모로 동작하는지**를 나타냅니다.

## Foundation Model: 여러 일을 배우는 바탕 모델

Foundation Model(파운데이션 모델)은 방대한 데이터로 미리 학습해 여러 작업의 바탕으로 사용할 수 있는 모델입니다. 특정 업무 하나만 수행하도록 만든 전통적인 모델과 달리 요약·분류·질의응답처럼 다양한 작업에 적용할 수 있습니다.

건물에 비유하면 파운데이션 모델은 여러 공간을 올릴 수 있는 **기초 공사**입니다. 그 위에 대화 서비스, 문서 검색, 코딩 도우미 같은 서로 다른 제품을 만들 수 있습니다.

## LLM: 언어를 입력받고 언어를 만드는 모델

LLM(Large Language Model, 대규모 언어 모델)은 많은 텍스트를 학습해 다음에 올 표현을 예측하는 방식으로 글을 이해하고 생성합니다.

```text
질문·문서·지시문
        ↓
      LLM
        ↓
답변·요약·분류·코드
```

LLM은 자연스러운 문장을 만들 수 있지만 다음 한계가 있습니다.

- 학습 당시의 지식과 현재 사실이 다를 수 있습니다.
- 그럴듯하지만 틀린 내용을 만들어 내기도 합니다.
- 회사 내부 자료를 자동으로 알고 있는 것은 아닙니다.
- 계산이나 검색처럼 정확성이 중요한 작업에는 별도 도구가 필요할 수 있습니다.

## SLM: 더 작고 가볍게 만든 언어 모델

SLM(Small Language Model, 소규모 언어 모델)은 LLM보다 파라미터 수와 연산량을 줄인 언어 모델입니다. 작은 서버나 개인 기기에서 실행하거나 정해진 업무를 빠르고 저렴하게 처리할 때 유리합니다.

| 비교 | LLM | SLM |
|---|---|---|
| 일반적인 강점 | 폭넓은 지식과 복잡한 추론 | 빠른 응답과 낮은 비용 |
| 필요한 자원 | 상대적으로 큼 | 상대적으로 작음 |
| 적합한 업무 | 복잡한 분석, 다양한 질문 | 분류, 정형 추출, 기기 내 처리 |
| 주요 주의점 | 비용·지연·보안 경계 | 좁은 지식 범위와 성능 한계 |

SLM이 항상 LLM보다 부족한 것은 아닙니다. 업무 범위가 명확하고 관련 데이터로 잘 조정되어 있다면, 작은 모델이 특정 작업에서 더 경제적이고 일관된 선택이 될 수 있습니다.

## VLM: 이미지와 언어를 함께 이해하는 모델

VLM(Vision-Language Model, 시각·언어 모델)은 이미지와 텍스트를 함께 다룹니다. 사진을 설명하거나 도표를 읽거나 화면과 질문을 연결해 답할 수 있습니다.

```text
장비 사진 + "이 경고등은 무엇인가요?"
                    ↓
                  VLM
                    ↓
       사진과 질문을 함께 고려한 설명
```

제조 현장에서는 외관 이미지 설명, 계기판 판독 보조, 도면 질의응답 등에 활용할 수 있습니다. 다만 작은 결함, 흐린 문자, 가려진 부분을 놓칠 수 있으므로 품질 판정의 최종 책임을 바로 맡겨서는 안 됩니다.

## VLA: 보고, 이해하고, 행동으로 연결하는 모델

VLA(Vision-Language-Action Model, 시각·언어·행동 모델)는 카메라 영상과 언어 지시를 받아 로봇이나 장치의 행동으로 연결합니다.

```text
카메라 영상 + "파란 상자를 오른쪽 선반에 놓아 주세요."
                            ↓
                           VLA
                            ↓
                 이동·집기·놓기 동작
```

VLM이 “무엇이 보이는지” 설명하는 데 강하다면, VLA는 “무엇을 해야 하는지”를 행동 출력으로 이어갑니다. 물리적 행동은 오류의 영향이 크므로 안전 구역·속도 제한·비상 정지 같은 별도의 제어 장치가 반드시 필요합니다.

## 네 모델을 한 번에 비교해 보겠습니다

| 용어 | 주된 입력 | 주된 출력 | 대표 활용 |
|---|---|---|---|
| LLM | 텍스트 | 텍스트 | 요약, 번역, 질의응답 |
| SLM | 텍스트 | 텍스트 | 기기 내 AI, 빠른 분류·추출 |
| VLM | 이미지·텍스트 | 텍스트 등 | 이미지 설명, 문서·화면 이해 |
| VLA | 이미지·텍스트·상태 | 행동 명령 | 로봇 조작, 자율 시스템 |

SLM은 **크기 기준**, VLM과 VLA는 **입출력 방식 기준**입니다. 그래서 작은 VLM이나 작은 VLA도 존재할 수 있습니다.

## Reasoning Model: 답하기 전에 더 오래 생각하는 모델

앞의 네 가지가 무엇을 입력받고 출력하는지에 따른 구분이라면, Reasoning Model(추론 모델)은 **답을 만들기 전에 얼마나 계산을 쓰는지**에 따른 구분입니다.

일반 모델은 질문을 받으면 곧바로 답을 쓰기 시작합니다. 추론 모델은 답을 내놓기 전에 내부적으로 문제를 쪼개고 중간 단계를 따져 보고 스스로 점검하는 과정을 거칩니다. 이 중간 과정은 사용자에게 전부 보이지 않거나 요약된 형태로만 제공되기도 합니다.

```text
[일반 모델]   질문 → 곧바로 답변

[추론 모델]   질문 → 내부 사고 과정 → 검토 → 답변
```

학습을 마친 뒤 실제 사용 시점에 계산을 더 쓴다는 뜻에서 이 방식을 Test-time Compute(추론 시점 연산)라고 부릅니다. 모델을 더 크게 만드는 대신 같은 모델이 더 오래 생각하게 해서 성능을 올리는 접근입니다.

| 구분 | 일반 모델 | 추론 모델 |
|---|---|---|
| 응답 속도 | 빠름 | 느림 |
| 토큰 비용 | 낮음 | 보이지 않는 사고 과정까지 과금되어 높음 |
| 유리한 작업 | 요약, 번역, 분류, 일상 대화 | 수학, 복잡한 코드, 다단계 계획, 원인 분석 |
| 불리한 작업 | 여러 단계를 따져야 하는 문제 | 단순 반복 처리 |

### 업무에서 주의할 점

- 모든 질문에 추론 모델을 쓰면 비용과 대기 시간이 빠르게 늘어납니다. 어려운 문제에만 선택적으로 쓰는 편이 좋습니다.
- 오래 생각한다고 정답이 보장되지는 않습니다. 잘못된 전제에서 출발하면 정교한 논리로 틀린 결론에 도달합니다.
- 화면에 보이는 사고 과정은 실제 내부 계산의 요약이거나 사후 설명일 수 있습니다. 근거로 인용하기 전에 사실 확인이 필요합니다.

## 재미로 계산해 보는 H200 GPU 장수

모델 종류만 보고 필요한 GPU 수를 정확히 정할 수는 없습니다. 같은 LLM이라도 8B와 400B는 크기가 크게 다릅니다. VLM과 VLA도 사용하는 언어 모델의 크기에 따라 달라집니다.

그래도 규모를 체감할 수 있도록 몇 가지를 단순하게 가정해 보겠습니다.

- [NVIDIA 공식 사양](https://www.nvidia.com/en-us/data-center/h200/)에서 H200 한 장의 메모리는 141GB이지만 여기서는 편의상 **140GB**로 계산합니다.
- 학습이 아닌 **한 번의 추론 서비스**를 기준으로 합니다.
- BF16에서는 파라미터 하나에 약 2바이트, 4-bit 양자화에서는 약 0.5바이트가 필요하다고 단순 계산합니다.
- 실행 엔진, KV Cache, 이미지 처리, 긴 컨텍스트에 쓸 공간을 남겨 두고 GPU 메모리의 약 80%만 모델 가중치에 사용한다고 가정합니다.

```text
BF16 가중치 용량 ≈ 파라미터 수 × 2바이트
4-bit 가중치 용량 ≈ 파라미터 수 × 0.5바이트
H200 한 장에 안전하게 담을 가중치 ≈ 140GB × 80% = 112GB
```

| 구분 | 재미를 위한 대표 크기 | BF16 가중치만 계산 | BF16 실사용 추정 | 4-bit 실사용 추정 |
|---|---:|---:|---:|---:|
| SLM | 3B | 약 6GB | H200 1장 | H200 1장 |
| LLM | 70B | 약 140GB | H200 2장 | H200 1장 |
| 초대형 LLM | 400B | 약 800GB | H200 8장 안팎 | H200 2장 안팎 |
| VLM | 90B급 언어 모델 + 시각 모듈 | 180GB 이상 | H200 2장 이상 | H200 1장 안팎 |
| VLA | 7B급 언어 모델 + 시각·행동 모듈 | 14GB 이상 | H200 1장 | H200 1장 |

> 이 표는 제품 구매나 설비 설계를 위한 산정표가 아닙니다. 동시 사용자 수, 입력 길이, 이미지 해상도, 응답 속도, 양자화 방식에 따라 필요한 GPU 수가 늘어날 수 있습니다. 모델을 **학습**하려면 가중치뿐 아니라 기울기와 Optimizer State도 저장해야 하므로 추론보다 훨씬 많은 GPU가 필요합니다.

“H200 한 장에 모델이 들어간다”와 “원하는 속도로 여러 사용자에게 서비스할 수 있다”는 서로 다른 문제입니다. 메모리에 들어가더라도 처리량을 높이려면 여러 장이 필요할 수 있습니다.

### MoE 모델에서는 계산이 달라집니다

최근 공개되는 대형 모델 상당수는 MoE(Mixture of Experts, 전문가 혼합) 구조를 씁니다. 내부를 여러 전문가 블록으로 나누고 토큰마다 그중 일부만 활성화하는 방식입니다.

```text
전체 파라미터 400B  ←  메모리에는 전부 올려야 함
활성 파라미터  40B  ←  실제 계산에 참여하는 부분
```

그래서 MoE 모델은 **메모리는 전체 크기만큼 필요하지만 연산량과 응답 속도는 활성 크기에 가깝습니다.** 모델 사양에 “총 파라미터”와 “활성 파라미터”가 따로 적혀 있다면 이 구조라고 보시면 됩니다. 위 표처럼 파라미터 수만으로 GPU를 계산하면 MoE 모델의 속도를 지나치게 낮게 잡습니다.

## Distillation: 큰 모델의 행동을 작은 모델이 배우는 방법

Distillation(지식 증류)은 큰 Teacher Model(교사 모델)의 출력이나 판단 패턴을 작은 Student Model(학생 모델)이 학습하도록 하는 모델 압축 방법입니다.

```text
교사 모델의 예측과 설명
          ↓ 학습 자료로 활용
      학생 모델 학습
          ↓
더 작고 빠른 모델
```

교사가 교과서의 모든 내용을 학생에게 그대로 복사하는 것은 아닙니다. 여러 문제를 푸는 모습을 보여 주고 학생이 비슷한 판단을 하도록 훈련하는 것에 가깝습니다.

### 증류의 장점

- 추론 속도와 서비스 비용을 줄일 수 있습니다.
- 메모리와 전력 사용량도 함께 줄어듭니다.
- 작은 장치나 제한된 서버에 배포하기 쉬워집니다.

### 증류의 한계

- 학생 모델이 교사 모델의 능력을 모두 보존하지는 못합니다.
- 교사의 오류나 편향도 함께 배울 수 있습니다.
- 모델이 작아졌다고 자동으로 보안이나 정확성이 좋아지지는 않습니다.

## 업무에서 어떻게 선택하면 좋을까요?

1. 먼저 필요한 입력과 출력을 확인합니다.
2. 복잡한 범용 추론이 필요한지, 좁고 반복적인 작업인지 구분합니다.
3. 정확도뿐 아니라 비용, 응답 시간, 보안, 운영 환경을 함께 비교합니다.
4. 물리적 행동이나 중요한 의사결정에는 별도의 검증과 안전장치를 둡니다.

## 핵심 요약

- LLM은 언어, VLM은 시각과 언어, VLA는 시각·언어·행동을 연결합니다.
- SLM은 작은 규모에 초점을 둔 분류이므로 VLM·VLA와 기준이 다릅니다.
- 추론 모델은 입출력이 아니라 답하기 전에 쓰는 계산량으로 나눈 구분이며 어려운 문제에만 선택적으로 쓰는 것이 좋습니다.
- MoE 모델은 메모리는 전체 크기만큼, 연산은 활성 크기만큼 쓰므로 파라미터 수만으로 자원을 계산하면 어긋납니다.
- 증류는 큰 모델의 판단을 작은 모델에 옮겨 효율을 높이는 방법입니다.
- 모델 선택은 “가장 큰 모델”이 아니라 “업무에 필요한 능력과 제약”을 기준으로 해야 합니다.
