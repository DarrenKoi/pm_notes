# 로드맵 기록 검토 안내

## 이 자료를 다시 읽는 방법

원문은 2026-05-14/15의 설계 논의다. **당시 결정**, **달성할 목표**, **설명을 위한 예시**, **사내에서 확인해야 할 사실**을 구분한다. ADR의 `Accepted`와 outline의 해결 표시를 당시 기록으로 보존했다. 현재 조직 권한·사업 승인·성과를 확인한 표기가 아니다.

보고서의 작동 방식은 현황 진단 → 비전 → 목표 지표 → 추진 트랙 → 기반 역량·책임 → 일정 → 초기 PoC다. 실제로 적용하려면 데이터 접근과 기준선을 확보하고, 평가·복구·운영 책임을 정한 뒤 검증 결과에 따라 확대한다. 일정의 연차는 시작 기준일이 확정되지 않아 달력 연도로 환산하지 않았다.

## 기술적 정확성과 적용 조건

**암묵지 캡처는 이 업무에서 검증할 가설이다.** “RAG 품질 상한은 암묵지 채굴이 결정한다”를 모든 RAG의 일반 법칙으로 읽지 않는다. 원 RAG 논문은 검색 가능한 외부 메모리와 생성 모델을 결합하는 방식 및 특정 과제의 실험을 설명한다. 실제 품질은 회수할 근거·검색·생성·평가 조건에 영향을 받으며, 명시지로 충분한 질문도 있다. 순환고리의 검수·저장·검색·피드백 각 단계와 업무 효용을 따로 확인해야 한다. 지식 그래프는 이 로드맵의 제안 기반이며 모든 RAG의 필수 선행 조건은 아니다.

**지표 이름에 분모와 관측 조건을 붙인다.** 정확도는 맞힌 사례/전체 사례다. 희귀 고장처럼 클래스가 불균형하면 전체 정확도가 높아도 고장을 놓칠 수 있다. precision은 맞힌 고장 알림/전체 고장 알림, recall은 찾아낸 고장/전체 실제 고장으로 분리한다. `hit rate`·회수 정확도·채택률은 원문에서 분모·대상·중복 처리·시간창이 일관되게 정의되지 않아 미확인이다. 예지보전은 장비·고장 단위, 사전 경고 기간, 중복 알림 처리와 누락/오경보 비용도 정의해야 한다.

예를 들어 정상 990건·고장 10건에서 모두 정상으로 분류하면 전체 정확도는 **99%**, 고장 recall은 **0%**, balanced accuracy는 **50%**다. 이 산술은 희귀 고장에 전체 정확도만 쓰는 문제를 설명하며 사내 모델의 측정 결과가 아니다. 감소율은 `(baseline-적용 후)/baseline`으로 계산하되 baseline=0이면 정의되지 않는다. 처리시간 감소는 같은 업무 범위·측정 방법·비교 기간을 전제로 해석한다.

**2주 자동 운영과 수용 ≥70%는 당시 제안 gate다.** 일반적인 production 인증 표준으로 취급하지 않는다. SLI는 서비스의 측정 지표이고 SLO는 목표 범위다. 대상 요청·측정 위치·관측 기간과 실패 시 행동이 정해져야 SLO를 평가할 수 있다. “담당자가 손 떼도” 또는 “무감시”는 모니터링·on-call 요구와 함께 읽어야 하며 장애 대응 책임이 사라진다는 뜻으로 적용하지 않는다. 사용자의 기본 수용·호출 수는 품질이나 성과와 동일하지 않다.

**공통 능력의 재사용은 공통 계약을 재사용하는 전략이다.** 분류·RAG·예측이라는 이름이 같아도 데이터 스키마·권한·모델·평가·배포 조건은 다를 수 있다. “학습 데이터만 다름”, 개선 즉시 전파, 인프라 5개만 개발, 87% 고장 확률·ROI 최고 등의 표현은 구현·검증이 없는 제안 또는 예시다. 장비 예측의 87%가 보정된 실제 확률인지 확인하지 않았다. DRM 자료 추출·채팅 기록 색인·영상 캡처는 도구 제안이며 사용 권한이나 사내 승인 확인을 뜻하지 않는다.
