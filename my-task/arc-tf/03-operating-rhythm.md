# 운영 방식

> 회의, 보고, 의사결정, 작업 관리, 안전 원칙. 여러 팀이 겸직으로 모이는 TF라서 정해진 리듬이 없으면 흩어진다.

## 회의

| 회의 | 주기 | 참석 | 시간 | 다루는 것 |
|---|---|---|---|---|
| 실무 회의 | 초기 주 1회 → 집중 단계에서 주 2회 | 리드, 플랫폼 팀, 셀 엔지니어 | ⟨확인: 60분⟩ | 셀별 진행, 막힌 것, 다음 주 할 일, 결정 필요 사항 |
| 셀 작업 세션 | 셀마다 필요할 때 | 플랫폼 팀 1명 + 셀 | — | 절차 정의, 녹화 검토, 장비 검증 |
| 임원 보고 | 월 1회 | 리드 (필요하면 셀 대표) | ⟨확인⟩ | 진행, 지표, 위험, 요청 사항 |

**주 2회로 바꾸는 시점**: 1차 구축 단계(2027-03)에 들어가 셀들이 동시에 장비 검증을 하기 시작할 때. 바꿀 때는 [결정 기록](./decision-log.md)에 남긴다.

### 실무 회의 진행 순서

1. 지난 회의 할 일 확인 (5분)
2. 셀별 진행: 한 셀에 5분, 형식은 "한 것 / 막힌 것 / 다음 할 일"
3. 결정 필요 사항: 그 자리에서 정하고 결정 기록에 남긴다. 못 정하면 담당과 기한을 정한다
4. 위험 목록에서 바뀐 것 확인
5. 다음 주 할 일과 담당 확정

회의록은 짧게, 결정과 할 일만 남긴다.

## 월간 임원 보고 형식

1페이지로 쓴다. 기능 설명보다 효과를 먼저 쓴다.

| 항목 | 내용 |
|---|---|
| 이번 달 결과 | 무엇이 되었나, 어떤 지표가 바뀌었나 |
| 지표 | 셋업 시간, 예정에 없던 개입 횟수, 셋업 뒤 첫 측정 성공률, 완주한 레시피 유형 수 (기준선 대비, 측정 규칙은 [기획안](./01-tf-proposal.md)) |
| 다음 달 계획 | 단계와 통과 기준 |
| 위험 | 새로 생긴 것, 커진 것 |
| 요청 | 임원이 결정하거나 도와줘야 할 것 |
| 참여 시간 | 셀별 겸직 시간 실적 (계획 대비) |

## 의사결정

- 범위와 우선순위는 리드가 정한다. 장비 절차와 판정 기준은 셀 엔지니어가 정한다.
- 결정은 [결정 기록](./decision-log.md)에 날짜, 결정, 이유와 함께 남긴다. 뒤집을 때도 남긴다.
- 셀 사이에 의견이 갈리면 실무 회의에서 리드가 정한다. 예산이나 인력이 걸린 것은 월간 보고에서 임원에게 올린다.
- 단계 통과는 리드가 정리하고 월간 보고에서 임원이 승인한다. 미달이면 보완, 축소, 중단 중 하나를 정한다 ([기획안](./01-tf-proposal.md) 5절).

## 작업 관리

- 할 일은 ⟨확인: 이슈 트래커 / 사내 도구⟩에 셀 단위 라벨로 관리한다.
- 코드는 공통 플랫폼 저장소 하나에 둔다. 장비별 절차는 같은 저장소 안의 장비군 폴더로 나눈다.
- 장비 데이터, 화면 캡처, 사내 수치는 사내 환경에만 둔다. 이 문서 폴더에는 일반화된 계획만 남긴다.

## 안전 원칙 (모든 셀 공통)

PoC에서 정한 규칙을 그대로 가져온다.

- **검증에 실패하면 기본은 중단이다.** 무한 재시도는 없다. 마지막 대안은 사람에게 넘기는 것이다.
- 되돌릴 수 없는 조작은 실행 전과 후 모두 검증한다. 실패하면 자동으로 다시 실행하지 않는다.
- 모든 조작은 증거를 남긴다: 조작 전후 화면, VLM 응답, 좌표.
- 낮은 CV 점수를 VLM 답변으로 덮어쓰지 않는다.
- 엔지니어 작업 녹화는 화면만 본다. 입력을 가로채지 않는다.
- 실장비 검증은 처음에는 엔지니어가 지켜보는 상태에서만 한다.

### 조작별 승인

| 조작 | 승인 |
|---|---|
| 화면 읽기, 창 전환, 값 확인 | 필요 없음 |
| 측정 위치·Align 후보 선택, 입력란 채우기 (저장 전) | 필요 없음. 단계마다 검증하고 실패하면 중단 |
| 측정 실행 | 셀 엔지니어 승인 |
| 레시피 저장·적용 | 셀 엔지니어 승인 |
| 삭제, 덮어쓰기, 장비 모드 변경 | 셀 엔지니어 승인. 1차에서는 Agent에게 맡기지 않는 것을 기본으로 한다 |

장비군마다 다르게 분류할 조작은 셀이 절차 정의 때 이 표에 더한다.

### 중단, 인계, 복구

- **즉시 중단**: 엔지니어는 언제든 Agent를 멈출 수 있어야 한다. 중단 수단(버튼·단축키)은 ⟨확인⟩이며, 1차 구축 단계의 필수 기능이다.
- **제어권 인계**: Agent는 중단하거나 실패하면 마우스와 키보드에서 손을 떼고, 마지막 화면과 진행 단계를 엔지니어에게 넘긴다. 엔지니어가 수동으로 이어서 하거나 처음부터 다시 한다.
- **원본 보존**: 기존 레시피를 고치는 작업이면 시작 전에 원본을 백업한다. 신규 레시피는 승인 전까지 확정하지 않는다.
- **오조작 복구**: 잘못 저장된 레시피는 셀 엔지니어가 백업으로 되돌리고, 결정 기록에 원인과 함께 남긴다. 원인을 찾을 때까지 그 절차의 자동 실행을 멈춘다.

## 데이터 취급

| 항목 | 규칙 |
|---|---|
| 담당 | 플랫폼 팀이 관리하고 리드가 책임진다. 보안 담당과 범위를 협의한다 |
| 녹화 동의 | 엔지니어 작업 녹화는 본인 동의를 받고, 녹화 중임을 화면에 표시한다 |
| 수집 범위 | 장비 화면, 조작 기록, VLM 응답, 좌표. 계정·비밀번호 입력 구간은 가린다 |
| 접근 권한 | TF 구성원만. 셀은 자기 장비군 데이터만 본다 |
| 보존·삭제 | 보존 기간 ⟨확인⟩, 기간이 지나면 삭제. 학습 자료로 쓸 것은 따로 표시해 남긴다 |
| 교육 자료로 쓸 때 | 장비명·Lot·수치를 가린 사본만 쓰고, 리드가 승인한다. 사내 환경 밖으로 내보내지 않는다 |
