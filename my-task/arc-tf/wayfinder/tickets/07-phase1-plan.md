# 2027 관찰·지식화 단계의 분기별 계획

## Question

2027년 1단계를 분기 단위로 어떻게 나누는가? 각 분기에 무엇을 내고, 무엇으로 다음 분기로 넘어가는가?

이미 정해진 틀: 2027-01~02 온보딩(8주, 셀 기준선 측정과 녹화 시작). 성과 과제인 Align Fail 자동 대응의 현장 운영 시점(입력 주입 테스트와 입력 보안 승인 포함)을 먼저 박고, 그 둘레에 관찰·지식화 기능 순서를 놓는다: 관찰·녹화 → 절차·노하우 추출 → 지식 자산 DB → 요청형 돌파구 추천 → 채팅. 서버 확보(01), PC 자원 한도(02), 추출 자동화 수준(03), 의뢰서 접근(04), 통과 기준(05)의 답을 근거로 쓴다.

## Resolution

2026-11-06 grilling에서 정함. 계기: AI 임원이 2027 상반기까지 Align Fail 자동 대응 완성을 원함. 전체 계획은 유지하고, Align Fail을 **빠른 첫 통과**로 먼저 끝낸 뒤 그 과정에서 나온 요소를 장기 계획에 반영함.

**Align Fail 자동 대응 — 빠른 첫 통과 (2027 상반기)**

- 완성 = CD-SEM과 Thickness 모두 자동 해결률 기준을 넘기고 실알람에 무인 대응. 2027-06 관문 판정 ([2027 통과 기준](05-phase1-gate.md)의 Align Fail 부분을 이 결정으로 바꿈)
- Thickness는 SecureVDI 입력 주입 시험(2026-12) 통과가 조건. 입력이 막히면 VDI 안 설치를 추가 승인받아 검증하고, 그것도 막히면 Thickness는 관찰·돌파구 추천(엔지니어 수동 조작)으로 한정해 무인 대응 완성에서 제외함 (2026-11-06 Codex 리뷰 반영: 입력 불가면 반자동도 성립하지 않음)
- 반자동 기간은 **제안 적중률**로 무인 전환을 판단하고, 자동 해결률은 무인 기간에만 셈
- 무인 대응 허용 조작은 레시피를 바꾸지 않는 위치 재조정과 해당 지점 재측정 재시도뿐임. 저장·삭제·모드 변경·레시피 수정 금지
- 2028 진입에는 관찰·지식화 통과에 더해 공통 기술·안전 요건(입력 실행기가 의도한 조작만 하고 불확실하면 스스로 멈춤)이 필요함. Align Fail 성과 목표 미달은 진입을 막지 않음

| 시기 | CD-SEM | Thickness |
|---|---|---|
| 2027-01 | 입력 주입 시험(RCS), 입력 승인, PoC 제품화 | 알람 사례 수집·녹화 (SecureVDI 입력 주입 시험은 2026-12) |
| 2027-02~03 | **2월 반자동 운영 시작**, 자동 해결률 누적 | 인식·재조정 구축 (CD-SEM보다 위치 지정이 단순하고 패턴 인식이 쉬움) |
| 2027-04~05 | 기준을 넘은 장비부터 무인 전환 | **4월 반자동 운영 시작** |
| 2027-06 | Align Fail 관문 판정 | 무인 전환, 관문 판정. 미달이면 무인 전환을 3분기로 미루고 지연으로 기록 |

- **버리는 코드로 만들지 않음**: 캡처 클라이언트, 화면 영역 지도, 입력 실행기, 자체 중단 가드레일, 실행 로그(서버)는 플랫폼 부품으로 만듦. 속도 때문에 하드코딩한 곳은 표시해 두고 나중에 걷음
- **2027-06 산출물 = 요소 목록**: Align Fail에 필요했던 요소를 "그대로 재사용 / 고쳐 쓰기 / 버림"으로 나누고 7개 기능에 대응시킴. 하반기 계획과 [2028·2029 단계 범위](08-phase23-scope.md)의 입력

**관찰·지식화 (리드는 상반기 Align Fail 전담, 나머지 0.5~1명)**

| 시기 | 내는 것 |
|---|---|
| 2026-12 | 최소 녹화기 (녹화 모드만, 수동 시작, 뷰어 창 크롭, 업로드). `observe_probe.py` 바탕 |
| 2027 상반기 | 녹화 클라이언트 두 모드 완성(3월 말), 서버 수집, 3개 장비군 화면 영역 지도. 3개 장비군 녹화를 계속 쌓음 (Align Fail 녹화 포함) |
| 2027-07~09 | 절차 추출 파이프라인(AI 초안, 결정 지점 질문, 검토 화면), 레시피 의뢰서 연동, 첫 절차서 |
| 2027-10~12 | 지식 자산 DB와 요청형 돌파구 추천, 반복 입력 빈도 분석(2028 대행 후보), 12월 관문 판정 |
| 2028-01~03 | 채팅 (이월) |

- 관찰·지식화 통과 기준 세 가지는 그대로임. 추천 채택률은 측정 기간이 약 2개월이라 목표를 보수적으로 잡음
- 레시피 의뢰서 접근이 늦어지면 녹화 시작 때 엔지니어가 레시피 유형을 고르는 방식으로 대신함. 일정이 [의뢰서 접근](04-request-form-access.md)에 걸리지 않음
- 인력이 모자라면 채팅을 먼저 미룸 (관문 밖 기능)

**보안 승인**
- 2026-11~12에 두 건으로 나눠 신청함. **관찰**(화면 캡처·녹화, 온보딩 전 필요)과 **입력**(Align Fail 위치 재조정·해당 지점 재측정 재시도로 한정, RCS·SecureVDI 두 경로, 2027-01 필요). 한쪽 심사가 다른 쪽을 막지 않게 함
- 2028 입력 대행은 2027 말에 따로 신청함

**회사 확인 작업**
- [PC 자원 실측](10-pc-measurement.md)과 [절차 추출 시범](12-extraction-trial.md)은 2026-11~12에 함. Thickness SecureVDI 입력 시험을 같이 함. 늦어지면 절차서 수 ⟨N⟩과 채택률 목표는 2027-03 말까지 정함
