# 녹화에서 절차와 노하우를 자동으로 뽑아낼 수 있는 수준은 어디까지인가

## Question

엔지니어의 화면 녹화(조작 기록 없음, 장비 뷰어 창만)에서 **절차(단계 순서)** 와 **노하우(판단 근거)** 를 사내 VLM(Qwen3-VL-8B/30B급)으로 어느 정도까지 자동 추출할 수 있는가? 사람 손이 반드시 필요한 부분은 어디인가?

알고 싶은 것:
1. 화면 녹화에서 GUI 조작 단계를 복원하는 공개 연구, 도구의 현재 수준 (클릭, 입력 추정, 단계 나누기)
2. 키 입력, 마우스 기록 없이 화면만으로 할 때의 한계
3. "왜 그렇게 했는가"(노하우)는 화면에서 나오지 않는다. 공개 사례에서 이를 어떻게 보충하는가 (작업 후 짧은 음성, 채팅 설명, 검토 화면 등)
4. 30분짜리 녹화 1건을 처리하는 데 VLM 호출이 얼마나 드는가의 어림 방법 (프레임 샘플링 기준)

이 답이 1단계 일정의 가장 큰 불확실성이다. 자동화 가능 범위가 작으면 1단계는 "사람이 검토하는 반자동 추출"로 잡는다.

## Resolution

조사 결과: 브랜치 `research/03-procedure-extraction`의 `my-task/arc-tf/wayfinder/research/03-procedure-extraction.md` (2026-11-06, 병합하지 않음)

- **절차 초안은 자동으로 가능함.** 가장 가까운 공개 사례(VideoAgentTrek, ICLR 2026)는 조작 기록 없이 영상만으로 7B VLM을 미세조정해, 조작 검출 F1 0.78(클릭 0.82)을 보고함. 조작 값의 타당도 0.658은 사람이 "그럴듯한가"로 판정한 값이라 정확 일치가 아님. 미세조정 없이 범용 VLM을 쓰면 약 20%p 낮음
- **사람 검토가 반드시 필요한 부분**: 키 입력(재현율 0.08로 대부분 놓침), 드래그, 입력한 수치, 문자열(OCR 잡음으로 후보 수준), 단계를 의미 단위로 묶기(공개 벤치마크 최고 17.1%)
- **노하우는 화면에서 나오지 않음.** 영상만으로 의도를 복원했다는 공개 시스템이 없고, 녹화를 다시 보여주는 회고만으로는 "왜"가 늘지 않았다는 연구가 있음 → 결정 지점마다 짧은 질문(핵심 결정 인터뷰 방식)을 붙여 엔지니어에게 받음
- **비용**: 30분 영상을 한 번에 넣으면 글자를 못 읽음. 화면이 바뀐 구간의 전후 프레임 쌍으로 나눠 물음. 녹화 1건에 약 100~250회 호출, 입력 0.3M~0.8M 토큰 (추정, 실측 필요)
- **1단계 방식 권고**: 화면 변화 검출 → 구간별 조작 추정 → OCR 값 대조 → AI 절차 초안 → 결정 지점 질문 자동 생성 → 엔지니어 검토와 "왜" 답변. 노하우의 원천은 엔지니어 답변이고 AI는 질문과 문장 정리를 맡음
- **1단계 지표 후보**: 단계 재현율, 엔지니어 수정률, 검토 시간, 노하우 채택률
- **확인 못 함**: 사내 모델(8B, 30B급)의 GUI 벤치마크 공식 수치, 비표준 계측 화면에서의 정확도 → 새 티켓 "시범 녹화로 절차 추출 정확도 실측"
