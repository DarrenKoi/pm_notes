# Auto Recipe Creation TF: 한 장 요약

> Align Fail 자동 대응 PoC의 시사점을 바탕으로 공통 플랫폼을 만들어, 숙련 엔지니어의 레시피 셋업 노하우를 회사 자산으로 남기고 장비가 늘어도 셋업 인력을 같은 비율로 늘리지 않는 구조를 만들고자 합니다.

## 출발점: PoC의 성과와 시사점

- Align Fail 자동 대응 PoC로 API 없는 장비를 사내 AI로 읽고 조작하는 기반 확보
- 이 일에는 **개발자와 현업 엔지니어 두 역할이 동시에** 필요. PoC는 TF 리드가 두 역할을 혼자 맡아 진행
- AI 모델 최적화와 운영, 최신 VLM 적용 테스트, 녹화 DB 추출까지 혼자 하기에는 시간 부족
- LLM 모델만으로는 안 됨: 정밀 좌표가 흔들리고, 장비 절차를 모르고, 성공/실패 여부를 스스로 확인하지 못하며, 진행 상태를 기억하지 못하고, 화면을 직접 조작하지 못함. 모델은 판단 한 부분이고 정밀 좌표(CV), 승인된 절차, 규칙 확인과 결과 검증, 입력 실행은 플랫폼이 채워야 함
- 처음에는 Agent 전용 PC를 따로 두려 했으나, 사무 PC를 계속 늘리는 방식은 PC 확보, 계정과 접속 권한, 관리 부담, 아무도 보지 않는 화면 같은 제약이 많음. 그래서 공통 플랫폼을 개발해 **엔지니어 본인 PC에 설치**하는 방향으로 바꿈
- 결론: MI 장비 전반으로 넓히려면 **공통 플랫폼**을 만들어 개발(플랫폼 팀)과 장비 지식(장비군 담당)을 나눠야 함

## 문제

- MI 장비 레시피 셋업은 숙련 엔지니어가 원격 화면에서 손으로 반복하는 작업임. 레시피당 평균 30~60분 (현업 경험치)
- 판단 기준이 사람에게만 있어 담당자가 바뀌면 노하우가 사라짐
- 장비, 제품이 늘면 셋업 인력도 같은 비율로 늘어야 함. Align Fail 알람이 나면 엔지니어가 하던 일을 멈추고 대응해야 장비가 다시 돎

## 해결 방향

- 엔지니어 작업 녹화에서 절차와 판단 근거를 추출하고 담당 엔지니어가 승인해, 다른 엔지니어가 찾아 쓰는 **지식 자산**으로 축적함
- AI는 현재 화면에 맞는 승인 절차를 찾아 **한 단계씩** 수행하고, 결과가 불명확하면 멈춤. 위험 조작과 저장, 적용은 엔지니어가 승인함
- 초기 개발은 **CD-SEM, Thickness 위주**(Align Fail PoC와 기존 PyAutoGUI 자동화를 재사용)로 공통 플랫폼을 베타까지 만듦. 같은 기간 다른 MI 장비군은 인터뷰, Recipe Workflow 조사로 준비해 설계에 반영하고, 베타 뒤 본격 참여
- 개발과 AI에 익숙하지 않은 엔지니어는 합류 시점마다 교육하며 TF를 운영함

## 단계별 타겟

| 시기 | 타겟 | 회사에 남는 것 |
|---|---|---|
| 2027 상반기 | 선발대(CD-SEM, Thickness) Align Fail 자동 대응 지능화, 공통 플랫폼 설계 완성과 베타 | 장비 가동 시간 회수, 확장 가능한 플랫폼 |
| 2027 하반기 | 2차 장비군(다른 MI 장비군) 합류, 선발대 셋업 노하우 지식 자산화 | 노하우의 조직 자산화 |
| 2028 | 엔지니어 앞에서 반복 입력 대행 | 엔지니어 직접 투입 시간 감소 |
| 2029 | CD-SEM, Thickness에서 AI가 셋업을 진행하고 특이 사항, 위험 때만 엔지니어 개입 | 셋업 인력을 장비 수에 비례해 늘리지 않음 |

- 효과는 엔지니어 직접 투입 시간과 예정에 없던 개입 횟수로 확인함. 기준선은 온보딩 때 실측, 측정 전에는 목표를 숫자로 정하지 않음
- 검토한 대안: A(선발대만 + 개발 2명)는 LLMOps와 녹화 추출이 리드에게 다시 몰리고, C(전체 동시 개발)는 플랫폼 없이 여러 장비군을 지원해야 함. B(처음부터 전체 + 개발 3명, 상반기는 CD-SEM, Thickness 중점)를 권고함
- 2차 본격 참여는 2027-06 베타 판정을 통과해야 함. 단계마다 검증 증거를 확인한 뒤에만 다음 단계로 확대함

## 요청 사항

- **ARC TF 구성 승인** (2027-01~12, 조직과 명단은 전체로, 참여는 선발대부터 단계적으로)
- **선발대 Thickness 담당 엔지니어 협업**: 1~2명, 주 5시간 (CD-SEM은 TF 리드)
- **2차 장비군 담당 엔지니어 지정**: 다른 MI 장비군마다 1~2명. 12월에 함께 지정, 상반기는 인터뷰, Recipe Workflow 조사(주 1~2시간), 베타 통과 후 7월부터 주 5시간
- **개발 인력 2명 지정** (백엔드 1, 프론트엔드 1. TF 리드 포함 3명, 각 50%, 실질 1.5명). PoC처럼 리드 혼자 개발하는 구조는 더 이상 유지할 수 없음
- 새 서버 구매 없음. 기존 사내 AI 서버와 서버 자원 사용, 녹화 스토리지는 2027 하반기에 사용량 실측 후 요청
