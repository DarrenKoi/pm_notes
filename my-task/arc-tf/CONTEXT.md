# ARC TF 도메인 용어

> ARC TF 문서와 대화에서 쓰는 말의 뜻. 구현 방법은 적지 않는다. 결정과 이유는 [결정 기록](./decision-log.md)에 둔다.

## 용어

**레시피 셋업 (Recipe setup)**
계측(MI) 장비에서 새 레시피를 만들거나 기존 레시피를 고쳐, 측정이 통하는 상태로 저장하기까지의 작업 전체.
_피할 말_: 레시피 작업, 튜닝(튜닝은 셋업의 일부인 "기존 레시피 고치기"를 말할 때만)

**장비군 담당 (Equipment owner group)**
한 장비군을 맡는 MI 현업 엔지니어 묶음(예: CD-SEM 담당). 그 장비의 절차와 판정 기준을 정한다. 그 안의 사람 한 명 한 명은 **담당 엔지니어**라 부른다.
_피할 말_: 셀(어색하다, 2026-11-06 변경), 팀(공통 플랫폼 팀과 헷갈린다). "장비군"만 쓰면 장비 자체를 가리킨다

**선발대 (1차 장비군), 2차 장비군**
선발대는 2027 상반기에 개발을 먼저 진행하는 CD-SEM, Thickness다. Align Fail 기준으로 ARC 부분 기능이 이미 있어, Align Fail 자동 대응 지능화와 공통 플랫폼 설계, 베타를 맡는다. 2차 장비군은 VeritySEM, Provision, Inspection 장비군이고, 2027-06 베타 판정 뒤 2027 하반기에 본격 합류해 공통 플랫폼을 실제로 적용한다 (2026-11-09 변경)
_피할 말_: 1차 지정군, 2차 지정군 (이전 구성: 1차 CD-SEM, Thickness, VeritySEM, 2차 Inspection 선택)

**단계적 참여**
조직과 2차 명단은 처음부터 전체로 승인받고, 초기 개발은 선발대(CD-SEM, Thickness) 위주로 한다. 2차 장비군은 상반기에 장비 특징, 작업 절차, 필요한 기능 파악을 해 요구사항을 정리하고(플랫폼 설계에 반영), 플랫폼이 베타 기준을 통과하면 본격 참여한다. 개발은 리드 + 지정 2명(백엔드, 프론트엔드), 각 50%
_피할 말_: small TF, s-TF (2차 인원까지 처음부터 정하므로 맞지 않음, 2026-11-09 변경)

**베타 기준**
2차 장비군 합류 전에 공통 플랫폼이 넘어야 할 조건. 선발대 엔지니어 PC에서 관찰, 녹화, Align Fail 입력, 즉시 중단이 정해진 기간 문제없이 돌고, PC 자원 한도를 지키고, 새 장비군을 장비별 코드 없이 화면 영역 지도와 절차 정의만으로 얹을 수 있어야 한다. 2027-06 관문에서 판정

**절차 (Procedure)**
한 레시피 유형을 셋업할 때 거치는 단계의 순서. 엔지니어 작업 녹화에서 뽑아내고, 사람이 읽는 형태는 **절차서**라 부른다.
_피할 말_: workflow, 워크플로

**노하우 (Know-how)**
절차의 각 단계에 붙는 판단 근거. "왜 그 위치를 골랐는가", "이 화면이 나오면 무엇을 확인하는가" 같은 것.
_피할 말_: 암묵지(로드맵 문서의 용어와 뜻이 다를 수 있다)

**지식 자산 (Knowledge asset)**
여러 엔지니어의 절차와 노하우를 모아, 다른 엔지니어가 찾아 쓸 수 있게 저장한 것.

**관찰 (Observation)**
프로그램이 엔지니어 화면과 읽기 전용 데이터로 레시피 상태와 엔지니어가 하는 작업을 파악하는 것. 화면에 입력하지 않는다.

**막힘 (Stuck point)**
엔지니어가 셋업 중 다음 단계로 나아가지 못하는 지점. 1단계에서는 엔지니어가 스스로 도움을 요청한 지점만 막힘으로 본다.

**돌파구 추천 (Breakthrough suggestion)**
막힘에서 지식 자산 중 비슷한 상황의 절차와 노하우를 찾아 해결 방안으로 제시하는 것.
_피할 말_: 솔루션 제공

**레시피 의뢰서 (Recipe request form)**
레시피를 만들어 달라고 요청할 때 쓰는 시스템 문서. 패턴 스키마, 좌표, 파라미터 등이 적혀 있다. 1단계에서 프로그램이 읽는 유일한 시스템 데이터.
_피할 말_: 요청서, 오더

**단계 (Phase)**
플랫폼을 1년에 하나씩 내는 큰 묶음. **관찰과 지식화**(2027) → **보조**(2028) → **자율**(2029).
_피할 말_: 차수(1차, 2차는 장비군을 여는 순서를 말할 때만 쓴다)

**자동 해결률 (Auto-resolution rate)**
Align Fail 실알람 가운데 엔지니어 손을 거치지 않고 해결된 비율.

**Align Fail 자동 대응 (Align Fail auto-response)**
Agent가 엔지니어 본인 PC에서 실알람의 위치 재조정과 재측정 재시도를 엔지니어 판단 없이 처리하는 것. 엔지니어는 늘 자리에 있고 결과에 책임을 진다. 관찰과 판단은 백그라운드에서 돌지만, 화면에 입력하는 몇 초 동안은 **제어권 인계**를 거친다. 반자동과의 차이는 재조정 위치를 엔지니어가 건마다 확정하는지 여부뿐이다.
_피할 말_: 무인 대응, 무인 전환, 무인 운영(엔지니어가 없어도 된다는 뜻으로 읽혀, 사고 시 책임질 사람이 없다는 오해를 낳는다. 2026-11-08 변경)

**제어권 인계 (Control handover)**
Agent가 엔지니어 PC의 마우스와 키보드를 잠시 넘겨받아 입력하고 돌려주는 것. 알림 → 엔지니어가 넘겨줌 → 대상 창 확인 → 짧은 입력 → 결과 확인 → 반환 순서다. 입력은 실제 마우스와 키보드를 움직이므로 그동안 엔지니어는 PC를 쓰지 못한다. 엔지니어가 마우스를 건드리거나 포커스가 바뀌면 Agent는 즉시 멈춘다.
_피할 말_: 백그라운드 입력(엔지니어가 다른 일을 하는 동안 입력된다는 뜻으로 읽힌다. 확인되지 않았다)

**제안 적중률 (Suggestion hit rate)**
Align Fail 반자동 기간에, 엔지니어가 확정한 재조정 위치 가운데 Agent 제안과 같은 비율. 자동 전환을 판단하는 데 쓴다. 자동 해결률은 자동 기간에만 센다.

**관문 (Gate)**
한 해의 단계를 통과했는지 판정하는 기준 묶음. 2027에는 Align Fail 관문(6월)과 관찰과 지식화 관문(12월)을 따로 판정한다.
_피할 말_: 마일스톤(일정 시점과 헷갈린다)

**자율 완주율 (Autonomous completion rate)**
Agent가 예정에 없던 엔지니어 개입 없이 레시피 셋업을 끝까지 진행한 비율. 최종 저장 승인은 예정된 개입이라 세지 않는다.

**자체 중단 (Self-stop)**
특이 사항이나 위험을 만나 Agent가 스스로 멈추고 엔지니어를 부른 것. 실패로 보지 않고 따로 센다.

**신뢰도 (Confidence index)**
레시피 유형 × 절차 단계마다 최근 이력으로 매기는 지수. 높은 단계는 엔지니어가 실시간으로 지켜보지 않아도 흘러간다. 실패나 자체 중단이 나면 즉시 내려간다.
_피할 말_: 완성도(한 장비군의 "완성"과 헷갈린다)

**라이브 영역 (Live region)**
측정 장비 화면에서 실시간 영상(SEM 영상, 스테이지 화면 등)이 계속 바뀌는 부분. 엔지니어 조작이 없어도 바뀐다.

**조작 영역 (Control region)**
버튼, 입력란, 목록, 팝업처럼 엔지니어 조작에 따라 바뀌는 화면 부분.

**화면 영역 지도 (Screen region map)**
장비군의 대표 화면마다 라이브 영역과 조작 영역을 나눠 적은 것. 담당 엔지니어가 정한다.

**상시 관찰 모드 / 녹화 모드 (Observation mode / Recording mode)**
상시 관찰은 프로그램이 켜져 있는 동안 조작 영역이 바뀔 때만 화면을 1장씩 남긴다. 녹화는 엔지니어가 시작하거나 Align Fail 대응 중일 때 초당 10장으로 남긴다.

**중요 프레임 (Key frame)**
녹화 원본을 서버에서 다시 처리해 영구 보관하기로 고른 화면. 조작 직전, 직후, 화면 전환, 값 변경, 팝업, 경고.

**빠른 첫 통과 (Fast first pass)**
작은 대상 하나(2027 상반기 Align Fail 자동 대응)를 플랫폼 부품으로 먼저 끝까지 만들어, 장기 플랫폼에 필요한 요소를 찾아내는 방식. 버리는 시제품이 아님.
_피할 말_: PoC(이미 끝난 1차 PoC와 헷갈린다)

**요소 목록 (Element list)**
빠른 첫 통과가 끝날 때 내는 목록. 쓰인 요소마다 재사용, 고쳐 쓰기, 버림을 적고 플랫폼 7개 기능에 대응시킨다.

**의미 단계 (Semantic step)**
절차 안에서 시작 조건과 완료 조건을 따로 확인할 수 있는 작업 하나. 클릭 여러 개를 묶은 것. 예: 레시피 사본 만들기.

**조작 단위 (Skill)**
Agent가 한 번에 실행하는 화면 조작 묶음. 사전조건, 인자, 사후조건, 재시도 한도를 계약으로 정한다. Agent는 조작 단위 하나를 실행할 때마다 화면을 다시 보고 결과를 확인한다.
_피할 말_: 스킬(에이전트 도구의 skill과 헷갈린다)

**시연 (Demonstration)**
엔지니어 녹화에서 뽑은 한 번의 작업 기록. 지식 자산의 근거이며 명령이 아니다.

**규칙 확인 (Policy gate)**
AI가 제안한 조작을 서버가 권한, 허용 분기, 인자, 값과 단위로 다시 확인하는 단계. 거부하면 실행하지 않는다.

**Shadow 제안 (Shadow suggestion)**
Agent가 실제 화면을 보고 다음 조작을 제안만 하고 입력은 하지 않는 운영. 화면 입력을 열기 전에 판단 정확도를 재는 데 쓴다.

**작업용 사본 (Recipe draft)**
원본 레시피를 바꾸지 않고 수정하려고 만든 사본. 운영 적용은 별도 승인이다.

**Offline 지식화, Online 실행**
공통 플랫폼의 두 갈래. Offline은 녹화에서 승인된 절차와 노하우를 만들고, Online은 현재 화면을 확인하며 조작 단위를 하나씩 실행한다. Codex 설계의 "Workflow"는 이 문서의 **절차**다.

## 관계

- 절차와 노하우가 모여 지식 자산이 된다.
- 돌파구 추천은 막힘에서 지식 자산을 찾아 쓴다.
- 빠른 첫 통과의 요소 목록이 장기 계획(2027 하반기, 2028, 2029)의 입력이 된다.
- 관찰은 화면을 주로 보고, 장비 데이터와 시스템 DB는 읽기만 한다.
