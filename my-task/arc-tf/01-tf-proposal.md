# Auto Recipe Creation TF 구성 기획안

> MI 장비 Recipe 셋업을 AI가 마우스와 키보드를 직접 조작하는 컴퓨터 사용(Computer-use) 기반으로 자동화하려고 합니다. R&D MI 현업 엔지니어들과 협업해 자동화 공통 플랫폼을 개발하고자 합니다.

## 요약

**핵심 개발 방향**: 공통 플랫폼을 통해 AI가 지식 자산화된 마우스, 키보드 조작과 레시피 셋업 방법을 그대로 수행할 수 있는가를 검증하고 구현함

**요청 사항 (2026-12)**

- ARC TF 구성 승인: 공통 플랫폼 팀(개발 2명)과 장비군 담당 엔지니어로 2027-01부터 운영
- **1차 지정군**: CD-SEM, Thickness, VeritySEM 담당 엔지니어의 TF 조직도 협업 요청 (장비군마다 1~2명, 주 5시간)
  - 지정 사유: 이미 ARC 작업이 진척 중이며 엔지니어들도 기본적인 데이터 흐름과 작업 방식을 알고 있음
  - 공통 플랫폼의 기초 틀이 될 수 있도록 작업
- **2차 지정군 (선택)**: Inspection 장비군
  - 1차 지정군 장비로 얻은 작업 노하우를 2차 장비군에 적용
  - 공통 플랫폼 개발을 실제로 적용하는 첫 대상
- 개발 인력 2명: 1인당 업무 시간 50% 투입 (실질 1명)

**확인 필요 사항 (R&D MI H/W 담당자)**

- 장비 화면 녹화분 DB에 직접 접근할 수 있는지 확인 필요
  - 가능하면: 녹화분을 바로 받아 써서 개발 속도가 빨라짐
  - 불가능하면: RCS에서 GUI 자동화로 녹화분을 내려받아야 함 (속도가 느리고 불편함)
- 스크린샷과 녹화 영상을 매우 많이 쓰므로 스토리지 소모량이 매우 큼. 추후 스토리지 자산 확보가 필요함

**2027년 타겟**

| 시점 | 타겟 | 판정 |
|---|---|---|
| 2027 상반기 | CD-SEM, Thickness의 **Align Fail 자동 대응 완성** (실알람 무인 대응) | 2027-06 |
| 2027 연말 | 1차 지정군 3개 장비의 셋업 절차, 노하우를 **지식 자산**으로 축적, 막힌 지점에서 바로 찾아 씀 | 2027-12 |

- 셋업 시간 단축은 2028 보조 단계부터, Agent가 레시피 셋업을 진행하는 자율 단계는 2029 타겟임
- 필요 자원: 개발 2명(각 50%, 실질 1명), 담당 엔지니어 겸직, 기존 사내 VLM 서버와 사내 서버 자원, 녹화 스토리지. 새 서버 구매 없음

## 1. 배경과 문제

### 문제

- 레시피 셋업은 숙련 엔지니어가 원격 제어 화면에서 마우스와 키보드로 하는 반복 수작업임. 측정 위치를 잡을 때 측정, 실패, 재조정을 되풀이함
- 노하우가 개인에게 있음. 담당자가 바뀌면 지식이 사라지고 사람마다 품질이 다름
- 관리 장비가 늘어나거나 개발 제품이 증가하면 셋업 인력도 같은 비율로 늘어나야 하나, 이 구조로는 한계가 있음
- 측정 중 Align Fail(정렬 실패) 알람이 나면 엔지니어가 원격으로 위치를 다시 잡을 때까지 장비가 멈춤

### 안 하면 생기는 일

- ⟨확인: 신규 제품, 공정 도입 때 레시피 셋업 대기로 늦어지는 기간⟩
- ⟨확인: 장비군별 레시피 셋업에 쓰는 엔지니어 시간 (월 기준)⟩
- ⟨확인: Align Fail 알람으로 멈추는 장비 시간 (월 기준)⟩
- 장비군마다 따로 자동화를 시도하면 화면 인식, 조작, 안전 장치를 매번 새로 만들게 됨

## 2. 목표와 기대 효과

가장 중요한 개발 방향은 **공통 플랫폼을 통해 AI가 지식 자산화된 마우스, 키보드 조작과 레시피 셋업 방법을 수행할 수 있느냐**입니다. 아래 단계는 모두 이 질문에 답하기 위한 순서입니다.

### 단계별 목표

| 단계 | 시기 | 목표 | 회사에 남는 것 |
|---|---|---|---|
| Align Fail 자동 대응 | 2027 상반기 | CD-SEM, Thickness 실알람 무인 대응 | 장비 가동 시간 회수 |
| 관찰과 지식화 | 2027 | 엔지니어 작업 녹화에서 절차, 노하우를 뽑아 지식 자산으로 축적, 막힌 지점에서 돌파구 추천 | 노하우의 조직 자산화 |
| 보조 | 2028 | 엔지니어가 보는 앞에서 반복 입력 대행, 막힘 자동 감지 | 엔지니어 직접 투입 시간 감소 |
| 자율 | 2029 | Agent가 레시피 셋업을 진행하고 특이 사항, 위험 때만 엔지니어가 개입 (CD-SEM, Thickness) | 셋업 인력을 장비 수에 비례해 늘리지 않음 |

### 효과 지표

| 효과 | 측정 지표 | 현재 | 목표 | 타겟 시점 |
|---|---|---|---|---|
| 장비 가동 시간 회수 | Align Fail 장비 정지 시간의 감소분 (월) | ⟨확인⟩ | ⟨확인⟩ | 2027 상반기 |
| 지식 자산화 | 절차서로 정리된 레시피 유형 수 | 0 | 장비군마다 ⟨N⟩개 이상 | 2027 연말 |
| 막힘 해소 | 돌파구 추천 채택률 | - | ⟨확인⟩% | 2027 연말 |
| 엔지니어 투입 감소 | 1건당 엔지니어 직접 투입 시간, 예정에 없던 개입 횟수 | ⟨확인⟩ | ⟨확인⟩ | 2028 |
| 셋업 시간 단축 | 레시피 1건 셋업 경과 시간 | 레시피당 평균 30~60분 (현업 경험치, 셋업 전체 기준) | ⟨확인⟩% 단축 | 2028 |
| 품질 균일화 | 셋업 뒤 첫 측정 성공률 | ⟨확인⟩ | ⟨확인⟩ | 2029 |
| 확장성 | 새 장비군 합류에 드는 기간 | - | ⟨확인⟩ | 2029 |

셋업 시간의 현재 값은 현업 경험치입니다. 자동화 대상 구간의 실측값과 나머지 현재 값은 TF 온보딩 기간(2027-01~02)에 담당 엔지니어가 직접 측정해 확정하겠습니다. 측정하기 전에는 목표를 숫자로 정하지 않습니다.

**시간 구분**: 효과를 계산할 때 세 가지 시간을 나눠 셉니다.

- 작업 경과 시간: 셋업 시작부터 끝까지 걸린 시간
- 엔지니어 직접 투입 시간: 엔지니어가 실제로 조작, 판단, 승인에 쓴 시간. 회사 효과 계산에는 이 값을 씀
- 장비 정지 시간: Align Fail 등으로 장비가 멈췄다가 다시 측정하기까지의 시간. 회수한 장비 가동 시간은 이 정지 시간의 감소분으로 셈

**측정 규칙** (기준선과 이후 측정을 같은 조건으로 비교하기 위해 온보딩 측정 양식에 고정)

- 대상: 장비군마다 정한 대표 레시피 유형 1개. 전체 셋업이 아닌 **자동화 대상 구간(측정 위치, Align 셋업)** 의 시작과 끝을 정해 측정
- 포함: 그 구간 안의 실패, 재작업, 수동 인계 시간. 승인 대기 시간은 별도 기록
- 개입 횟수: 반드시 거치는 승인(저장 전 등)은 제외하고 **예정에 없던 개입**만 집계

### 엔지니어 시간이 줄면 회사에 무엇이 남는가

```
레시피 셋업 수요(건/월) × 건당 엔지니어 직접 투입 시간 감소분
  → 회수되는 엔지니어 시간 (월 ⟨확인⟩시간)
  → 신규 제품, 공정 도입 때 셋업 대기 단축, 엔지니어가 분석, 개선 업무로 이동
  → 장비가 늘어도 셋업 인력을 같은 비율로 늘리지 않아도 됨
```

- 가정: ⟨확인: 장비군별 월 셋업 수요와 증가 추세⟩. 셋업 수요가 장비, 제품 수와 함께 늘어야 "인력이 비례해야 한다"는 주장이 성립함

## 3. 이미 확보한 것

### 1차 PoC (Align Fail 대응 자동화)

ARC는 처음부터 레시피 자동 생성을 목표로 했습니다. 1차 PoC로는 범위가 좁고 효과를 재기 쉬운 **Align Fail 무인 대응**을 선택했고 이 PoC에서 레시피 자동 생성에 그대로 쓸 기반을 검증했습니다.

| 확보한 것 | 레시피 자동 생성에서의 쓰임 |
|---|---|
| 사내 인프라에서 화면 이해 모델(VLM, OCR) 자체 운영 | 외부 API 없이 화면 이해 |
| 표준 컴포넌트가 아닌 계측 화면에서도 대략 위치 → 정밀 좌표 → OCR 확인 순서로 클릭 | API 없는 장비 화면 조작 |
| VLM은 "어디를 볼지", CV는 "정확히 어디인지"를 맡는 역할 분리 원칙 | 측정 위치, Align Key 등록의 정확도 |
| 최근 성공 사례를 모은 기준 이미지로 Align Key 탐색 정확도 개선 (오프라인 평가 기준) | 레시피 Align 셋업 |
| 실장비 반자동 운영: 위치 재조정은 자동, 최종 확정은 엔지니어 | TF의 안전 원칙 |
| 엔지니어 작업 녹화 → 조작 타임라인 → 한국어 절차서 | 장비별 레시피 절차 정의 |
| SecureVDI 경유 화면에 키보드, 마우스 입력 가능 확인 (2026-11) | VeritySEM, Thickness도 같은 방식으로 조작 |

상세 목록은 [PoC 자산과 남은 과제](./05-poc-assets.md)에 있으며 수치는 사내용 문서에만 둡니다.

### 현업이 이미 만든 자동화 (Thickness)

- Thickness 담당자들이 PyAutoGUI 기반으로 자동화해 둔 작업이 많음. 고정 좌표와 정해진 순서로 반복 입력을 처리하는 방식임
- 검토 과제: 이 PyAutoGUI 자동화와 VLM 기반 방식을 어떻게 섞어 쓸지 정해야 함
  - 정해진 순서의 반복 입력: 검증된 PyAutoGUI 스크립트를 그대로 재사용
  - 화면 인식과 판단이 필요한 구간 (위치 확인, 예외 화면, 막힘): VLM이 맡음
  - PyAutoGUI 스크립트 앞뒤에 VLM 화면 확인을 붙여, 화면이 예상과 다르면 멈추게 함
- 2027-01~02 온보딩 때 Thickness 기존 스크립트를 목록화하고, 2027-06 요소 목록에 혼합 방식을 반영함

**PoC로 확인한 것**: API 없는 장비 화면을 보고 조작 가능, 오프라인 평가에서 Align Key 탐색 가능, SecureVDI 경유 입력 가능

**아직 확인하지 못한 것**과 확인 시점:

| 항목 | 확인 시점 |
|---|---|
| SecureVDI 경유 화면에서도 VLM 인식 정확도가 직접 접속과 같은가 | 2027 상반기 Thickness Align Fail 운영 |
| PyAutoGUI 기존 자동화와 VLM 방식을 섞었을 때 안정적으로 동작하는가 | 2027 상반기 Thickness Align Fail 운영 |
| Agent가 엔지니어가 한 작업의 의미를 파악하고 그대로 따라 진행할 수 있는가 | 2027 하반기 절차화, 2028 보조 단계 |
| 새로운 측정 파라미터를 추가할 때, 의뢰서를 근거로 위치를 찾고 몇 차례 조정을 거쳐 이미지를 제대로 등록할 수 있는가 | 2028 보조 단계, 2029 자율 단계 |

모두 장비 화면과 레시피 절차를 아는 현업 엔지니어들과 함께 검증해야 합니다. 그래서 TF가 필요합니다.

## 4. 추진 방안

### 범위

| 구분 | 내용 |
|---|---|
| 최종 목표 | 신규 레시피 셋업의 전 과정 자동화: 생성 → 측정 위치, Align Key 등록 → 파라미터 → 검증 측정 → 저장 |
| 2027 상반기 선행 과제 | **Align Fail 자동 대응** (CD-SEM, Thickness). 플랫폼 부품으로 먼저 완성해 장기 플랫폼에 필요한 요소를 찾아냄 |
| 레시피 셋업 자동화 대상 구간 | 시행착오가 가장 많은 **측정 위치, Align 셋업 구간**. 2027에는 관찰과 지식화, 2028부터 엔지니어 앞에서 Agent가 입력을 대행, 2029에 Agent가 진행 |
| 1차 지정군 | CD-SEM, Thickness, VeritySEM. 공통 플랫폼의 기초 틀을 만듦 |
| 2차 지정군 (선택) | Inspection 장비군. 1차 지정군에서 얻은 노하우와 공통 플랫폼을 실제로 적용 |
| 실행 방식 | 설치형 프로그램을 엔지니어에게 배포하고 엔지니어가 **자기 PC에서** AI 자동화 프로그램과 함께 작업. 장비 PC에는 설치하지 않음. 접속 경로는 장비군마다 다름: CD-SEM은 엔지니어 PC에서 RCS로 직접, VeritySEM, Thickness는 SecureVDI(웹 VDI)의 가상 Windows 안에서 RCS나 Radmin Viewer로 접속. Agent는 어느 경로든 엔지니어가 보는 화면(FHD 모니터 기준)을 캡처하고 같은 화면에 입력 |
| 녹화분 확보 | 장비 화면 녹화분 DB 직접 접근(가능 여부를 R&D MI H/W 담당자에게 확인), 불가하면 RCS에서 GUI 자동화로 다운로드 |
| 제외 | 장비 유지보수, 하드웨어 제어, 장비 내부 소프트웨어 설치 |

### 자동화 수준과 안전 원칙

- **반자동(Supervised Autonomy)이 원칙임**: Agent가 조작하고, 위험 조작(측정 실행, 삭제, 모드 변경)과 레시피 저장, 적용 직전에는 엔지니어가 승인
- **Align Fail 무인 대응은 승인된 예외임**: 허용 조작은 레시피를 바꾸지 않는 위치 재조정과 해당 지점 재측정 재시도뿐임. 저장, 삭제, 모드 변경, 레시피 수정은 계속 금지. 인식이 불확실하거나 화면이 예상과 다르면 Agent가 스스로 멈추고 엔지니어를 부름
- **무인 전환 승인**: 반자동 운영 실적을 리드가 정리하고, 담당 엔지니어 확인을 거쳐 월간 보고에서 장비별로 승인받음
- 레시피 셋업의 완전 자동은 반복 검증과 자체 중단 기록까지 통과한 레시피 유형만 단계 승인을 거쳐 검토함

### TF 구성

| 구분 | 구성 | 맡는 일 |
|---|---|---|
| TF 리드 + 공통 플랫폼 팀 | TF 리드 포함 개발 2명 | 화면 인식, 조작 엔진, 안전 규칙, 승인 화면, VLM 연동, 교육 |
| CD-SEM 담당 | TF 리드 | 장비별 레시피 절차, 성공 판정 기준, 현장 검증 |
| Thickness 담당 | MI 엔지니어 | 위와 같음. 기존 PyAutoGUI 자동화 공유 |
| VeritySEM 담당 | MI 엔지니어 | 위와 같음 |
| 2차 지정군 담당 (선택) | Inspection 장비군 MI 엔지니어 | 1차 기간에는 학습과 작업 녹화, 절차서 정리 |

- **공통 플랫폼**: 모든 장비군이 함께 사용. 장비마다 엔진을 새로 만들지 않음
- **장비군 담당**: MI 현업 엔지니어 1~2명으로 구성. 그 장비의 레시피 절차 정의, 성공 판정 기준, 현장 검증을 맡음
- **2차 지정군 담당**: 참여가 정해지면 1월에 함께 합류. 1차 기간에는 학습을 받고 담당 장비 작업을 녹화해 절차서로 정리. 플랫폼 준비 후 바로 투입
- **인프라(GPU, VLM 서빙)**: 필요 시점에 합류. 장비 벤더는 필요할 때 자문

**개발 인력 배분 (2명 필요, 1인당 업무 시간 50% 투입 = 실질 1명)**

| 시기 | TF 리드 | 개발 1명 |
|---|---|---|
| 2027 상반기 | Align Fail 자동 대응 (CD-SEM 담당 겸임) | 녹화분 확보 경로, 서버 수집, 화면 영역 지도 |
| 2027 하반기 | 절차화, 지식 자산, 돌파구 추천 | 상시 관찰 모드 완성, Align Fail 운영 유지, 절차 추출 파이프라인 |

- 두 사람 모두 개인 과제를 병행하므로 TF 전담은 불가함. 각자 업무 시간의 50%를 TF에 씀
- 상반기에는 Align Fail을 우선함. 관찰과 지식화는 녹화 축적까지만 하고, 상시 관찰 모드와 PC 자원 한도 검증은 3분기 초로 미룸
- 온보딩 교육(2027-01~02)은 두 사람이 나눠 맡음
- 인력이 늘면 상시 관찰 모드와 채팅을 먼저 당김
- 인력이 모자라면 채팅 기능(관문 밖)을 먼저 미루고, 다음으로 돌파구 추천 대상 장비군을 줄임

역할 분담은 [참여 팀과 역할](./02-roles-and-teams.md)에 있습니다.

## 5. 일정

2027년은 두 갈래로 진행합니다. 상반기에 **Align Fail 자동 대응을 빠른 첫 통과로 완성**하고 같은 기간에 레시피 셋업 자동화의 바탕인 **관찰과 지식화**를 쌓습니다. Align Fail은 일회성 시제품이 아니라 플랫폼 부품(화면 캡처, 화면 영역 지도, 입력 실행기, 자체 중단, 실행 로그)으로 만들고 그 과정에서 필요했던 요소를 장기 계획에 반영합니다.

### 관문과 2028 진입 조건

- 2028 보조 단계(반복 입력 대행)로 넘어가려면 두 가지가 필요함
  - 관찰과 지식화 관문 통과
  - 공통 기술, 안전 요건 충족: 입력 실행기가 실장비에서 의도한 조작만 하고, 불확실할 때 스스로 멈추는 것이 운영 기록으로 확인됨
- Align Fail의 성과 목표(자동 해결률, 회수 시간)는 별도 성과 과제이므로, 미달이어도 위 두 조건을 채우면 2028 진입을 막지 않음. 미달분은 보완, 축소 결정 대상이 됨

**단계 통과 결정**: 관문마다 리드가 통과 기준과 결과를 정리하고 담당 엔지니어의 품질 확인을 받아 월간 보고에서 승인받겠습니다. 기준에 못 미치면 **보완**(기간 연장), **축소**(대상 유형, 장비군 축소), **중단** 중 하나를 정해 [결정 기록](./decision-log.md)에 남깁니다.
