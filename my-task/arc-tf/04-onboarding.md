# 주간 미팅과 노하우 공유

> 개발과 AI에 익숙하지 않은 MI 현업 엔지니어가 AI Agent로 레시피를 자동화할 때 알아야 할 배경 지식과, 장비군마다 따로 쌓인 개발 노하우를 매주 미팅에서 나누기 위한 자료. 교육 과정이나 세미나를 따로 두지 않고, 매주 미팅에서 개발 노하우를 공유하고 현재와 앞으로의 진행사항을 확인하며 TF를 운영한다.

| 자리 | 주기 | 참석 | 하는 일 |
|---|---|---|---|
| 주간 미팅 | 매주 | 개발자, 현업 엔지니어 | 개발 노하우 공유(아래 주제를 한 주에 하나씩), 장비군별 현재 진행사항과 앞으로 할 일 확인, 막힌 지점 질의, 실전 피드백 ([운영 방식](./03-operating-rhythm.md)) |

2차 장비군 담당 엔지니어는 합류 시점(2027-07)부터 같은 주간 미팅에 참석한다. 앞선 주제는 발표 자료로 따라온다.

## 왜 필요한가

담당 엔지니어는 장비와 레시피는 잘 알지만, LLM, VLM이 무엇을 잘하고 무엇을 못하는지는 모른다. 이걸 모르면 두 가지가 생긴다.

- Agent에게 맡기면 안 되는 판단(정밀 좌표, 반복 가능한 판정)을 맡기는 절차를 쓴다.
- Agent가 실패했을 때 원인이 모델인지, 화면 품질인지, 절차 정의인지 구분하지 못한다.

또 자동화 방법, 사내 DB 테이블 같은 작업 방법은 장비군마다 따로 쌓여 있어, 나누지 않으면 같은 작업을 반복한다.

목표는 엔지니어가 **자기 장비의 레시피 절차를 Agent가 실행할 수 있는 형태로 정의하고, 결과를 판정할 수 있게** 되는 것이다. AI 개발자를 만드는 자리가 아니다.

## 전제

- **Python 기초 문법은 사전 자료로 제공한다.** 미팅에서는 코드를 읽고 간단히 고치는 정도까지만 실습으로 맞춘다.
- 겸직 시간(주 5시간) 안에서 진행한다. 노하우 공유는 짧게 하고, 실습은 미팅 밖 TF 업무 시간에 이어 간다.
- 기초 주제는 리드와 공통 플랫폼 팀이 발표한다. 작업 방법 공유는 장비군 담당 엔지니어가 돌아가며 발표한다.
- 2차 장비군이 합류하면 선발대 엔지니어가 실습을 돕는다.

## 노하우 공유 주제

순서는 TF 진행에 맞춰 정한다. 기초 주제(1~4)를 먼저 다루고, 작업 방법 공유(5)는 그 뒤로 이어 간다.

| 번호 | 주제 | 다루는 것 | 실습 |
|---|---|---|---|
| 1 | TF와 플랫폼 개요, Git, LLM과 VLM의 특성 | ARC 목표, 장비군 담당의 역할, 저장소 구조, 브랜치와 리뷰. LLM, VLM이 잘하는 것(화면 의미 이해, 설명)과 못하는 것(좌표가 흔들림, 기억 없음, 환각), 프롬프트가 결과를 바꾸는 방식 | 저장소 받기, 문서 수정 PR. 같은 화면을 여러 번 물어보고 답이 흔들리는 것 확인하기 |
| 2 | VLM과 CV 역할 분리, 컴퓨터 사용 Agent, 안전 규칙 | "어디를 볼지"는 VLM, "정확히 어디인지"는 CV. 화면 캡처 → 판단 → 조작 → 검증 순환과 실패 유형(화면 품질, 모델, 절차). 검증 실패 시 중단, 되돌릴 수 없는 조작, 저장 전 승인, 증거 기록 | PoC의 Align Key 탐색 점수 해석하기. 비생산 화면에서 클릭, 입력 시켜 보기. 실패 기록을 보고 원인 분류하기 |
| 3 | 작업 녹화 → 절차서 → 플랫폼 절차 정의 | 화면 녹화, 조작 타임라인, 한국어 절차서. 단계, 각 단계의 성공 조건, 실패 시 행동, 조작별 승인 분류 | 자기 장비 레시피 셋업 1건을 녹화해 절차서로 만들고, 절차 정의로 옮겨 녹화본에 대고 모의 실행하기 |
| 4 | 기준선 측정과 판정 기준 | 측정 양식 쓰는 법, 성공 판정 기준 정하기 | 장비군별 대표 레시피 유형, 판정 기준, 기준선 측정 계획 발표 |
| 5 | ARC 작업 방법 공유 (이어 가는 주제) | 장비군이 쓰는 자동화 방법, 사내 DB 테이블 등 ARC에 쓸 수 있는 효율적인 작업 방법 | 발표한 방법을 다른 장비군이 자기 작업에 적용해 보기 |

공통 플랫폼 베타가 나오기 전(2027 상반기)에는 실습을 **녹화본과 모의 실행**으로 한다. 베타 뒤에는 베타 플랫폼으로 녹화, 절차 정의, 입력 없는 모의 실행을 실습한다. 입력 실습은 비생산 화면에서 승인이 필요 없는 조작만 쓰고, 실장비 입력은 승인된 Align Fail 범위로 한정한다.

## 기준선 측정 양식

주제 4에서 양식을 익히고, 장비군마다 합류 첫 달에 이 양식으로 잰다 (선발대 2027-02까지, 2차 장비군 2027-08까지). 파일럿에서도 같은 양식을 쓴다.

| 항목 | 적는 것 |
|---|---|
| 레시피 유형 | 장비군 담당의 대표 유형 1개 |
| 구간 | 자동화 대상 구간(측정 위치, Align 셋업)의 시작 화면과 끝 화면 |
| 소요 시간 | 구간 안의 실패, 재작업, 수동 인계를 포함한 시간. 승인 대기는 따로 |
| 예정에 없던 개입 | 반드시 거치는 승인은 빼고 센다 |
| 첫 측정 결과 | 셋업 뒤 첫 측정의 성공/실패 |
| 표본 수 | ⟨확인: 유형당 최소 건수⟩ |

기준선 측정 결과가 [TF 구성 기획안](./01-tf-proposal.md)의 ⟨확인⟩ 칸(현재 셋업 시간, 목표 단축률)을 채운다.

## 노하우 공유로 갖추려는 것

- 자기 장비 레시피 셋업 1건의 절차서가 있다.
- 그 절차를 플랫폼 절차로 정의하고, 녹화본에 대고 모의 실행해 봤다.
- Agent 실패 기록을 보고 원인(화면 품질 / 모델 / 절차 정의)을 구분할 수 있다.
- 장비군 담당의 성공 판정 기준과 기준선 측정 계획(대표 레시피 유형, 표본)이 정해져 있다.

## 선택 과정

더 깊이 알고 싶은 엔지니어는 [AI/DT 교육 커리큘럼](../ai-dt-curriculum/README.md)에서 준비 중인 오픈웨이트 LLM 심화 과정을 추가로 들을 수 있다. TF 주간 미팅과는 별개다.
