## 1. 회사에 기여한 것 (Company Impact)

### 1-1. 정렬 실패 대응 Agent — 수작업 손실 제거, 회사 공식 포상

**전략적 위치 — 의뢰 통합 처리(One Stop) 체계 → 레시피 자동 생성 파이프라인의 첫 PoC.** 센터는 모든 의뢰를 한 곳에서 처리하는 One Stop 체계를 추진 중이고, 그 핵심은 일괄 접수한 의뢰를 받아 **레시피를 자동 생성·튜닝하는 파이프라인**이다. 정렬 실패 처리에는 이미지 처리·VLM 자동화·소규모 레시피 튜닝이 모두 들어가므로, 파이프라인 요소 기술을 한 번에 검증할 수 있는 과제로 골라 PoC로 진행했다. 따라서 이 과제의 성과는 정렬 실패 한 건에 그치지 않고 **센터 중점 과제의 기술 검증 결과**이기도 하다.

| 질문 | 내용 |
|---|---|
| 문제 | 계측 장비 정렬 실패가 전체 측정의 약 10%에서 발생, 엔지니어가 매번 화면을 보고 수동 재정렬 → 수작업 손실 + 대응 지연 동안 장비 정지 |
| 안 하면 | 장비 대수가 늘수록 손실이 비례해 커지고, 야간·교대 시간대 대응 공백이 계속된다 |
| 한 일 | VLM 판단 → 애매한 건만 사람에게 에스컬레이션하는 무인 처리 구조 설계·구현. GUI 클릭 자동화, 기준 표식 없이 주변을 훑는 Search Around 개발 |
| PoC 결과 | CV 정렬 성공률 **약 25%p 향상(저배율)**, 클릭 성공률 **99% 수준** |
| 배포 시 기대효과 | 건당 처리 시간 **80% 단축**, 절감 시간만큼 측정 가능량·장비 가동률 증가. 정성: 야간·주말 공백 없는 24h 대응, 숙련도 의존 제거 *(배포 전 목표값)* |
| 인정 | **사내 AI 행사 AX 혁신 공모전 수상** |

추가로, 사내 AI 과제 기획 방법론으로 이 과제의 **실행기획 11단계를 직접 완주**했다. 개발자가 기획 산출물(Pain 정량화·As-Is/To-Be·기대효과)까지 쓴 사례라서, 부문의 다른 AI 과제가 따라 쓸 수 있는 기준 사례가 되었다.

### 1-2. 계측 장비 관리·분석 플랫폼 — 타 조직 TF가 기대는 데이터 기반

| 질문 | 내용 |
|---|---|
| 문제 | 계측 장비 데이터·통계를 얻으려면 담당자에게 묻고, 받고, 다시 확인하는 소통 왕복이 반복됐다 |
| 안 하면 | 엔지니어 업무가 "데이터 기다리기"에 묶이고, 계측 효율화 같은 부문 과제는 근거 데이터를 매번 수작업으로 모아야 한다 |
| 한 일 | v3 전면 재구축 (코드 약 40배, 엔터프라이즈급). 대상 장비 약 1.5배, 사내 실데이터 연결. 디바이스 통계·통합 분석 대시보드·장비 간 편차 분석·실시간 알람·RAG 어시스턴트 신규 개발 |
| 효과 ① (대표 사례) | **계측 효율화 TF의 계측 포인트 간소화는 이 플랫폼 없이는 할 수 없다** (아래 1-3 상세). **플랫폼이 있어야 가능한 일을 보여주는 단적인 예이며, 아래 기능들도 각 현업에서 함께 쓰이고 있다** |
| 효과 ② | 데이터 요청·확인용 소통 왕복을 줄여, 엔지니어가 필요한 정보를 스스로 바로 찾고 업무를 진행한다 |
| 그 밖의 기능 | • **디바이스 통계 서비스** — 디바이스별 계측 통계 (TF 사례의 기반)<br>• **통합 분석 대시보드**<br>• **장비 간 편차 분석**<br>• **실시간 알람** — 현업 교대 인력 상시 사용<br>• **RAG 어시스턴트** — 매뉴얼·알람 코드 질의<br>• **사내 실데이터 연결** — 모든 기능이 같은 데이터 위에서 동작 |
| 지표 | **현업 일상 사용 중** |

### 1-3. [플랫폼 활용 대표 사례] 계측 효율화 TF — 장비 구매 전에 효율로 메운다

플랫폼의 여러 기능 중 디바이스 통계 서비스가 타 조직 과제의 성패를 좌우하는 단적인 예다. 플랫폼의 기여는 이 사례에 한정되지 않는다(1-2 「그 밖의 기능」 참고).

| 질문 | 내용 |
|---|---|
| 문제 | 공정 중 wafer가 계속 늘면서 **장비 측정 대기 시간이 크게 증가** → 전체 흐름이 느려져 **연구 개발에 큰 악영향** |
| 목표 | **측정 대기 시간 약 1/4로 단축** — 과거 lot flow가 원활했던 시기 수준 |
| 안 하면 | 현재 기준으로 목표를 맞추려면 **계측 장비를 추가로 구매**해야 한다 |
| 합의된 방향 | 계측 효율화를 먼저 최대한 달성하고, **부족한 장비 수만 구매**한다. TF는 ① 레시피 최적화와 ② 계측 포인트 간소화를 병행 (9월 착수) |
| 내 기여 | **② 계측 포인트 간소화에는 이 플랫폼이 반드시 필요하다** — 디바이스 통계 등으로 어떤 포인트를 줄여도 되는지 판단한다 |
| 효과 | 계측 포인트 간소화 달성 시 **추가 구매 필요 장비의 약 29%** 확보, **10월 현재 약 10% 확보 추정** *(측정이 빨라진 만큼을 장비 대수로 환산한 값)* |

### 1-4. 확산 기반 — 한 건씩 전달하던 방식을 체계로

- **메신저 연동 → 웹 Application 선회**: 메신저 챗봇이 단답형 응답에만 유효하다는 걸 확인하고 방향을 빠르게 바꿔, 솔루션을 현업에 전달하는 공통 통로를 다시 잡았다.
- **부문별 AI/DT 로드맵 실체화 지원**: 만드는 일을 넘어 부문 전체의 추진 방향을 맞추는 데 기여했다.
- **장비 데이터 매핑 Agent 기획(2027)**: 과제마다 "데이터가 어디 있나"를 다시 찾는 반복을 없애는 공통 기반을 직접 제안했다.

- **1인이 엔터프라이즈급 시스템을 만드는 방식 체득**: Vibe Coding + Harness Engineering으로, 전문 개발 조직 없이 엔터프라이즈급 플랫폼을 구축·운영했다.

## 5. 승격 추천 사유

1. **성과가 회사 공식 인정으로 검증됐다** — 사내 AX 혁신 공모전 수상. 이 과제는 센터 One Stop 체계의 레시피 자동 생성 파이프라인 첫 PoC로, 센터 중점 과제의 기술 가능성을 직접 증명했다.
2. **내가 만든 것이 다른 조직의 업무 기반이 됐다** — 계측 효율화 TF가 장비 추가 구매 대신 효율화로 측정 대기를 줄이는 작업에서 계측 포인트 간소화가 이 플랫폼에 의존한다. 현업이 매일 사용한다. 개인 과제가 아니라 회사 인프라다.
3. **혼자서 고유 과제 3건 + 지원 업무를 끝까지 밀었다** — 백업 인력 없이 개발·운영·기획을 함께 감당했다.
4. **이미 상위 레벨의 일을 하고 있다** — 부문 표준 양식, 교육·인증 체계 설계, 협의체 조율, 2027 공통 기반 과제 제안. 개인 실행을 넘어 조직의 방식을 바꾸는 일이다.

- **에이전트 개발 방식 팀 전파** — 가이드·교류회로 노하우를 개인에서 팀 자산으로
