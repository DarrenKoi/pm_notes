# AI Agent 추진 현황 리뷰 — 작성 가이드

> 각 부서(임원)가 **2026 상반기 로드맵 대비 AI Agent 개발 이행 정도**를 ITC장께 5~10분으로 보고하기 위한 발표 자료 작성 안내입니다.

## 왜 이 양식인가 (Why)

- 이 리뷰의 기준선은 **상반기에 발표한 전체 로드맵**입니다. 새로 무엇을 요청하는 자리가 아니라, **약속한 로드맵을 얼마나 이행했는지**를 보여주는 자리입니다.
- 동시에 이 리뷰는 **하반기의 기준선을 남기는 자리**입니다. 장표 2의 "하반기 목표 (H2 기준선)" 컬럼이 연말 리뷰에서 그대로 "H2 계획" 칸이 됩니다 — 지금 측정 가능하게 적어야 연말에 같은 방식으로 비교할 수 있습니다.
- ITC장께서는 여러 부서 발표를 연속으로 보십니다. 그래서 **모든 부서가 동일한 4장 구조**를 사용합니다 — 부서 간 이행 정도를 한눈에 비교하기 위함입니다.
- 발표자는 각 부서 **임원**입니다. 슬라이드는 운영 세부가 아니라 **임원 눈높이의 결과·판단**을 담습니다.

## 무엇을 제출하나 (What)

각 부서는 **`템플릿_빈서식.pptx`를 열어 직접 편집**합니다. (별도 변환 작업 불필요)

| 파일 | 용도 |
|------|------|
| `템플릿_빈서식.pptx` | **이 파일을 열어 `<...>` 자리를 채웁니다.** 부서별 발표 원본. |
| `예시_채워진샘플.pptx` | 채워진 예시(가상 부서). 어느 수준으로 쓸지 참고용. |
| `작성가이드.md` | 이 문서. 채우는 방법·기준. |
| `*.md` (동명 파일) | pptx의 원본 마크다운. 부서는 쓸 필요 없고, 서식을 고칠 때만 씁니다. |

작성 흐름: `템플릿_빈서식.pptx` 복사 → PowerPoint에서 `<...>` 자리 채움 → `부서명_발표.pptx`로 저장 → 발표.

**작성 주체 (역할 분담):**

1. **과제 담당 엔지니어** — 자기 과제의 장표 2 행(계획·실적·이행도·미달 사유·H2 목표)과, 대표 과제로 선정된 경우 장표 3 심화 내용을 초안 작성
2. **부서 취합 담당** — 행을 모아 한 파일로 취합, 총평(롤업) 한 줄과 장표 4 초안 작성
3. **발표 임원** — 이행도 자기평가·상태(🟢🟡🔴)·총평을 검수하고 최종 확정

> 이행도와 상태는 엔지니어의 초안 값을 임원이 **승인**하는 구조입니다 — 최종 숫자의 책임은 발표 임원에게 있습니다.

## 어떻게 채우나 (How)

### 4장 구조와 시간 배분 (총 5~10분)

| 장표 | 내용 | 권장 시간 |
|------|------|-----------|
| 1. 표지 | 부서명 · 발표 임원 · 발표일 | 0.5분 |
| 2. 상반기 로드맵 이행 총괄 | 포트폴리오 표 + 한 줄 총평 | 2~3분 |
| 3. 대표 과제 심화 | As-Is → To-Be + 증거 | 2~3분 |
| 4. 이슈·리스크 · 하반기 중점 | 걸림돌 + 하반기 방향 | 1~2분 |
| (부록) 부서 재량 | 로드맵 수정 사항 + 그 밖의 보강 자료 — **필요 시** | 발표 안 함 |

> 부록은 **부서 재량 공간**입니다. 발표는 하지 않고 질문이 나올 때만 펼칩니다. 넣을 게 없으면 부록 장을 지웁니다. 부서 간 비교는 어디까지나 **1~4장**으로 합니다.

### 장표 2 — 포트폴리오 표 (이 리뷰의 핵심)

상반기 로드맵에서 **우리 부서가 약속했던 AI Agent 과제를 모두** 한 행씩 적습니다. 과제가 1개면 1행, 여러 개면 여러 행입니다.

컬럼 정의:

| 컬럼 | 무엇을 적나 |
|------|-------------|
| 과제명 | 로드맵에 있던 에이전트/과제 이름 **그대로** (로드맵 과제 ID가 있으면 병기) |
| H1 계획 | 상반기에 약속한 목표 (예: "PoC 완료", "적용률 70%") |
| 실적 | 실제 이룬 것 (같은 단위로) |
| 이행도 | 계획 목표를 100으로 볼 때 달성 비율(%) — 자기평가 |
| 상태 | 🟢 / 🟡 / 🔴 (아래 기준) |
| 미달 사유 | 100% 미만이면 **왜** 그런지 한 줄. 달성이면 `—` |
| 하반기 목표 (H2 기준선) | H2에 달성할 목표를 **측정 가능한 한 줄**로 (자원 요청 아님). 이 칸이 연말 리뷰의 "H2 계획" 칸이 됩니다 — "고도화 지속" 같은 방향 표현이 아니라 "전 라인 이관", "정확도 80%"처럼 됐는지 안 됐는지 판정 가능한 문장으로 |

**상태 기준:**

- 🟢 **정상** — 계획 대비 이행 **90% 이상**
- 🟡 **주의** — **50~89%** (지연 또는 부분 이행)
- 🔴 **위험** — **50% 미만** (미착수 또는 중대 지연)

**한 줄 총평 (부서 롤업):** 표 아래에 부서 전체를 한 문장으로 요약합니다. **상태 개수를 먼저** 적고 핵심 판단을 붙입니다.

- 형식: `N개 과제 · 🟢 M / 🟡 K / 🔴 L — <한 문장 판단>`
- 예: `5개 과제 · 🟢 3 / 🟡 1 / 🔴 1 — 3개 정상 이행, 로그 진단은 데이터 편중으로 지연.`
- 부서 전체 현황은 **이 총평 한 줄로 갈음**합니다. 같은 내용을 별도 앞장(요약 장)으로 중복하지 않습니다 — 표지의 "30초 임팩트"를 남겨 둡니다.

### 이행도 자기평가 — 비교 공정성

이행도(%)는 **자기평가**입니다. 부서마다 난이도·모수·측정 단위가 다르면 ITC장께서 부서를 나란히 비교하기 어렵습니다. 그래서:

- 이행도 옆(또는 미달 사유 칸)에 **무엇을 100으로 봤는지 — 모수·단위를 한 조각** 명시합니다.
  - 예: "적용률 = 대상 12개 라인 중 적용 라인 수", "정확도 = 파일럿 라벨 500건 기준".
- 절대 수치가 회사 기밀이면 **상대값(감소율·달성률·파일럿 N건 기준)**으로 적습니다.

### 장표 3 — 대표 과제 심화

부서에서 **가장 중요한 에이전트 1개**를 골라 깊이 보여줍니다.

- **As-Is**: 에이전트 도입 전 방식과 문제 (수작업 의존, 병목 등)
- **To-Be**: 에이전트 적용 후 달라진 일하는 방식
- **증거 (효과)**: 핵심 지표를 전→후로 보여주고, 거기서 **한 단계 더 환산**해 임원 언어로 옮깁니다 — 물량↓ → 인시(man-hour)·리드타임·정확도. 회사 기밀이면 절대 수치 대신 **상대 감소율 / 파일럿 기준**으로.
- **사용범위 (수용도)**: "만든 것"과 "쓰이는 것"은 다릅니다. **실사용 범위·빈도·현업 피드백 중 최소 1개**를 한 조각 덧붙입니다 (예: "3개 라인 적용·주 5회 사용" 또는 "리뷰어 3명 상시 사용"). 초기 PoC면 정성 피드백 1줄로 대체.
- **vs 계획**: 상반기 계획 대비 지금 어디까지 왔는지 한 줄 — 이 캡션으로 "자랑"이 아니라 "이행 보고"가 됩니다.

### 장표 4 — 이슈·리스크 · 하반기 중점

**이슈·리스크**에는 각 항목에 통제 주체 태그를 답니다:

- `[통제가능]` — 우리 부서가 조정할 수 있는 걸림돌 (예: 데이터 라벨링, 모델 재학습)
- `[외부의존]` — 타 부서 데이터·공통 인프라(사내 LLM 서빙 용량, 데이터 플랫폼 등)·현장 승인 등 우리 밖의 요인

> 태그는 "누구 탓"이 아니라 ITC장께서 **개입 지점을 판단**하시도록 돕는 표시입니다. 자원 요청이 아닙니다.

**하반기 중점 방향**은 대표 과제 **1~2개만 마일스톤까지** 구체화합니다 (전 과제에 일정을 달면 장표가 일정표로 과밀해집니다). 나머지 과제의 H2 목표는 **장표 2 마지막 컬럼이 기준선**이므로 여기서 반복하지 않고, 특이사항이 있을 때만 한 줄 덧붙입니다:

- 형식: `<대표 과제>: Q3 <마일스톤> → Q4 <마일스톤> / 완료 기준: <무엇을 보면 됐다고 하나>`
- "완료 기준(DoD)"이 있어야 다음 반기 리뷰의 **비교 기준선**이 자동으로 생깁니다.

### 부록 — 부서 재량 (필요 시)

부록은 각 부서가 자유롭게 채우는 공간입니다. 두 가지 용도로 씁니다:

1. **로드맵 수정 사항** — 상반기 로드맵 자체를 **고쳐야 하는 변경**(과제 추가·삭제, 목표 상향/하향, 일정 재조정)이 있으면 변경 항목 · 사유를 한 줄씩.
2. **그 밖의 보강 자료** — 본문(1~4장)에 다 못 담은 근거를 부서가 재량으로 추가합니다. 상세 지표, 추가 화면 캡처, 백업 데이터, 용어 설명, ITC장 예상 질문 대비 근거 등.

- 부록은 **발표하지 않습니다** — 질문이 나올 때 펼치는 예비 자료입니다. 5~10분 발표 시간은 1~4장에만 씁니다.
- 넣을 게 여러 개라 한 장을 넘기면 부록 장을 여러 개(장표 5, 6 …)로 쪼갭니다.
- 넣을 게 없으면 부록 장을 통째로 지웁니다. 부서 간 비교는 **1~4장**으로만 합니다.

### 정량화 / 미확정 값 원칙

- 측정 가능한 것은 **전·후 수치**로 보여줍니다.
- 아직 측정·확정 못 한 값은 **지어내지 말고** 플레이스홀더로 둡니다:
  - `<측정 예정>` — 지표는 정의됐으나 아직 측정 전
  - `<확정 전>` — 목표·범위가 아직 확정 전
- 초기 PoC라 정량치가 없으면 정성 근거(사용자 피드백, 재현 사례)로 대체하되 상태는 솔직하게 표기합니다.

### PowerPoint에서 편집할 때

- 각 슬라이드의 발표 스크립트는 **슬라이드 노트(발표자 노트)** 칸에 들어 있습니다. 노트도 우리 발표에 맞게 고쳐 쓰세요.
- 장표 2의 표는 네이티브 PPTX 표입니다. 과제가 많으면 **행을 추가**하고, 적으면 빈 행을 지웁니다.
- 상태 칸은 🟢 🟡 🔴 이모지를 그대로 입력하면 됩니다.

> **서식 자체를 바꿔야 할 때(전략팀용):** 원본은 동명의 `.md` 파일입니다. `.md`를 고친 뒤 `AIX_POC/`에서 아래를 실행해 pptx를 다시 만들어 재배포합니다.
> ```bash
> cd ../AIX_POC
> python3 tools/md2pptx.py ../report-template-ai-agent/템플릿_빈서식.md ../report-template-ai-agent/템플릿_빈서식.pptx
> ```

## 주의사항

- **회사 기밀 제외**: 구체 장비 수치·내부 시스템 상세는 넣지 않습니다. 필요하면 상대값(감소율·달성률)으로 갈음합니다.
- **솔직한 상태 표기**: 🔴도 사유가 분명하면 감점이 아니라 정보입니다. 부풀린 🟢가 더 위험합니다.
- **임원 눈높이**: 코드·아키텍처 세부가 아니라 결과와 판단 위주로 씁니다.
- **모델 전제는 공통**: 우리 에이전트는 모두 **사내 오픈소스 LLM**(외부 API 차단) 위에서 동작합니다. 이건 전 부서 공통 제약이므로 슬라이드에 자랑거리로 넣지 말고, 그로 인한 **한계·이행 제약**이 있을 때만 장표 4 리스크에 적습니다.
