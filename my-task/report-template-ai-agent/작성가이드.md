# AI Agent 추진 현황 리뷰 — 작성 가이드

> 각 부서(임원)가 **2026 상반기 로드맵 대비 AI Agent 개발 이행 정도**를 ITC장께 5~10분으로 보고하기 위한 발표 자료 작성 안내입니다.

## 왜 이 양식인가 (Why)

- 이 리뷰의 기준선은 **상반기에 발표한 전체 로드맵**입니다. 새로 무엇을 요청하는 자리가 아니라, **약속한 로드맵을 얼마나 이행했는지**를 보여주는 자리입니다.
- ITC장께서는 여러 부서 발표를 연속으로 보십니다. 그래서 **모든 부서가 동일한 4장 구조**를 사용합니다 — 부서 간 이행 정도를 한눈에 비교하기 위함입니다.
- 발표자는 각 부서 **임원**입니다. 슬라이드는 운영 세부가 아니라 **임원 눈높이의 결과·판단**을 담습니다.

## 무엇을 제출하나 (What)

각 부서는 **`템플릿_빈서식.pptx`를 열어 직접 편집**합니다. (별도 변환 작업 불필요)

| 파일 | 용도 |
|------|------|
| `템플릿_빈서식.pptx` | **이 파일을 열어 `<...>` 자리를 채웁니다.** 부서별 발표 원본. |
| `예시_채워진샘플.pptx` | 채워진 예시(가상 부서). 어느 수준으로 쓸지 참고용. |
| `작성가이드.md` | 이 문서. 채우는 방법·기준. |
| `*.md` (동명 파일) | pptx의 원본 마크다운. 부서는 쓸 필요 없고, 서식을 고칠 때만 씁니다. |

작성 흐름: `템플릿_빈서식.pptx` 복사 → PowerPoint에서 `<...>` 자리 채움 → `부서명_발표.pptx`로 저장 → 발표.

## 어떻게 채우나 (How)

### 4장 구조와 시간 배분 (총 5~10분)

| 장표 | 내용 | 권장 시간 |
|------|------|-----------|
| 1. 표지 | 부서명 · 발표 임원 · 발표일 | 0.5분 |
| 2. 상반기 로드맵 이행 총괄 | 포트폴리오 표 + 한 줄 총평 | 2~3분 |
| 3. 대표 과제 심화 | As-Is → To-Be + 증거 | 2~3분 |
| 4. 이슈·리스크 · 하반기 중점 | 걸림돌 + 하반기 방향 | 1~2분 |

### 장표 2 — 포트폴리오 표 (이 리뷰의 핵심)

상반기 로드맵에서 **우리 부서가 약속했던 AI Agent 과제를 모두** 한 행씩 적습니다. 과제가 1개면 1행, 여러 개면 여러 행입니다.

컬럼 정의:

| 컬럼 | 무엇을 적나 |
|------|-------------|
| 과제명 | 로드맵에 있던 에이전트/과제 이름 |
| H1 계획 | 상반기에 약속한 목표 (예: "PoC 완료", "적용률 70%") |
| 실적 | 실제 이룬 것 (같은 단위로) |
| 이행도 | 계획 목표를 100으로 볼 때 달성 비율(%) — 자기평가 |
| 상태 | 🟢 / 🟡 / 🔴 (아래 기준) |
| 미달 사유 | 100% 미만이면 **왜** 그런지 한 줄. 달성이면 `—` |
| 하반기 방향 | 다음 반기에 어디로 갈지 한 줄 (자원 요청 아님) |

**상태 기준:**

- 🟢 **정상** — 계획 대비 이행 **90% 이상**
- 🟡 **주의** — **50~89%** (지연 또는 부분 이행)
- 🔴 **위험** — **50% 미만** (미착수 또는 중대 지연)

한 줄 총평: 표 아래에 부서 전체를 한 문장으로 요약합니다. (예: "5개 과제 중 3개 정상 이행, 2개 웨이퍼 이동 이슈로 지연.")

### 장표 3 — 대표 과제 심화

부서에서 **가장 중요한 에이전트 1개**를 골라 깊이 보여줍니다.

- **As-Is**: 에이전트 도입 전 방식과 문제 (수작업 의존, 병목 등)
- **To-Be**: 에이전트 적용 후 달라진 일하는 방식
- **증거**: 핵심 지표(전/후 수치) 또는 화면 캡처 1장. 없으면 정성 근거라도.
- **vs 계획**: 상반기 계획 대비 지금 어디까지 왔는지 한 줄 — 이 캡션으로 "자랑"이 아니라 "이행 보고"가 됩니다.

### 정량화 / 미확정 값 원칙

- 측정 가능한 것은 **전·후 수치**로 보여줍니다.
- 아직 측정·확정 못 한 값은 **지어내지 말고** 플레이스홀더로 둡니다:
  - `<측정 예정>` — 지표는 정의됐으나 아직 측정 전
  - `<확정 전>` — 목표·범위가 아직 확정 전
- 초기 PoC라 정량치가 없으면 정성 근거(사용자 피드백, 재현 사례)로 대체하되 상태는 솔직하게 표기합니다.

### PowerPoint에서 편집할 때

- 각 슬라이드의 발표 스크립트는 **슬라이드 노트(발표자 노트)** 칸에 들어 있습니다. 노트도 우리 발표에 맞게 고쳐 쓰세요.
- 장표 2의 표는 네이티브 PPTX 표입니다. 과제가 많으면 **행을 추가**하고, 적으면 빈 행을 지웁니다.
- 상태 칸은 🟢 🟡 🔴 이모지를 그대로 입력하면 됩니다.

> **서식 자체를 바꿔야 할 때(전략팀용):** 원본은 동명의 `.md` 파일입니다. `.md`를 고친 뒤 `AIX_POC/`에서 아래를 실행해 pptx를 다시 만들어 재배포합니다.
> ```bash
> cd ../AIX_POC
> python3 tools/md2pptx.py ../report-template-ai-agent/템플릿_빈서식.md ../report-template-ai-agent/템플릿_빈서식.pptx
> ```

## 주의사항

- **회사 기밀 제외**: 구체 장비 수치·내부 시스템 상세는 넣지 않습니다.
- **솔직한 상태 표기**: 🔴도 사유가 분명하면 감점이 아니라 정보입니다. 부풀린 🟢가 더 위험합니다.
- **임원 눈높이**: 코드·아키텍처 세부가 아니라 결과와 판단 위주로 씁니다.
