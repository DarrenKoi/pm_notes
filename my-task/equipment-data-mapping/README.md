# 장비 데이터 매핑 Agent 기획

> 검·계측(MI) 장비 안에 저장된 데이터의 계층·포맷·의미·연결을 지도로 만들고, 그 지도로 장비 간·벤더 간 차이를 비교하는 AI Agent의 기획 작업공간.

## 한 문단 요약

공정이 미세해질수록 장비 간 차이(SKEW)는 더 줄여야 하는데, 차이를 만드는 요인은 여럿이 겹쳐 있고 담당 엔지니어도 장비 안의 파일과 데이터를 다 알지는 못한다. 모르는 항목은 비교할 수 없다. 이 과제는 Agent가 장비 안의 데이터를 훑어 **데이터 지도**를 만들고, 같은 지도를 여러 장비에 적용해 **값의 차이**를 드러내며, 벤더가 달라 이름이 다른 파라미터를 **같은 개념**으로 묶는다. 전부 비교한 끝에 남기는 것은 **관리 대상 파라미터 목록**이다. 한 모델로 시작하지만 모든 모델과 장비로 넓히고, 같은 장비를 주기적으로 다시 보며 달라진 곳을 갱신하는 Agent를 목표로 한다. 지도가 바탕이고 비교와 벤더 간 대응은 각각 그 위에 올라간다. 지도만 끝나도 쓸 수 있는 결과가 남는다.

## 확인된 전제 (2026-10-09)

요약이다. 정의와 규칙은 [지도 만들기 설계](./02-map-design.md)에 있고, 어긋나면 그쪽이 맞다.

- 파일 수는 장비 한 대에 수만 단위다. 전부 내려받지 않고 목록 → 이름으로 묶기 → 표본 수집으로 간다.
- 큰 파일은 일부만 읽는다. 일부 읽기는 허용할 수 있다.
- 파일은 쓰임으로 셋이다: H/W 설정·운영 파일, 웨이퍼 측정 뒤 나오는 산출 파일, 장비 컨디션을 보려고 몇 시간~며칠 주기로 갱신되는 파일.
- 확장자는 txt·pdf·csv·xlsx와 장비사 고유 확장자가 섞여 있다. 이 가운데 xlsx와 pdf는 대상에서 뺀다.
- 이름에 `lock`·`tmp`·`temp`가 들어간 임시·잠금 파일은 읽지 않는다. 글자 포함이 아니라 토막 일치로 건다(`temperature`·`clock`이 걸리지 않게).

## 채워야 할 ⟨확인⟩ 목록

근거가 없어 비워 둔 자리다. 사무실에서 확인해 채운다. 숫자는 사내용 문서에만 적는다.

**설득 논리에 필요한 것**

- ⟨확인: 담당 엔지니어가 장비의 파일 종류 가운데 뜻을 아는 비율 (과제 전 장악률)⟩
- ⟨확인: 지금 장비 간 차이를 볼 때 확인하는 항목의 수⟩
- ⟨확인: 공정 세대에 따라 장비 간 차이 허용 기준이 어떻게 바뀌어 왔는지⟩
- ⟨확인: 최근 장비 연계·분석 과제 1~2건에서 "데이터 찾기"에 쓴 기간과 사람 수⟩
- ⟨확인: 같은 데이터를 두 번 이상 다시 탐색한 사례⟩
- ⟨확인: 보정 수치 사례 — 그 장비의 차이가 지속된 기간, 재조정 전후의 장비 간 차이⟩ **재조정이 끝나기 전에 조정 전 값을 기록한다**
- ⟨확인: 그 밖에 장비 간 차이로 실제 손실이 났던 사례와 원인 규명에 걸린 시간⟩
- ⟨확인: 벤더 문서가 다루는 범위와 다루지 않는 범위⟩
- ⟨확인: 사내에 이미 있는 유사 활동 — 파라미터 관리, 장비 간 매칭 활동, 온톨로지 과제⟩

**실행에 필요한 것**

- ⟨확인: 첫 대상 장비 모델과 그 모델의 보유 대수⟩
- ⟨확인: 장비 폴더의 목록 조회와 표본 복사를 읽기 전용으로 할 수 있는 경로와 승인 절차⟩
- ⟨확인: 대상 장비의 총 용량, 파일 종류로 묶었을 때의 종류 수⟩
- ⟨확인: 벤더 계약·보안 규정상 장비 내부 파일 분석이 허용되는 범위⟩
- ⟨확인: GLM-5.3의 컨텍스트 길이, tool calling 지원 여부, 이미지 입력 여부⟩
- ⟨확인: 지도를 검증해 줄 현업 엔지니어와 쓸 수 있는 시간⟩
- ⟨확인: 지금 공식적으로 관리하는 파라미터의 수와 관리 방식⟩
- ⟨확인: 조건을 맞춰 잰 장비 간 차이 지표가 있는지, 어디서 얻는지⟩
- ⟨확인: 보정 수치 사례 말고 이미 알려진 장비 간 차이 사례가 더 있는지 (통과 판정용)⟩
- ⟨확인: 비교에 필요한 최소 장비 대수, 회차마다 올릴 후보 수의 상한⟩
- ⟨확인: P0~P1의 기간·본인 투입·현업 검증 시간의 상한⟩
- ⟨확인: 정기 점검의 주기와 장비 접근이 허용되는 시간대⟩
- ⟨확인: 대상이 될 전체 모델 수·벤더 수·장비 대수⟩
