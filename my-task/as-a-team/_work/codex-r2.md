# AX Team 승격 후보 2차 검토

우선 제안할 일은 기존 솔루션의 운영 공백 해소, 현업 간 과제 배정, 파견 업무시간의 공식 확보입니다. 팀 승격의 근거는 이 책임을 증원한 파트나 기간제 TF에 같은 수준으로 맡길 수 있는지 확인한 뒤 확정할 수 있습니다.

## Why | 기록으로 확인되는 병목과 승격의 판단 기준

- 한 구성원의 회고에 개발과 운영의 1인 병행, 백업 인력 충원 요청, 개인에게 집중된 현업 요청이 기록됨. 후속 회고에는 백업과 요청 분류 체계의 미반영 여부가 확인 항목으로 남음. 파트 전체의 운영 상태와 직제에 따른 반려 사례는 미확인
- ARC 기획안은 현업 협조 요청만으로는 엔지니어 시간이 공식 인정되지 않고 소속 팀의 과제에 반영되지 않는다고 설명함. ARC TF는 과제 인정과 두 조직을 가로지르는 보고를 확보하기 위해 제안한 방식임. 정례 보고와 공식 과제 참여는 TF에서도 설계 가능
- ARC 파일럿 이후 인수할 상시 운영 조직은 미정으로 기록됨. Align 자동 대응 Agent의 현업 효과와 ARC의 확대 효과는 확인이 남아 있으므로 상시 운영 인력 수요에 반영할 때 시범 결과와 실제 지원 공수 필요
- 사내 직제상 파트와 팀의 인사, 평가, 예산, 전결 차이와 예산 금액은 미확인. 9명과 파견을 포함한 15~20명은 사용자 전제와 요청안에 해당. 겸직 자체는 리스크 사유에서 제외하고, 합의된 과제 투입 시간과 백업 가능 공수로 판단

판단 기준은 **사업 기간을 넘어 반복되는 수요에 대해 누가 인력과 운영비를 배정하고, 과제 충돌을 조정하며, 장애와 인수 결과에 책임지는가**입니다. 증원한 파트에 같은 위임, 자원, 상시 책임을 부여할 수 있다면 팀 승격 근거가 약합니다. 특정 과제의 효과 검증과 한시 협업이 목적이라면 TF로도 수행할 수 있습니다.

### 최종 제안 9개와 대안 비교

운영 공백과 과제 배정부터 제시하고, 이후 인력과 비용, 기술 적용, 역량 확대, 상시 조직 자립 순으로 제시합니다. ‘약함’은 해당 대안으로도 달성할 수 있어 승격을 뒷받침하는 힘이 약하다는 뜻입니다. 다른 항목도 실제 위임과 책임을 비교하기 전에는 승격 필수로 단정할 수 없습니다.

| 순서와 업무 | 부문 효과와 판단 지표 | 인원만 충원한 파트 | TF |
| --- | --- | --- | --- |
| 1. 기존 운영 솔루션의 상시 책임, 백업, 장애 복구와 현업 이관 | 운영 중단과 신규 개발 지연 감소. 백업 검증률, 장애 복구시간, 운영 요청으로 밀린 개발 일수 | **약함.** 기존 서비스에 담당자와 백업 공수를 배정하면 증원한 파트도 수행 가능. 여러 솔루션의 운영 인수, 지원 범위, 종료 결정까지 책임질 수 있는지 확인 필요 | TF 기간 내 운영과 인계는 가능. 종료 후 장애 대응과 유지보수는 상시 인수 조직을 지정해야 지속 가능 |
| 2. 현업 간 상시 과제 접수, 우선순위 조정, PoC 적용 및 중단 결정 | 개인에게 집중된 요청과 적용 대기 감소. 접수부터 결정까지 기간, 담당 미배정으로 대기한 건수, 승인 과제 운영 전환율 | 단순 증원으로 접수 인력은 생기나 타 팀 인력과 일정 변경에는 부문에서 정한 조정권자와 위임 필요. 파트에도 같은 위임이 가능하면 승격 근거 약함 | ARC 범위의 조정, 현업 과제 인정, 정례 보고는 가능. 신규 과제가 계속 들어오는 부문 전체 창구의 종료 이후 책임자 필요 |
| 3. 현업 파견 수용, 업무시간과 목표 합의, 평가 의견 전달 및 복귀 전 인수 | 현업 참여의 실효성과 복귀 후 업무 연속성 확보. 합의 대비 실제 투입 공수, 평가 의견 반영 여부, 후임 검증률 | AX 인원 충원만으로 원소속 팀의 업무시간 인정이나 평가 절차가 바뀌기 어려움. 명시적 파견 합의가 파트에도 가능하면 승격 근거 약함 | **초기에는 약함.** 단일 과제의 현업 시간과 실적 반영은 TF로도 공식화 가능. 여러 기수의 파견, 복귀, 후임 배치가 반복되면 상시 책임자 필요 |
| 4. 운영 수요에 맞춘 연간 재원과 공용 연산 배정 | 운영과 신규 개발의 자원 경합 완화. 연산 대기시간, 운영비 계획 대비 편차, 자원 미배정으로 지연된 건수 | 인원 충원으로는 예산과 용량 배정 권한이 생기지 않음. 상위 팀이 정례 배분을 책임질 수 있다면 **독립 승격 근거는 약함** | **개별 사업은 약함.** ARC안도 과제 용량 확보를 TF가 추진하는 구상. 여러 운영 서비스의 다음 연도 재원은 상시 예산 책임자 필요 |
| 5. 검증된 레시피 자동화, Align 자동 대응 Agent와 공통 기능의 단계적 확대 | 장비군별 중복 개발과 승인 준비 공수 감소. 신규 대상당 준비기간, 공통 기능 재사용률, 현업 적용 후 효과 | **개발 자체는 약함.** 필요한 전문 인력, 현업 승인과 운영 공수가 확보되면 파트도 가능. 확대와 유지보수가 여러 과제에서 동시에 쌓이는지 확인 필요 | **ARC 확대 자체는 약함.** 계획된 장비군의 시범과 플랫폼 검증은 ARC TF 범위. 검증 후 여러 과제의 공통 기능을 계속 유지할 주체는 별도 지정 필요 |
| 6. 공통 평가와 변경 관리, 관계 조직의 보안 및 배포 승인 조정 | 공통 변경에 따른 품질 저하와 반복 심사 축소. 변경 전 회귀 평가 적용률, 반복 보완 건수, 변경 후 장애 건수 | **약함.** 개별 평가와 협의는 파트도 가능. 공통 솔루션 전체에 기준을 적용하려면 각 승인 조직과 반복 운영 책임 합의 필요 | **과제 범위에서는 약함.** TF도 평가와 승인 조정을 수행할 수 있고 공통 모델이 바뀔 때마다 운영 서비스 전체를 재검증할 주체는 상시 지정 필요 |
| 7. FDE 방식의 기간 한정 현장 배치와 현업 인수 시범 | 현장 요구 반영과 인수 속도 개선. 배치부터 첫 적용까지 기간, 인수 후 현업 자체 처리율, 중앙 운영 공백 | **약함.** 한 곳 시범은 파트도 가능. 여러 곳을 지원하면서 중앙 운영을 유지할 만큼 배치 공수가 확인돼야 확대 근거 확보 | **약함.** 단건 현장 협업은 TF도 가능. TF 밖의 여러 현업에 반복 배치할 수요와 현업 인수 효과가 확인돼야 상시화 근거 확보 |
| 8. 고급 AX 교육 정례 운영, 사내 강사 양성, 현업 적용 지원 | 현업의 자체 적용 역량 확보. 활동 강사와 멘토 확보율, 교육 후 현업 적용률, 적용 전후 처리시간 | **약함.** 교육 운영 조직과 업무시간을 합의하면 파트도 정례 운영 가능 | **약함.** TF로 파일럿 가능. 종료 뒤 반복 기수와 현업 적용 지원을 맡을 교육 조직이 있다면 AX Team의 독립 근거는 약함 |
| 9. 기반기술센터 AI Solution 팀의 상시 운영 기반 확보 | 파견자 복귀와 TF 종료 후에도 중요 솔루션 지속 지원. 상시 직무 충족률, 운영 재원 확보 여부, 과제별 인수 검증률 | **조건부.** 모조직이 상시 직무, 운영비, 조정권을 보장하면 증원한 파트도 같은 효과 달성 가능. 모조직에 두기 어려운 책임이 무엇인지 확인 필요 | 한시 TF는 운영 실적과 인수 준비를 검증할 수 있음. 종료를 전제로 계속 유지할 솔루션의 장기 인력과 예산 책임은 정규 조직에 지정 필요 |

1~3번을 앞에 두는 이유는 운영 공백, 요청 집중, 현업 시간 미인정이라는 직접적인 기록이 있기 때문입니다. 4번은 실행 조건이고, 5~6번은 검증을 통과한 솔루션의 확대 범위입니다. 7~8번은 일단 시범 또는 확대 업무로 제시합니다. 9번으로 상시화 여부를 결정합니다.

## How | ARC TF와의 관계 및 시행 순서

### 부문장에게 제시할 답변

> ARC에서 정규 조직을 먼저 만들면 효과를 검증하기 전에 조직을 바꿔야 한다고 판단해 정규 조직 신설안을 비교표에서 제외했습니다. 그 판단은 이번에도 적용합니다. ARC는 계획대로 TF에서 현업 효과와 장비군 확대 가능성을 검증하고, 계획의 종료, 연장, 상시 전환 판단을 유지합니다. 이번 승격 요청의 근거는 이미 운영 중인 솔루션에서 나온 백업 인력 충원 요청과 개인에게 몰리는 현업 요청, 여러 현업의 참여 시간을 공식 배정해야 할 필요입니다. 이 문제를 계속 맡을 조직과 책임을 지금 정해 달라는 요청입니다. 현재 기록만으로 직제가 문제의 원인이었다거나 팀만 해결할 수 있다고 말하기는 어렵습니다. 증원한 파트에 동일한 상시 책임, 인력, 재원과 조정 권한을 지정할 수 있다면 그 방식이 먼저입니다. 팀 단위에서만 확보할 수 있는 책임이나 위임이 확인되는 범위로 승격 요청을 좁히겠습니다.

### 시기와 파견 방향

| 시기 | 배치할 업무 | 인력과 전환 조건 |
| --- | --- | --- |
| 승격 직후 | 1번 기존 솔루션의 운영 책임자와 백업 지정, 2번 접수처와 과제 조정권자 확정, 3번 현업 파견 수용, 4번 운영비와 연산 용량 기준 확인 | **현업 → AX Team.** 파견자는 자기 과제를 가져오고 원소속 팀과 근무 비중, 과제 목표, 실적 반영 절차, 복귀 조건을 합의. 파견 인력은 요청 규모 15~20명에 포함하며 AX Team과 ARC TF의 실제 공수 중복 배정 여부 확인 |
| 승격 후 1년 안 | 4번 승인 자원의 반복 배정 운영, 5번 검증 통과 대상의 확대, 6번 회귀 평가와 배포 검토 운영, 7번 FDE 시범, 8번 정례 교육과 강사 양성의 운영 가능성 검증 | **AX Team → 현업.** 중앙 운영 백업이 작동하고 현업 과제 책임자와 인수자가 지정된 뒤 제한된 범위에서 FDE 시범. 기간, 투입 시간, 인수 기준을 사전에 합의하고 시범 종료 후 AX Team으로 복귀. 현업에서 들어온 파견자의 기본 배치와 FDE의 한시 배치는 공수에서 각각 확인 |
| 그 뒤, 2027년 이후 AI Solution 팀 자립 | 9번 상시 직무와 재원 확정, 1번의 중요 솔루션 운영 인수 검증, 3번의 복귀 또는 잔류 전 후임 확보. 5번과 7~8번 확대는 수요와 검증 결과에 따라 결정 | 첫해 검증이 끝난 뒤 상시 인력, 예산, 서비스별 인수자를 확인해 자립 판단. 현업 파견자의 복귀 또는 잔류는 파견 시작 후 2~3년을 기준으로 협의. ARC의 2027년 12월 종료, 연장, 상시 전환 판단은 별도 유지하고 인수 결정이 난 범위만 반영 |

‘2027년 이후’는 자립을 검토하는 기간입니다. 첫해 업무 검증과 파견자의 2~3년 뒤 복귀 시점은 각각 운영합니다. 승인 상정 전에는 원소속 팀과 인사, 예산 담당 조직에 **⟨확인: 파트에서도 위임 가능한 조정 범위, 파견 시간과 평가 인정 절차, 운영비 배정 단위, 승인 전결권자⟩**를 확인합니다. 현업의 대기 과제 수와 운영 공수, 각 팀의 파견 가능 시간을 확인한 뒤 15~20명 구성이 업무량에 맞는지 판단합니다.
