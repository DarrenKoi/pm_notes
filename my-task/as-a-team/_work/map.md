# 지형도: AX Part를 AX Team으로 올리는 판단

> wayfinder 스킬이 이 세션 목록에 없어 `arc-tf/wayfinder/map.md` 형식을 따라 손으로 만듦.

## 목적지

부문장이 기획서를 읽고 세 가지에 답을 얻는 것: 팀이 되면 무엇을 하는가, 왜 파트로는 못 하는가, 효과와 측정 지표는 무엇인가.

## 부문장이 판단할 때 볼 축

| 축 | 부문장의 질문 | 기획서에서 답하는 곳 |
|----|--------------|---------------------|
| 필요성 | 파트로 두면 무엇이 막히는가 | 1절 |
| 실적 | 이 조직이 팀을 맡을 만큼 해 왔는가 | 2절 |
| 차별성 | 리스트의 일이 정말 팀이어야 되는 일인가 | 3절 (항목별 "파트로 안 되는 이유") |
| 대안 | TF, 파트 유지, 인원만 충원으로는 왜 부족한가 | 5절 추진 방식 비교 |
| 비용 | 인력과 예산이 얼마나 더 드는가 | 7절 |
| 타 조직 영향 | 사람을 내주는 팀이 손해 보지 않는가, 업무가 겹치지 않는가 | 5절 경계, 파견 구조 |
| 지속성 | 파견 인력이 돌아가면 팀이 유지되는가 | 5절, 8절 |
| 되돌림 | 성과가 안 나오면 무엇으로 판단하고 어떻게 되돌리는가 | 6절 점검 시점, 8절 |

## 파트와 팀의 실제 차이

회사 직제와 위임전결의 실제 내용은 문서에 없음. 아래는 일반적인 형태이고 사내 규정으로 확인이 필요함 (open-questions로 보냄).

| 구분 | 파트 | 팀 | 리스트에서 쓰는 곳 |
|------|------|-----|-------------------|
| 권한 | 상위 팀을 거쳐 과제 수락, 조율 | 과제 접수와 수락, 보류, 종료를 직접 결정 | 과제 창구, 우선순위 조정 |
| 인력 규모 | 9명, 과제마다 1~2명 | 15~20명, 과제에 여러 역할을 동시에 배치 | 대규모 과제, 운영 전담 |
| 예산 | 상위 조직 예산의 일부 | 연간 예산 요구와 집행 단위 | 교육 정례화, 공통 기반 |
| 대외 창구 | 다른 팀, 인프라, 보안과 건별 협의 | 부문 AX의 공식 창구 | 파견, FDE, 보안과 배포 협의 |
| 평가와 육성 | 파트장은 실적 근거 제공 | 팀장이 목표와 평가, 육성 경로 관리 | 파견자 평가, AX 직무 육성 |
| 업무 연속성 | 담당자 1명에 의존 | 후임과 대체 인력을 둘 수 있음 | 운영 책임, 인수인계 |

## 가는 길 (지시서 순서)

1. 지형 (이 파일) → 2. 후보 30개 이상 (`candidates.md`) → 3. Codex 3회 (`codex-log.md`) → 4. grilling (`grilling.md`) → 5. 리스트 확정 → 6. 카운슬 2회 → 7. 기획서 → 8. docx, README, 커밋

## 아직 모르는 것

- 사내에서 파트와 팀의 권한 차이 (인사, 평가, 예산, 전결)
- 승격을 결정하는 절차와 시기 (정기 조직 개편 일정)
- 팀장 후보와 팀장 실무의 대체 방안
- 파견 대상 인력과 과제, 원소속 팀의 동의 여부
- 순증 인원의 출처 (전입, 신규 채용)
- 예산 규모
- 다른 부문과 전사에 비슷한 일을 하는 조직이 있는지
