# AX Team 승격 기획안 3차 검토

**현재 초안 기준으로는 승인 보류입니다.** 팀에서만 확보할 수 있는 결정권, 운영에 실제로 배정할 인력과 팀장 보임안, 파견을 보내는 팀의 업무 공백 대책이 승인 전에 필요합니다.

## Why | 부문장이 승인을 보류할 세 곳

### 1. 팀 직제가 꼭 필요하다는 결론이 근거보다 앞섬

- **위치와 문장** 요약 16행의 “상시 책임 단위가 지금은 없음”, 3절 98행의 “사람 수와 상관없이 팀 직제가 있어야 되는 일”, 3절 4번 140행의 “연간 예산과 정원을 요구하는 단위가 팀임”
- **부문장 반론** “내가 상위 팀에 운영 책임을 주고 파트에 인원과 권한을 주면 뭐가 안 됩니까? 팀을 만들어야만 할 수 있는 결정을 하나라도 사내 규정이나 실제 반려 사례로 보여 주십시오.”
- **수정 방향** 개인 회고에서 확인된 운영과 요청 병목을 먼저 제시. 인수, 파견, 과제 조정, 예산, 보안 협의 각각에 대해 현재 결정자, 파트에 위임 가능한 범위, 팀이 될 때에만 달라지는 권한 확인. 5절 285행의 대안을 요약과 3절에도 같은 조건으로 적용

> 한 구성원의 회고에 개발과 운영의 1인 병행, 백업 인력 충원 요청, 개인에게 집중된 현업 요청이 기록돼 있습니다. 기존 운영 솔루션의 인수 책임과 지원 범위, 현업 간 과제 조정권, 연간 운영 자원의 배정 책임을 지정할 필요가 있습니다. 증원한 파트와 상위 팀에 동일한 책임과 권한을 부여할 수 있다면 그 방식을 먼저 적용합니다. 사내 직제상 팀에서만 맡을 수 있는 결정이 확인되면 해당 결정과 근거를 명시해 승격을 요청합니다.

### 2. 정원 요청에 팀장 보임안과 실제 가용 인력이 빠짐

- **위치와 문장** 7절 310행의 “정원 15~20명 (현재 9명, 파견 인력 포함)”과 5절 248행의 “⟨확인: 팀장 후보와 팀장 실무의 인계 방안⟩”. 5절 262행은 인원 계획을 다시 계산해야 한다고 명시
- **부문장 반론** “15명이어도 운영과 신규 개발을 같이 할 수 있습니까? 20명이 필요한 조건은 뭡니까? 팀장으로 누굴 보임하고, 그 사람의 개발과 운영은 누가 받습니까? ARC TF에도 같은 사람을 보내면 여기 남는 시간은 얼마나 됩니까?”
- **수정 방향** 15명안과 20명안을 업무 범위와 실제 가용 공수로 비교. 정규 정원과 파견 포함 총 투입 인원을 구분하고, 기존 인력의 확정 과제와 ARC TF 투입 시간, 파견자의 원과제와 공통 업무, 팀장 실무 이관을 반영. 운영 책임자와 검증된 백업을 확보하지 못하는 안에서는 추가 과제 수와 교육 범위 축소

> 파견을 포함한 15명과 20명은 인력 검토 범위입니다. 보임 후보 ⟨확인: 팀장 후보⟩의 기존 과제는 ⟨확인: 인수자와 인계 일정⟩으로 이관합니다. 기존 과제와 ARC TF에 투입할 시간, 파견자의 원과제 시간을 반영한 뒤 상시 운영과 백업에 쓸 수 있는 인력을 산정합니다. 승인안에는 정규 정원, 파견 인원, 첫해 수용 과제와 교육 범위, 운영비를 함께 제시합니다.

### 3. 파견 팀이 부담할 업무 공백과 복귀 조건이 빠짐

- **위치와 문장** 3절 2번 123행의 “원소속 팀은 사람을 잃지 않고 과제가 계속 진행됨”, 4절 226행의 “실력자 1명의 소속 이동 (과제는 계속 진행)”, 5절 258행의 “복귀 또는 AX Team 잔류를 본인이 선택”
- **부문장 반론** “과제 이름과 성과가 원팀에 남는 건 알겠습니다. 그 사람이 맡던 장비 대응과 나머지 과제는 누가 합니까? AX 공통 업무까지 맡기면 원래 과제의 납기는 누가 책임집니까? 본인이 남겠다고 하면 원팀이 그 자리를 어떻게 채웁니까?”
- **수정 방향** 파견 대상 팀별로 기존 업무의 대체자와 공수, 원과제와 공통 업무의 배분, 성과 귀속과 평가 의견, 복귀 또는 잔류 절차를 사전 합의. 팀장 간 우선순위 충돌 시 결정권자 지정. 6절 303행의 “원소속 팀의 손실이 작음”은 환원 시 운영 인수자와 대체자까지 정해진 건에 한해 판단

> 1차 파견은 원소속 팀과 AX Team이 기존 업무의 대체 담당자, 원과제 납기 책임자, 공통 업무 투입 시간, 평가 의견 제출 절차를 합의한 경우에 시행합니다. 파견자의 복귀 또는 잔류 희망은 양 팀의 인력 계획과 인사 절차에 따라 협의합니다. 복귀 전에는 원과제와 운영 업무의 인수자를 지정하고 실제 인수를 확인합니다.

## What | 3절에서 파트로도 할 수 있다는 반론이 남은 항목

1~5번도 파트나 상위 팀에 어느 범위까지 위임할 수 있는지 확인 전에는 팀 전용으로 분류하기 어렵습니다. 6~9번은 규모와 가용 시간에 따라 확대할 업무입니다.

| 번호 | 부문장이 파트로도 된다고 볼 이유 | 남길 범위 |
| --- | --- | --- |
| 1 | 운영 담당자와 백업 지정, 복구 훈련, 인수 준비는 파트도 가능. 상위 팀이 최종 인수와 연간 운영 책임을 맡을 수도 있음 | 여러 서비스의 반복 인수와 상시 운영비 책임. 인수 결정권과 위임 한계 확인 |
| 2 | 현업 참여 시간과 과제 인정은 ARC TF에서도 가능. 장기 파견 수용과 평가 의견 제출을 파트장 또는 상위 팀장에게 위임할 수 있는지는 미확인 | 여러 팀과 반복하는 파견 수용과 평가 의견 반영, 파견 종료 전 후임 검증 |
| 3 | 단일 접수, 과제 분류, 집계 보고는 현 파트에서도 가능. 부서 간 충돌은 상위 팀이나 센터가 중재 가능 | 수락, 보류, 종료와 인력 재배정을 누가 결정하는지 명시 |
| 4 | 수요 취합과 예산 요청안 작성은 파트에서도 가능. 승인과 배정은 센터나 상위 팀이 맡을 수 있음 | 연간 재원 배정과 자원 경합 조정. 승인 단위와 전결 범위 확인 |
| 5 | 대표 연락 담당 지정과 공통 평가 수행은 파트에서도 가능. 팀이 되어도 보안과 배포 승인 조직은 별도 | 여러 운영 솔루션의 변경 전 회귀 평가와 관계 조직이 승인한 공통 기준의 유지 |
| 6 | 초안 165행도 증원한 파트에서 가능하다고 명시. 복수 직무를 묶는 단일 프로젝트는 TF로도 가능 | 운영 백업을 유지하면서 여러 대형 과제를 병행할 실제 수요와 가용 공수 |
| 7 | 교육 주관 조직이 기수 운영을 맡고 파트가 강사와 멘토를 제공할 수 있음 | 업무시간을 배정한 사내 강사와 멘토 양성, 반복 기수 운영 |
| 8 | 90일 지원과 사례 공유는 현업 담당자나 증원한 파트도 시범 가능 | 7번에 통합해 수료 후 현업 적용률과 지원 공수 측정. 복귀 파견자가 없는 초기에는 현업 지정 담당자가 접점 |
| 9 | 한두 팀의 FDE 시범은 초안 197행대로 파트에서도 가능 | 중앙 운영 백업과 현업 인수자를 확보한 뒤 시범. 반복 배치 수요와 효과를 확인한 뒤 확대 판단 |

## How | 수치, 사실과 일정의 정정

근거에서 확인되는 계획이나 내부 보고 수치는 있습니다. 아래는 수치를 새로 제시하거나, 근거보다 넓은 범위에 적용하거나, 계획을 확정 사실로 읽히게 한 부분입니다.

| 초안 위치 | 판정과 조치 |
| --- | --- |
| 요약 16행, 1절 51, 61행, 3절 1번 108행, 8절 339행 | **범위 확대.** 개인 회고로 파트 전체가 개인 단위로 일했다거나 센터에 상시 책임 단위가 없었다고 확정하기 어려움. 운영 사례를 한 건 확인한 것만으로 운영 솔루션이 전체 한 건이라고 셀 수 없음. “검토 자료에서 확인한 운영 사례”로 한정. PoC가 빨랐다는 비교 근거 추가 또는 해당 문장 삭제 |
| 1절 55행, 2절 82행, 3절 1번 109행 | **출처는 있으나 시점과 상태 표시 필요.** 접속 수치는 9월과 10월 자료의 값이 다르므로 10월 보고 기준 등 시점 명시. 9월 회고의 백업 미반영에는 확인 표시가 있어 “9월 회고에도 미해소 여부가 확인 항목으로 남음”으로 수정. 계측 시간 단축은 완료 시 전망, 감지 시간 개선은 당시 내부 보고 수치로 표기 |
| 요약 21행, 3절 6번 162, 166행, 5절 247행, 7절 310, 318행 | **인원 전제와 산정 근거 분리.** 9명과 15~20명은 사용자 전제와 요청 범위. 기존 9명 유지 시 6~11명 순증이라는 산술은 맞음. 파견 인력을 포함한 총원을 정규 정원으로 표기할 근거는 미확인. “과제마다 1~2명 배치가 한계”는 현재 배치표 확인 필요. “3명 이상”은 실적이 아닌 제안 배치 기준으로 표시 |
| 요약 16, 41행, 1절 58, 65, 72행, 3절 1번 112행, 6절 295~296행 | **ARC 계획의 상태와 결정 구분.** 2027년 운영은 승인 보고용 초안의 계획이며, 2027년 12월은 종료, 연장, 상시 전환의 판단 시점. “TF 종료 때 인수”는 “종료 또는 전환 결정 시 검증 통과 범위의 인수 준비”로 수정. 팀 승격 후 6개월과 12개월 점검은 승격일에 따라 달라지므로 ARC의 6월과 12월 일정과 별도 행으로 표시 |
| 1절 59, 66행, 3절 7~8번 172, 182행, 4절 238행 | **설계상 필요 인력과 실제 부족 구분.** Expert 과정의 멘토와 심사자 수는 설계에 명시. 인력이 실제 부족하거나 교육 후 지원 인력이 없다는 상황은 배정 현황 확인 필요. 고급 과정 60명은 검토 중인 참여 규모이고 수료자 수 실적은 없음. 수료 목표로 쓰려면 정원과 수료율 가정 구분 |
| 3절 2번 118, 120~121행, 5절 254~258행, 8절 336행 | **역량과 인사 가정.** 파트 내 역량 분포와 현업의 개인별 과제 형태는 자료로 확인되지 않음. ARC안이 지적한 것은 비공식 협조 요청에서 현업 시간을 과제로 인정하기 어렵다는 점. 파트의 전입 수용 가능 여부, 평가권, 파견자의 잔류 선택, 교육 수료자의 전입은 인사 확인 전 제안으로 표시 |
| 3절 8번 186행, 3절 202~210행, 4절 219행 | **일정 전제 충돌.** 8번을 첫해에 시작하면서 새 파견자가 2~3년 뒤 복귀한 뒤 중심을 맡는다고 쓰면 초기 담당자가 비어 있음. 첫해는 현업 지정 담당자, 복귀 이후에 합의된 인력이 이어받는 구조로 수정. 자립은 첫해 종료 또는 2027년 도래만으로 달성한 것으로 표기하지 않고 상시 인력과 운영 인수 확인 후 판단 |
| 5절 269, 274행, 8절 338행 | **TF 계획 인원과 가용 공수 구분.** AX Part의 ARC 공통 개발 3명은 TF 기획안의 편성 수치. 실제 배치 여부와 투입 시간은 확인 필요. 각 개인의 AX 운영과 TF 개발 시간 합계로 중복 확인 |
| 3절 9번 192행 | **제공된 근거에서 확인 범위 밖.** Palantir가 시작했다는 주장과 OpenAI의 채택은 제시된 요약 자료로 검증하지 못함. 사내 제안에는 FDE의 역할과 배치 방향 설명만으로 충분 |

| 과장되거나 모호한 표현 | 요약 16행 “상시 책임 단위가 지금은 없음”은 “운영과 개발의 1인 병행, 백업 인력 충원 요청이 보고된 사례가 있습니다.”, 3절 113행 “운영 요청이 신규 개발을 밀어내지 않음”은 “운영 요청으로 인한 신규 개발 지연 일수 감소”, 123행 “사람을 잃지 않고”는 “원소속 팀의 과제 유지 및 기존 업무 대체 인력 합의”로 수정. “현업 실력자”는 “과제 수행 경험이 있는 현업 엔지니어”로 구체화 |
