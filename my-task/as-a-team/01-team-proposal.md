# AX Team 승격 기획안

> AX Part를 AX Team으로 승격하면 추진할 수 있는 업무 11가지와 승격 요청 사항

## 1. 배경

- 기반기술센터는 업무와 성격이 다른 조직이 모인 부문으로, "As a One Team"을 기조로 운영 중
- AX 확산에는 지식 자산화 병행 필수: 조직마다 흩어진 지식을 자산으로 모아야 AX를 센터 전체로 확산 가능
- 양산총괄 등 다른 부문은 지식 자산화를 장기간 추진해 왔고 현재 그 성과를 활용 중
- 솔루션의 장기 발전에는 백업 인력 필요: 현재 솔루션마다 개발과 운영을 한 사람이 담당, 운영 대응과 기능 고도화의 병행에 한계
- 백업 인력이 있어야 담당자 부재에도 운영 유지, 담당자는 고도화와 신규 개발에 시간 확보
- 연구소, 양산총괄 등 다른 부문은 AX 조직을 15~20명 규모의 팀으로 운영 중
- 기반기술센터도 1~2년 안에 AX Team 필요. 더 늦기 전에 지금 구성하자는 취지
- 정기 인사는 연 1회 (가을~겨울): 이번 시기를 넘기면 정규 인원 충원 (전배)은 다음 정기 인사까지 대기
- 정기 인사 뒤에는 파견만 가능하고 상반기가 지나면 파견 기피 증가. 2026-12 안에 승격 결정 필요

## 2. 팀이 되면 추진할 수 있는 업무

### 가. 인사, 예산 권한이 있어야 추진할 수 있는 업무

| # | 업무 | 추진 내용 | 기대 효과 |
|---|------|-----------|-----------|
| 1 | TF 결과 인수와 솔루션 상시 운영 | 솔루션마다 책임자와 백업 지정, ARC (Auto Recipe Creation) TF가 검증한 결과 인수 | TF 종료 뒤에도 검증된 자산 유지, 운영 요청으로 인한 신규 개발 지연 축소 |
| 2 | 현업 개발 인력의 순환 파견 수용 | 파견자가 자기 과제와 함께 합류, 과제는 AX Team이 책임지고 추진, 성과는 원소속 팀과 공동 실적 | 현업 과제의 추진 속도 확보, 복귀 인력이 원소속 팀의 AX 거점 역할 |
| 3 | 센터 AX 과제 창구와 우선순위 조정 | 접수 창구 통합, 수락 기준 공개, 분기마다 과제와 성과 집계 보고 | 부문장님께 센터 AX 과제 일괄 보고, 중복 과제 축소 |
| 4 | 연간 인력, 예산, 연산 자원 요구와 배정 | 운영 솔루션과 신규 과제의 자원 수요를 연간 계획으로 요구, 승인 자원을 과제에 배정 | 자원 부족으로 대기하는 과제 축소 |
| 5 | 보안, 배포 검토와 공통 평가의 대표 창구 | Agent의 승인, 중단, 복구 기준을 승인 조직과 한 번 합의해 여러 과제에 적용 | 과제마다 반복되는 심사 축소, 현장 배치 기간 단축 |

### 나. 팀 규모가 되어야 추진할 수 있는 업무

| # | 업무 | 추진 내용 | 기대 효과 |
|---|------|-----------|-----------|
| 6 | 여러 역할을 같이 배치하는 대규모 과제 | 범위가 큰 과제에 3명 이상 배치, 1인 1 Agent 개발에서 팀 단위 개발로 전환 | 현업 엔지니어의 반복 업무 시간 절감 |
| 7 | AX 교육 정례 운영과 사내 강사, 멘토 양성 | 반복 과정은 사내 강사가 운영, 업체 과정은 사내에 없는 주제로 한정 | 업체 의존 축소, 센터 환경에 맞춘 교육 |
| 8 | 교육 수료자의 현업 적용 지원 | 수료자의 첫 과제를 90일 동안 지원, 팀별 AX 담당자 연결망 운영 | 2027년 고급 과정 (60명 검토 중)이 현업 적용으로 연결 |
| 9 | 현업 배치 개발 | 개발 인력이 부족한 팀의 과제에 AX Team 엔지니어 1명을 1개월 이내로 배치해 개발 후 인도, 그 팀 구성원이 배우면서 운영까지 맡도록 가이드 | 개발 인력이 부족한 팀의 AI/DT 과제 추진, 현업 팀의 운영 역량 확보 |
| 10 | 도메인 지식을 넣은 자체 모델 개발 (fine-tuning) | 회사 기밀 문서는 외부 LLM API 사용 불가, 사내 LLM API로 제공할 자체 모델 개발 | 도메인 업무에서 Agent 정확도 향상 |
| 11 | 엔지니어 업무의 지식 자산화와 DB 관리 | 엔지니어의 업무 지식을 수집, 정리해 DB로 구축, 담당 인력이 상시 관리 | AX 확산의 기반 확보, Agent와 자체 모델이 활용할 도메인 지식 축적 |

## 3. 조직 구성

| 항목 | 내용 |
|------|------|
| 소속 | 기반기술센터, 전략팀에서 독립한 팀 |
| 규모 | 18~20명 (현재 9명): 정규 13명, 순환 파견 5~7명 |
| 정규 인원 충원 | 4명, 팀 이동 (전배) 지원자로 충원 |
| 순환 파견 | 각 팀의 개발 인력이 2~5년 근무 뒤 희망에 따라 복귀. 1차 2~3명, 대상은 DEC, ME, DMI처럼 개발 인력이 있는 팀 (예상) |
| 팀장 | 현 파트장 보임 또는 외부 영입, 승격 결정 뒤 확정 |

- 순환 파견의 목적: 도메인 지식을 가진 현업 인력 확보, 현업 팀과의 협업 틀 유지

## 4. 일정

| 시점 | 내용 |
|------|------|
| 2026-12 | 승격 여부 결정 |
| 승격 뒤 3개월 | 솔루션별 책임자와 백업 확정, 접수 창구 개설, 1차 파견 합류 |
| 승격 뒤 6개월 | 점검 보고, 5~8번과 11번 착수 |
| 승격 뒤 12개월 | 점검 보고, 9~10번 착수 |

## 5. 요청 사항

- AX Part의 AX Team 승격, 전략팀에서 독립
- 인원 18~20명 (정규 13명, 순환 파견 5~7명)
- 1차 파견 2~3명 요청 승인과 대상 팀의 협조
