# AX Team 승격 기획안

> AX Part를 AX Team으로 승격하면 추진할 수 있는 업무 10가지와 조직 구성

## 1. 팀이 되면 추진할 수 있는 업무

### 가. 인사, 예산 권한이 있어야 추진할 수 있는 업무

**1. TF 결과 인수와 솔루션 상시 운영**

- 추진 내용: 솔루션마다 책임자와 백업 지정, TF가 검증한 결과 인수
- 기대 효과: TF 종료 뒤에도 TF에서 얻은 노하우 유지, 운영 요청으로 인한 신규 개발 지연 축소

**2. 현업 개발 인력의 순환 파견 수용**

- 추진 내용: 파견자가 자기 과제와 함께 합류, 과제는 AX Team이 책임지고 추진, 성과는 원소속 팀과 공동 실적
- 기대 효과: 현업 과제의 추진 속도 확보, 복귀 인력이 원소속 팀의 AX 거점 역할

**3. AX Acceleration TF와 역할 분담**

- 추진 내용: 과제 관리는 AX Acceleration TF가 담당, AX Team은 개발과 교육에 집중
- 기대 효과: 과제 관리와 개발의 책임 구분, 개발과 교육에 인력 집중

**4. 연간 인력, 예산, 연산 자원 요구와 배정**

- 추진 내용: 운영 솔루션과 신규 과제의 자원 수요를 연간 계획으로 요구, 승인 자원을 과제에 배정
- 기대 효과: 자원 부족으로 대기하는 과제 축소

**5. 보안, 배포 검토와 공통 평가의 대표 창구**

- 추진 내용: Agent의 승인, 중단, 복구 기준을 승인 조직과 한 번 합의해 여러 과제에 적용
- 기대 효과: 과제마다 반복되는 심사 축소, 현장 배치 기간 단축

### 나. 팀 규모가 되어야 추진할 수 있는 업무

**6. 여러 역할을 같이 배치하는 대규모 과제**

- 추진 내용: 범위가 큰 과제에 3명 이상 배치, 1인 1 Agent 개발에서 팀 단위 개발로 전환
- 기대 효과: 현업 엔지니어의 반복 업무 시간 절감

**7. AX 교육 정례 운영과 사내 강사 양성**

- 추진 내용: 사내 개발 환경을 아는 구성원이 강사 역할, 업체 과정은 사내에 없는 주제로 한정
- 기대 효과: 사내 강의 업무 부담 해소, 업체 의존 축소

**8. 현업 배치 개발**

- 추진 내용: 개발 인력이 부족한 팀의 과제에 AX Team 엔지니어 1명을 1개월 이내로 배치해 개발 후 복귀, 그 팀 구성원이 배우면서 운영까지 맡도록 가이드
- 기대 효과: 개발 인력이 부족한 팀의 AI/DT 과제 추진, 현업 팀의 운영 역량 확보

**9. 도메인 지식을 넣은 자체 모델 개발 (fine-tuning)**

- 추진 내용: 회사 기밀 문서는 외부 LLM API 사용 불가, 사내 LLM API로 제공할 자체 모델 개발
- 기대 효과: 도메인 업무에서 Agent 정확도 향상

**10. 엔지니어 업무의 지식 자산화와 DB 관리**

- 추진 내용: 엔지니어의 업무 지식을 수집, 정리해 DB로 구축, 담당 인력이 상시 관리
- 기대 효과: AX 확산의 기반 확보, Agent와 자체 모델이 활용할 도메인 지식 축적

## 2. 조직 구성

- 규모: 18~20명 (현재 9명): 정규 13명, 순환 파견 5~7명
- 정규 인원 충원: 4명, 팀 이동 (전배) 지원자로 충원
- 순환 파견: 각 팀의 개발 인력이 2~5년 근무 뒤 희망에 따라 복귀. 1차 2~3명, 대상은 DEC, ME, DMI처럼 개발 인력이 있는 팀 (예상)

- 순환 파견의 목적: 도메인 지식을 가진 현업 인력 확보, 현업 팀과의 협업 틀 유지
