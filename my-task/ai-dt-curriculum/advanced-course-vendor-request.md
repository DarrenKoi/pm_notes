# 기반기술센터 AI Agent 고급 과정 커리큘럼 요청서

> 기반기술센터 구성원 대상 AI Agent 고급 과정(2주, 80시간)의 커리큘럼 제안 요청

## 1. 배경

- AX 확산으로 팀별 AI Agent 생성과 그 수는 지속 증가 추세인 반면, 전문적인 관리와 운영 노하우 부재
- 교육 목적: 1인 개발이 아닌 팀 단위 AI Agent 개발과 운영, 팀별 Agent 관리 역량을 갖춘 구성원(챔피언) 확보

## 2. 교육 대상 구성원

1. Agent를 혼자 개발하고 운영해 본 경험이 있는 구성원
2. 프로그래밍 언어를 다룰 줄 알고 사내 전산 시스템 활용이 가능한 구성원

## 3. 과정 개요

| 항목 | 내용 |
|------|------|
| 대상 조직 | 기반기술센터 (2027년 센터 맞춤 과정) |
| 기간 | 연속 2주(10일), 하루 8시간, 총 80시간 |
| 인원 | 차수당 15명, 4차수, 총 60명 (검토 중) |
| 방식 | 대면 교육, 업체 교육장 (사당) |
| 실습 환경 | 업체 교육장 환경, public API 사용 (확정) |
| 개강 시기 | 협의 |

## 4. 커리큘럼 요청 범위

아래 주제를 포함한 세부 커리큘럼과 시간 배분 제안 요청

| 주제 | 다룰 내용 |
|------|-----------|
| Git, GitLab 기본 사용법 | 커밋, 브랜치, MR과 리뷰, 충돌 해결 (GitLab 기준 실습) |
| 팀 단위 Agentic Coding | 여러 구성원이 각자의 코딩 Agent로 하나의 저장소를 개발하는 방법, Agent 지침 파일과 Skill 공유, 작업 분할과 충돌 방지, Agent 작성 MR의 리뷰 기준, 특정 도구에 종속되지 않는 지침 파일 작성 (1인 사용법을 팀 단위 사용법으로 확장) |
| Agent 평가와 테스트 | Agent 유형별 성공 기준 정의, 평가셋 구축, Agent 테스트 방법, 채점 방식 선택, LLM-as-judge 보정, 품질 게이트 기준 설정 |
| AI 시스템용 GitLab CI/CD | Agent 테스트 자동화, 프롬프트와 모델 버전 관리, 평가 게이트의 파이프라인 연결, 배포와 롤백 (GitLab CI 기준 실습) |
| 소형 LLM 파인튜닝 | 튜닝 여부 판단 기준 (프롬프트, RAG 대비), 반도체 도메인 유형의 가상 데이터(이미지, 문서) 적용 방법, 튜닝 모델의 vLLM 배포와 운영 |
| RAG 심화와 지식 저장소 운영 | 2026년 RAG 과정 이후 기법 적용 실습, AI가 쓰는 지식 저장소(온톨로지, LLM wiki) 구축, 문서 갱신과 재색인, 검색 품질 평가, 이미지 문서의 비전 모델 기반 추출 |
| RE (Reverse Engineering)와 REA 활용법 | 코딩 Agent를 이용한 기존 프로그램 분석, REA 사용법 |
| Agent 모니터링 | Arize Phoenix 기반 실행 추적, 품질, 비용, 응답 시간 모니터링, 경보 기준과 장애 대응 절차, 운영 실패 사례의 평가셋 편입 |
| LLM 비용과 지연 최적화 | 캐싱, 모델 라우팅, 컨텍스트 축소, 지연과 토큰 관리 (호출 측 최적화 기준) |
| Agent 실행 제어 하네스 | 승인, 중단, 재시도, 재개, Trace 기반 실행 이력, Checkpoint 복구 (멀티 에이전트 역할 설계는 선택) |
| Agent 보안 설계 | prompt injection 방어, 도구 권한, 샌드박스. 실습: 사내형 공격 경로(오염된 문서, 도구 출력, 권한 초과)를 직접 만들어 자기 Agent를 시험하고, 뚫린 사례를 평가셋에 편입 |

## 5. 진행 조건

- 강의와 실습 비중: 강의 50%, 실습 50%
- 2026년 커리큘럼 활용 가능 (2026년 과정에 없는 주제만 신규 개발)
- 2026년 과정 재사용 모듈은 압축 적용 (예: Harness 4일 과정)
- 2인 1조 가상 프로젝트 1개를 2주 전체 모듈에서 이어서 사용, 발표 없음 (평가셋은 과정 초반에 만들어 CI/CD, 모니터링, 보안 실습에서 누적)
- 팀 Agent 운영 규칙 초안 작성 워크숍 포함 (등록 목록, 담당자, 인수인계, 폐기 기준, 업체는 양식 제공)
- 실습 데이터: 업체 제작 가상 프로젝트와 데이터만 사용 (회사 데이터와 코드 반출 불가)
- 사내 적용 범위 표시: Agent는 사내 전용으로 운영하고 모델은 사내 vLLM 기준. 주제별로 이 환경에서 적용 가능한 범위 표시
- 사내 GitLab 환경: Runner 사용 가능 (Docker executor, Runner 설정 변경 권한 없음), Runner에서 사내 LLM endpoint 호출 가능 (확인 완료)
- 오픈 모델 재실행: 도구 호출, 보안 공격, 캐싱 실습은 오픈 모델로 1회 재실행

## 6. 회신 요청 항목

- 교육 가능한 주제 (2주 기간에 넣기 어려운 주제는 별도 과정으로 진행 가능, 예: 소형 LLM 파인튜닝, RE와 REA 활용법)
- 모듈별 세부 커리큘럼과 시간 배분
- 시간 배분 2개 안과 안별 견적 (11개 전체 안, 소형 LLM 파인튜닝과 RE, REA를 별도 과정으로 뺀 안)
- 모듈별 2026년 과정 재사용, 신규 개발 구분
- 그 외 사내 폐쇄망 GitLab과의 차이 확인 사항 정리 (당사가 확인 후 회신)
- 실습 사용 도구와 패키지 목록, 라이선스, 오프라인 설치 가능 여부
- 오픈 모델과 GPU 실습 환경 제공 방식
- 견적: 1차수 금액과 4차수 총액
- Agent 보안 레드팀 심화(공격 자동 생성 도구 포함)의 별도 과정 가능 여부, 신규 개발 여부, 견적
- 투입 강사와 조교 인원, 강사 이력, 계약 후 개강까지 준비 기간
- 개인별 수료 판정 기준, 수료 산출물 (팀 Agent 저장소 템플릿: 지침 파일, CI 파이프라인, 평가셋, 모니터링 설정, 사내 이식 점검표)
- 교재, 실습 코드, 평가 세트의 소유권과 사내 재사용 조건
