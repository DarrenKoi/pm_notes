# 기반기술센터 AI Agent 고급 과정 커리큘럼 요청서

> 기반기술센터 구성원 대상 AI Agent 고급 과정(2주, 80시간)의 커리큘럼 제안 요청

## 1. 배경

- AX 확산으로 팀별 AI Agent 생성과 운영 증가, 그 수는 지속 증가 추세
- 교육 목적: 수료 구성원의 고품질 AI Agent 개발과 운영, 소속 팀 Agent 관리 역량 확보

## 2. 교육 대상 구성원

1. Agent를 혼자 개발하고 운영할 수 있는 구성원
2. 프로그래밍 언어(Python, SQL, JavaScript 등) 사용과 사내 시스템(HCP, DataLake) 활용이 가능한 구성원

위 역량은 선수 조건이며 과정에서 다시 다루지 않음

## 3. 과정 개요

| 항목 | 내용 |
|------|------|
| 대상 조직 | 기반기술센터 (2027년 센터 맞춤 과정) |
| 기간 | 연속 2주(10일), 하루 8시간, 총 80시간 |
| 인원 | 차수당 15명, 4차수, 총 60명 (검토 중) |
| 방식 | 대면 교육, 업체 교육장 (확정) |
| 실습 환경 | 업체 교육장 환경, public API 사용 (확정) |
| 개강 시기 | 협의 |

## 4. 커리큘럼 요청 범위

2026년 운영 과정의 재구성을 기본으로 하고, 2026년 과정에 없는 주제는 신규 개발 요청. 아래 주제를 포함한 세부 커리큘럼과 시간 배분 제안 요청

| 주제 | 다룰 내용 | 활용할 2026년 과정 | 신규 개발 요청 |
|------|-----------|--------------------|----------------|
| Git, GitLab 기본 사용법 | 커밋, 브랜치, MR, 충돌 해결 | 바이브코딩 풀스택 (GitHub 사용 부분) | GitLab 기준 실습 전체 |
| 팀 단위 Agentic Coding | 여러 구성원이 각자의 코딩 Agent로 하나의 저장소를 개발하는 방법, Agent 지침 파일과 Skill 공유 | 바이브코딩 풀스택 2일차 (CLI, MCP, 서브 에이전트, Hook, Skill), Harness/오케스트레이션 2일차 (Agent 지침 파일, Skill 명세) | 1인 사용법을 팀 단위 사용법으로 확장 |
| 사내 폐쇄망 GitLab과의 차이 | 사내 폐쇄망 GitLab에서 가능한 CI/CD 범위, GitLab.com 실습 내용을 사내로 옮길 때 달라지는 점 | - | 전체. 가능 범위는 업체가 확인 요청 사항을 전달하면 당사가 회신하는 방식으로 확인 후 커리큘럼에 반영 |
| AI 시스템용 GitLab CI/CD | Agent 테스트 자동화, 프롬프트와 모델 버전 관리, MR별 평가 게이트, 배포와 롤백 | 바이브코딩 풀스택 4일차 (GitHub Actions CI/CD), Agent Evaluation & Observability 2일차 (프롬프트 버전 관리, 변경 전후 품질 비교) | GitLab CI 기준 전환, MR별 평가 게이트 |
| 소형 LLM 파인튜닝 | 반도체 도메인 데이터(이미지, 문서, 사내 데이터 유형) 적용 방법, 튜닝 모델의 vLLM 배포와 운영 | LLM 활용과 고급화 5일차 (PEFT, LoRA, QLoRA), MLOps 및 Edge AI 배포 3일차 (서빙) | 이미지와 문서 데이터 적용, vLLM 배포와 운영 |
| RAG 동향과 AI용 DB 운영 | RAG 최신 동향 파악과 실습, AI가 쓰는 지식 저장소 운영법 (온톨로지, LLM wiki) | LLM 활용과 고급화 2~3일차 (검색 진단, Advanced RAG), AI 에이전트 프레임워크 구현 3일차 (Agentic RAG) | 온톨로지, LLM wiki 구축과 운영 |
| RE (Reverse Engineering)와 REA 활용법 | 코딩 Agent를 이용한 기존 프로그램 분석, REA 사용법 | - | 전체 |
| Agent 모니터링과 테스트 | 실행 추적, 품질, 비용, 응답 시간 모니터링, 평가셋 구축, Agent 테스트 방법 | Agent Evaluation & Observability 1~2일차, 바이브코딩 풀스택 3~4일차 (단위, E2E 테스트) | - |
| LLMOps | 캐싱, 모델 운영 최적화 (모델 라우팅, 서빙 최적화), 지연, 토큰, 비용 관리 | Agent Evaluation & Observability 2일차 (실행 시간, 토큰, 비용), MLOps 및 Edge AI 배포 3~4일차 (서빙, 모니터링) | 캐싱, 모델 라우팅 |
| Agent 보안 설계 | prompt injection 방어, harness 구축, 도구 권한, 샌드박스 | Harness/오케스트레이션 2~4일차 (실행 하네스, MCP와 도구 권한, Guardrails) | - |
| 2인 1조 토이 프로젝트 | 과정 중 병행하는 소규모 프로젝트. Git과 프롬프트 관리 실습 목적, 발표 없음 | AI 에이전트 프레임워크 구현 4일차 (Mini Project) 진행 방식 | 2주 병행 구조 |

위 2026년 과정 구분은 과정 개요 기준이며, 실제 교재 기준 확정은 업체 제안에 포함

선택 견적 대상 추가 과정: Agent 보안 레드팀, 평가 설계 심화

## 5. 진행 조건

- 강의와 실습 비중: 강의 50%, 실습 50%
- Git 상시 사용: 첫 주제 이후 모든 실습의 코드와 프롬프트를 GitLab 저장소로 관리하는 구조 (구성원의 Git 숙달 목적)
- 2인 1조 편성: 가능한 범위에서 토이 프로젝트와 실습을 2인 1조로 진행
- 실습 데이터: 업체 제작 가상 프로젝트와 데이터만 사용 (회사 데이터와 코드 반출 불가)

## 6. 회신 요청 항목

- 모듈별 세부 커리큘럼과 시간 배분
- 모듈별 2026년 과정 재사용, 수정, 신규 개발 구분
- 사내 폐쇄망 GitLab의 CI/CD 기능 확인 요청 사항 (당사가 확인 후 회신)
- 견적: 1차수 금액과 4차수 총액, 선택 견적은 과정별 분리
- 투입 강사와 조교 인원, 강사 이력, 계약 후 개강까지 준비 기간
- 수료 판정 방식과 산출물
- 교재, 실습 코드, 평가 세트의 소유권과 사내 재사용 조건
