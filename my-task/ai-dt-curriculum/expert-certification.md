# Expert 인증 체계 정리본

> Builder는 운영 중인 Agent와 개인 실기로, Guide는 실적과 판정 실습으로 인증한다. Guide 인증에는 Agent·tool 마켓 등록의 1차 승인 권한이 붙는다. 2026-10-09까지의 논의와 공개 인증 벤치마크를 반영한 확정본이다.

**읽는 법**: 점수·기간·건수는 파일럿 후 조정하는 값이다. 교육 내용은 [커리큘럼 정리본](./expert-curriculum.md)에 있다.

## 1. 왜 필요한가? (Why)

### 문제

교육을 들었다는 사실과 혼자 Agent를 만들어 운영할 수 있다는 사실은 다르다. 또 Agent를 잘 만드는 것과 남의 Agent를 판정하는 것도 다르다. 이 둘을 구분하지 않으면 마켓의 관문을 누구에게 맡길지 정할 수 없다.

### 안 하면 생기는 일

- 수료증만으로 Expert가 되면, 성공한 시연 하나로 역량을 판단하게 된다. 권한·중복 처리·복구를 확인하지 않은 Agent가 마켓에 올라간다.
- 승인 기준이 사람마다 다르면 관문이 팀마다 달라진다. 느슨한 팀으로 등록이 몰린다.

### 효과

- 인증받은 사람은 기록된 범위 안에서 독립 개발·운영 역량이 확인된 사람이다.
- 마켓에 올라간 Agent는 같은 필수 기준을 통과한 것이다.

### 측정 지표

| 지표 | 계산 |
|------|------|
| 관문의 효과 | 1차 승인에서 반려·보완된 비율과 주요 사유 |
| 인증의 지속성 | 인증 3개월 뒤에도 운영 중이며 한 번 이상 개선된 Agent 비율 |
| 심사 부담 | 후보 1인당 검토·재심 시간 |
| 심사 일치 | 심사자 간 총점 차이와 필수 기준 판정 불일치 건수 |

수료율과 인증율은 따로 보고한다. 운영 관찰이 필요해 첫 기수에는 "수료했지만 인증 유예"가 여럿 나올 수 있다. 인증율은 목표 지표가 아니며, 통과 기준은 파일럿 뒤에 근거가 있을 때만 조정한다.

## 2. 핵심 개념 (What)

### 기록의 종류

| 기록 | 발급 조건 | 뜻 |
|------|-----------|-----|
| Builder 과정 수료 | 필수 모듈과 과제 완료 | 과정을 마쳤다 |
| Expert Builder | 개인 실기·산출물·운영 증거·구술 통과 | 기록된 범위에서 독립 개발·운영 역량이 확인됐다 |
| Guide 과정 수료 | Guide 교육 완료 | 리뷰·지도·심사 방법을 배웠다 |
| Expert Guide | 유효한 Builder 인증 + 실적 + 판정 실습 통과 | 타인의 Agent를 판정하고 지도할 수 있다 |

- 인증 단계는 Builder와 Guide 두 개뿐이다.
- 분과마다 독립된 인증이다. 타 분과의 수료·인증을 입과 자격으로 요구하지 않는다.
- Guide 인증과 마켓 승인 권한의 활성 상태는 따로 관리한다 (5장).

### 인증에 붙는 권한

| 인증 | 권한 | 붙지 않는 것 |
|------|------|--------------|
| Builder | 팀의 Agent 개발·유지 역할 | 타인의 Agent 승인, 설비 제어 권한 |
| Guide | Agent·tool 마켓 등록의 1차 승인 | 최종 출시·보안 심사. 기존 조직 절차를 따른다 |

## 3. Builder 인증 (How)

### 심사 절차

1. 제출물과 개인 기여를 확인한다.
2. 심사자가 정한 입력으로 같은 버전의 Agent를 다시 실행한다.
3. 90분 개인 실기에서 요구사항 변경과 장애 진단을 수행한다.
4. 운영 관찰·복구·인수인계 증거를 검토한다.
5. 30분 구술에서 대안, 실패 원인, 권한, 운영 판단을 확인한다.
6. 점수와 필수 기준을 함께 판정한다.
7. 통과·보완·미통과와 근거를 기록한다.

실기에는 승인된 AI 코딩 도구와 문서를 허용한다. 생성된 코드를 본인이 설명·수정·검증할 수 있어야 한다.

### 평가표: 100점

| 영역 | 배점 | 통과 증거 |
|------|-----:|-----------|
| 업무 정의·해법 선택 | 10 | 기준선, 성공·실패 기준, Agent 선택 근거 |
| S/W·개인 구현 | 20 | 재현, 코드 이해, 변경 실기, 오류 처리 |
| Agent·도구·지식 연결 | 20 | 도구 계약, 상태·종료, 메모리, 검색·연결 동작 |
| 평가·회귀 | 20 | 평가 세트, 기준선 비교, 미공개 입력 확인 |
| 보안·권한·통제 | 15 | 접근 제한, 비밀정보 관리, 승인·주입 시험 |
| 배포·운영·인수인계 | 15 | 사용 관찰, 추적 기록, 장애 대응·복구 |

영역마다 0~4단계로 채점해 배점에 환산한다. 통과선은 총점 80점 이상, 모든 영역 3단계 이상, 아래 필수 기준 모두 통과다.

### 총점으로 상쇄하지 않는 필수 기준

1. 다른 사용자·조직의 허용되지 않은 정보에 접근하지 않는다.
2. 비밀정보를 코드·응답·로그에 노출하지 않는다.
3. 승인이 필요한 쓰기 동작은 승인 전에 실행되지 않는다.
4. 재시도·중복 요청이 업무를 중복 처리하지 않는다.
5. 도구 실패·컨텍스트 초과·예산 소진에서 종료하거나 정해진 대체 동작을 한다.
6. 모르는 질문이나 근거 없는 판단을 성공으로 처리하지 않는다.
7. 평가·운영 결과를 조작하지 않고 개인 기여를 설명한다.
8. 개인 실기에서 요구사항 변경과 장애 원인 설명·복구를 수행한다.

이 여덟 가지는 마켓 1차 승인의 기준으로도 그대로 쓴다. 교육에서 배운 기준과 승인 기준이 같다.

### 운영 증거

- 승인된 사용 범위에서 4주간 관찰한다. 실행 수, 입력 유형, 실패·중단, 사람 개입을 기록한다.
- 복구·중단·재개 시험을 한 번 이상 한다. 실제 장애가 없으면 장애를 주입해 시험한다.
- 운영 증거가 미완료이면 교육은 수료로 처리하고 Builder 인증은 유예한다.

### 직접 응시

이미 Agent를 개발·운영하는 사람은 교육 없이 같은 심사에 응시한다. 경력이나 외부 자격증만으로 인증을 발급하지 않는다.

## 4. Guide 인증 (How)

### 승급 요건

| 요건 | 내용 | 확인 방법 |
|------|------|-----------|
| Builder 인증 | 유효한 Expert Builder | 인증 대장 |
| 교육 이수 | Guide 과정 24시간 | 수료 기록 |
| 본인 Agent | 1건. Builder 인증 과제로 갈음 | Builder 심사 기록 |
| 타인과 함께한 Agent | 2건. 공동 개발 이력과 다른 팀 가이드 이력을 동등하게 인정 | 공동 개발 건은 본인 기여, 가이드 건은 가이드받은 사람이 혼자 수정·복구할 수 있는지 |
| 판정 실습 통과 | G1·G3에서 고의 결함이 섞인 제출물을 승인·보완·반려로 판정 | 놓친 필수 기준 위반과 과한 반려를 함께 본다 |

- 공동 개발 이력만으로도 실적 요건을 채운다. 가이드 건을 따로 강제하지 않는다.
- Fast Track 교육생을 가이드한 것도 실적으로 인정한다. 의무는 아니다.
- 리뷰·판정 경험의 공백은 판정 실습으로 메운다. 그래서 판정 실습은 필수 통과 요건이다.

### 승급 직후

승급 후 첫 마켓 승인 3건은 초기 심사단이 함께 확인한다. 판정이 맞으면 단독 승인으로 넘어간다.

### 평가표: 100점

| 영역 | 배점 | 확인 증거 |
|------|-----:|-----------|
| 설계·코드 리뷰 | 30 | 결함 근거, 우선순위, 판정 실습 결과 |
| 멘토링·학습자 자립 | 30 | 지도 기록, 함께한 사람의 독립 수행 |
| 재사용·운영 전파 | 20 | 타인의 실제 적용과 피드백 반영 |
| 평가·설명·심사 일치 | 20 | 공통 제출물 채점, 근거 설명 |

통과선은 Builder와 같다. 총점 80점 이상, 모든 영역 3단계 이상이다.

## 5. 마켓 1차 승인 (How)

### 누가 승인하는가

- Guide만 승인한다. Builder 인증만으로는 승인하지 못한다.
- 첫 Guide가 나오기 전에는 초기 심사단이 대행한다.
- Guide가 없는 팀의 Agent는 다른 팀 Guide가 승인한다.
- Guide 본인의 Agent는 본인이 승인하지 못한다. 다른 Guide가 승인한다.

### 무엇을 내는가

| 제출 항목 | Guide가 확인하는 것 |
|-----------|---------------------|
| 기능·사용 범위·버전 | 허용 사용자와 데이터, 수행 작업, 실패·중단 조건 |
| 도구 목록 | 도구마다 읽기 전용인지 쓰기·삭제·전송을 하는지 선언. 선언과 실제 동작이 같은지 |
| 필수 기준 시험 결과 | 3장의 필수 기준 여덟 가지 |
| 운영 담당자·제거 책임자 | 장애 연락, 중단, 인수인계 문서 |
| 알려진 한계 | 하지 못하는 일과 틀릴 수 있는 경우 |

### 등록 뒤

- 권한이나 도구가 늘어나면 재승인을 받는다. 그 밖의 변경은 변경 기록만 남긴다.
- 승인 기록을 남긴다. 필수 기준 위반을 통과시킨 것이 확인되면 조사한 뒤 해당 Guide의 승인 권한을 정지한다.
- 사고의 책임은 승인자 개인이 아니라 절차 개선에 묻는다. 승인자에게 사고 책임을 지우면 Guide를 맡을 사람이 없어진다.

### 범위

Guide의 승인은 1차 관문이다. 최종 출시·보안 심사를 대신하지 않는다. 마켓 등록 절차에 Expert 승인 단계를 넣는 일은 마켓 운영 조직에 요청할 사항이다(⟨확인: 마켓 운영 조직·2차 관문⟩).

## 6. 운영 (How)

### 첫 기수 심사단

- 사내 개발·운영 경험자와 Agent 개발 경험자로 초기 심사단을 꾸린다.
- 후보 1명당 심사자 2명이 따로 채점한다. 직속 멘토나 공동 개발자는 단독 심사자가 되지 않는다.
- 초기 심사단에게 Guide 인증을 자동으로 주지 않는다. Guide 심사에 먼저 응시할 기회를 준다.
- 심사자가 부족하면 기수 규모를 줄인다.

### 심사 편차와 이의

- 첫 심사 전에 통과·보완·미통과 제출물을 함께 채점해 해석을 맞춘다.
- 총점 차이가 10점을 넘거나 필수 기준 판정이 다르면 제3자가 다시 본다.
- 보완 기한은 통지 후 4주, 이의제기는 통지 후 10영업일이다.

### 유효기간과 갱신

| 항목 | 규칙 |
|------|------|
| 유효기간 | 2년. 매년 활동을 확인한다 |
| Builder 갱신 | 최근 12개월 안의 평가 갱신, 운영 개선, 장애 대응, 동등한 실기 중 하나 |
| Guide 갱신 | Builder 역량 유지 + 최근 지도·리뷰·승인 실적 |
| 승인 권한의 활성 | 1년간 승인·가이드 활동이 없으면 Guide 인증은 유지하고 승인 권한만 비활성으로 둔다. 판정 실습을 다시 통과하면 활성으로 돌린다 |
| 기준 변경 | 필수 기준이 바뀌면 해당 항목만 추가로 확인한다. 전체 재수강을 요구하지 않는다 |

### 인사 연계

승진·보상을 약속하지 않는다. 가이드·승인 활동에 쓰는 시간을 업무로 인정하는 것만 요구한다.

### 기록

첫 기수는 기존 학습 시스템이나 승인된 문서함과 인증 대장으로 운영한다. 별도 인증 플랫폼을 만들지 않는다. 대장에는 인증 단계와 상태, 기준 버전, 발급·만료일, 검증 범위, 증거 링크, 심사 근거, 승인 권한의 활성 여부를 남긴다.
