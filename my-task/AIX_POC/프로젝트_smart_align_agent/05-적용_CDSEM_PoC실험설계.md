# AIX 적용 사례 — CD-SEM 좌표 재정합 PoC 실험 설계 (KSF#1 검증)

> [!note] 설계 당시 기록과 현재 확인의 경계
> 2026-06월 기획/설계 문맥을 보존한 문서다. VLM의 좌표 정밀도·실시간 동작·24시간 무중단·Skew Zero는 목표/가설이며 검증된 성과가 아니다. 회사 API 차단·모델 별칭·DRM 비율·GUI/좌표 계약은 현재 환경에서 미확인이다. 체크 완료와 `통과`는 문서 작성/설계 점검이며 실제 PoC·장비 검증/승인을 뜻하지 않는다. 원래 본문은 남기고 아래 검토 절에 현재 적용 조건을 추가했다.


> [04 기술문서](./04-적용_CDSEM기술.md)에서 **1순위 선결 조건(KSF#1)** 으로 못 박은 *"VLM 좌표 재정합 정확도가 엔지니어 수용 기준 이상"* 을 실제로 검증하기 위한 실험 설계서. 04의 개발 일정 **Phase 0**에 해당하며, 통과해야 Phase 1(GUI 제어 통합)으로 넘어간다.

## 왜 이 실험이 먼저인가? (Why)

04의 To-Be는 두 개의 미검증 가정을 동시에 담고 있다 — (가정 A) VLM이 GUI를 직접 제어한다, (가정 B) VLM이 SEM 이미지를 보고 좌표/align을 재정합한다. 둘을 한 번에 검증하면 실패 원인을 분리할 수 없다.

본 PoC는 **가정 B만 격리**한다. 이유:

- **최대 리스크 우선** — ⑥ 오인식 수정의 본질은 "좌표를 맞히는 능력"이다. 이게 안 되면 GUI 제어가 완벽해도 과제는 성립하지 않는다. (No-Regret: 먼저 깨질 곳을 먼저 친다)
- **Align fail = ⑥의 대표 슬라이스** — align fail 시 recipe 수정과 ⑥ 오측/인식 실패 시 수정은 큰 틀에서 같은 개념(실측 이미지 기준 재정합·재등록)이라, align fail 좌표 재정합 정확도만 검증해도 ⑥ 병목 해소 가능성을 대표로 가늠할 수 있다. 게다가 align image 재등록(recipe tuning)은 비교적 간단한 축이라 PoC 진입점으로도 적합하다.
- **실 장비 영향 0** — GUI 제어를 빼면 실 장비·웨이퍼를 건드리지 않고 *오프라인 이미지→좌표* 만으로 검증 가능. 안전·비용·승인 부담 최소.
- **싸고 빠른 판단 게이트** — 정확도가 수용 기준 미달이면 GUI 제어 개발에 자원을 쓰기 전에 과제를 재설계한다.

## 무엇을 검증하는가 (What)

### 검증 가설

- **H1 (대립가설)**: 사내 VLM(Qwen3-VL)은 SEM 이미지에서 정렬 패턴과 측정 포인트 좌표를, 실측 시 발생하는 shift/align 실패 상황에서도 **엔지니어 수용 기준(τ) 이내로 재정합**할 수 있다.
- **H0 (귀무가설)**: VLM의 좌표 재정합 오차가 수용 기준을 넘어, ⑥ 자동화에 쓸 수 없다.

### 측정 대상 (03·04에서 지목한 집중 근본원인)

| 대상 | 정의 | 04 연결 |
|------|------|---------|
| **(a) 패턴 인식** | SEM 화면에서 Alignment/Addressing 패턴 위치를 찾는 능력 | 근본원인 (a) 패턴 인식 실패 |
| **(b) 측정박스·좌표** | 측정 포인트(EP) 좌표·측정박스 위치를 제시하는 능력 | 근본원인 (b) 측정박스·좌표 오류 |
| **(c) 오인식 검출** | "이 정합/측정이 틀렸다"를 스스로 판단하는 능력 (⑥의 핵심) | ⑥ 오인식 수정 반복 |

### 성공 기준 (수용 기준 — 임계값은 엔지니어 협의)

> 구체 수치(τ, r, N)는 측정박스 허용 범위·공정 스펙에 의존하므로 **엔지니어가 확정**한다. 본 문서는 기준의 *형식*만 고정한다.

- **정확도**: 예측 좌표와 정답 좌표 간 오차의 **P95 ≤ τ** (τ = 허용 측정박스/정렬 마진 기반).
- **재정합 성공률**: shift/align 실패 케이스에서 오차 ≤ τ로 복구한 비율 **≥ s%**.
- **오인식 검출**: **recall ≥ r** (놓치면 불량 측정 유발 → 높게) + **false-alarm rate ≤ f** (너무 잦은 사람 호출은 효용 상쇄).

## 어떻게 검증하는가 (How)

### 1. 실험 구성

| 요소 | 설계 |
|------|------|
| **데이터셋** | ① 기존 등록 Recipe + 대응 SEM 이미지 = 정답(ground-truth, 숙련 엔지니어 라벨) / ② 과거 ⑥에서 실제 오인식·shift가 났던 케이스 = **hard set** / layer별 균형, 최소 N건(N=엔지니어 협의) |
| **모델** | 사내 **Qwen3-VL-8B vs 30B** 비교 (정확도/latency trade-off 확인) |
| **비교군(baseline)** | ① 장비 기본 템플릿 매칭 성공률(이걸 넘어야 의미) / ② 숙련 엔지니어 수동 재정합(정확도 상한 reference) |
| **출력 방식** | VLM grounding 프롬프트로 정규화 좌표/bbox 출력 → 픽셀(또는 장비 좌표계)로 역변환 후 정답과 비교 |

### 2. 평가 메트릭 (정량)

1. **좌표 오차 분포** — median·P95 (px 또는 nm 환산). 핵심 지표.
2. **재정합 성공률** — shift/align 실패 케이스에서 오차 ≤ τ 복구 비율.
3. **오인식 검출 성능** — precision/recall, false-alarm rate.
4. **자율 처리율 vs 핸드오프율** — 예외 임계 적용 시 사람 개입 없이 통과한 비율(KSF#3 연결).
5. **모델 비교·latency** — 8B vs 30B 정확도·응답시간.

### 3. 실험 절차

```
1) 데이터 수집·라벨링: 기존 Recipe·SEM 이미지에서 정답 좌표 추출 (캡처+VLM 추출, 익명화)
2) hard set 구성: 과거 오인식/shift 케이스 분리
3) 추론: Qwen3-VL(8B·30B)에 이미지 입력 → 좌표·오인식 판단 출력
4) 정답 대조: 오차 분포·성공률·검출 성능 산출
5) baseline 대비: 템플릿 매칭·엔지니어 기준과 비교
6) 게이트 판정 (아래)
```

### 4. 실험 환경 (제약 반영)

- **오프라인·섀도우** — 실 장비/웨이퍼 영향 0. 이 PoC는 *이미지→좌표* 만 검증하고 **실제 GUI 제어는 범위 밖**(Phase 1).
- **사내 엔드포인트만** — 외부 LLM 차단, Qwen3-VL OpenAI-호환 내부 API 사용.
- **DB 로컬 미가용** — 코드 검증은 import·문법 수준, 데이터는 파일 기반.
- **DRM** — 사내 문서/이미지 99% DRM → 스크린샷+VLM 추출이 기본, 익명화 후 사용.

### 5. 판단 게이트 (Phase 0 → 다음)

| 결과 | 조건 | 다음 액션 |
|------|------|-----------|
| **PASS** | P95 오차 ≤ τ **그리고** 오인식 recall ≥ r | Phase 1 진행 — GUI 제어 통합 |
| **CONDITIONAL** | 일부 layer/패턴만 충족 | 충족 범위로 적용 좁혀 진행 + 미충족 원인 분석 |
| **FAIL** | 수용 기준 미달 | 과제 재설계 — fine-tune / 전용 vision 모델 / hybrid(템플릿+VLM) 검토 |

## 리스크 & 한계

- **VLM 좌표 정밀도** — 범용 VLM의 grounding이 계측 수준 정밀도에 못 미칠 수 있음(이 PoC가 검증하려는 바로 그 점). FAIL 시 fine-tune·전용 모델이 대안.
- **정답 라벨 품질** — ground-truth가 숙련 엔지니어 판단에 의존 → 라벨 합의 기준 필요.
- **격리의 한계** — GUI 제어를 뺐으므로, PASS여도 Phase 1에서 *제어 안정성*은 별도 검증 필요(가정 A).
- **데이터 대표성** — hard set이 실제 오인식 분포를 충분히 반영해야 일반화 가능.

## 2026-10-04 검토 보완 — 실행 전 적용 조건

원래 실험 설계/체크리스트는 당시 기록으로 보존했다. 아래는 현재 문서 검토에서 발견한 누락을 보완한 조건이며 이번 작업에서 PoC를 수행한 결과가 아니다.

### 데이터·정답·분할

- Recipe에 기록된 좌표는 출처 후보이며 곧바로 영상 정답이 아니다. 숙련자 라벨/합의 기준·영상 좌표계·오차 단위와 실제 유효성 확인을 별도로 남긴다. 평가 대상VLM이 추출한 좌표를 같은VLM의 정답으로 사용하지 않는다.
- 같은 Recipe/웨이퍼·연속 캡처의 근접 이미지가 학습·조정·평가 양쪽에 섞이지 않도록 출처 단위로 분할한다. 분할 정책·표본 수/정상·실패 분포·라벨/이미지 버전을 고정하고 hard set 성능과 대표 운영 분포 성능을 구분한다.
- 크로스헤어/오버레이가 정답을 직접 노출하는지 확인한다. 누출 있는 입력과 실제 추론 입력을 구분하며,샘플 몇 건으로 모델 일반화를 주장하지 않는다.

### 좌표와 지표 정의

| 항목 | 현재 적용 시 필요한 정의 |
|---|---|
| 좌표 계약 | 원본/crop·resize·padding·화면DPI·점/bbox·원점/축/정규화 범위·역변환을 API별로 확인. 픽셀→nm/장비 좌표는 배율·캘리브레이션 근거 없으면 미확인 |
| P95 | 유효 오차의 단위/노름·표본 수·percentile method·실패 출력 처리를 고정. 파싱 실패/범위 밖/무응답을 조용히 제외해 성능을 올리지 않음 |
| 검출 | 양성=실제 오인식으로 고정. precision=TP/(TP+FP),recall=TP/(TP+FN),false-alarm을FPR로 쓰면FP/(FP+TN). 분모0은 정의 불가/표본 부재로 표시 |
| 재정합 성공률 | 동일 실패 모집단에서 오차 기준 충족 건수/평가 대상 실패 건수. 정합 실패·무응답·핸드오프 포함 여부를 명시 |
| 자율 처리율 | 평가 대상 전체 중 사람 개입 없이 종료한 비율. 처리율뿐 아니라 잘못된 자동 통과 건수/전체와 자동 통과 중 오류도 함께 기록 |
| 기호 | 이 문서의r은recall임계로 쓰였고04/양식의r은재시도 횟수다. 적용 계획에서는 `τ_recall`과 `r_retry`로 분리하고s성공률과공수s도 분리 |

### 보완 게이트

원래PASS표는P95와recall만 요구해 본문의재정합 성공률·false-alarm조건을 누락했다. 현재 실행판정은 확정된 **P95오차·재정합성공률·recall·false-alarm조건을 모두** 대조해야 한다. 값·단위·표본·출력실패처리·라벨·계약이 미확정이면 `UNCONFIRMED`로 두며PASS/CONDITIONAL로 진행하지 않는다. 조건부 통과도 해당layer/패턴/입력조건·근거·담당자승인으로 범위를 제한한다. 오프라인통과가 장비/GUI통합통과를 대신하지 않는다. H1/H0는 현재 운영 가설이며 통계검정 절차/유의수준을 정의하지 않아 통계적 기각으로 해석하지 않는다.

### 버전·출처와 미확인

- [Qwen 공식 저장소](https://github.com/QwenLM/Qwen3-VL): 8B와30B-A3B의Instruct/Thinking를 구분한다(확인2026-10-04). 원문30B는 당시사내별칭으로 보존했다. 실제weight/revision·양자화·API배포/입출력 계약·장비 성능은 미확인이다. 공개grounding지원은 SEM계측정밀도 검증 결과가 아니다.
- [scikit-learn 지표 문서](https://scikit-learn.org/stable/modules/model_evaluation.html)(확인시표시1.9.1,2026-10-04): precision/recall의분모 정의를 대조했다. 로컬scikit-learn이나모델을 실행했다는 뜻이 아니다.
- [NumPy1.26 percentile](https://numpy.org/doc/1.26/reference/generated/numpy.percentile.html): percentile의method를명시해야 같은 P95계산을 재현한다(확인2026-10-04). 로컬검사는 별도의 가상수열산술만 허용하며 실제PoC는 실행하지 않았다.
- [NIST AI RMF1.0](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf),MEASURE2.1/2.3/2.5의시험조건·한계 기록과 대조했다. 회사 승인/임계값을 대신하는 규칙은 아니다.
