# AI 용어 및 기술 HTML 리더 설계

## 목표

`ai-dt/ai-terms-and-technologies/`의 Markdown 자료를 사람이 더 쉽게 탐색하고 읽을 수 있는 정적 HTML 학습 포털로 변환한다.

완성된 결과는 `ai-dt/ai-terms-and-technologies/html/index.html`을 더블클릭하는 것만으로 사용할 수 있어야 한다. 인터넷 연결, CDN, 패키지 설치, 로컬 서버는 필요하지 않다.

## 범위

### 변환 대상

- `README.md`
- `01-ai-model-families.md`
- `02-vector-embedding-and-rag.md`
- `03-zero-shot-and-few-shot.md`
- `04-vibe-coding-harness-agent-orchestration.md`

`README.md`는 포털의 `index.html`이 되고, 나머지 문서는 같은 기본 파일명을 가진 `.html` 페이지가 된다.

### 범위에서 제외하는 것

- 원본 Markdown 내용 수정
- 외부 검색 서비스 또는 서버 검색
- 로그인, 사용자 계정, 학습 이력 동기화
- 외부 글꼴, 아이콘, 이미지, JavaScript 라이브러리
- Markdown 밖의 다른 `ai-dt` 자료를 HTML로 추가 변환

## 설계 원칙

1. **오프라인 우선**: 모든 읽기 기능은 `file://` 환경에서 동작한다.
2. **원본 보존**: 문장, 표, 목록, 인용문, 코드 블록과 링크를 빠뜨리지 않는다.
3. **점진적 향상**: JavaScript가 꺼져도 본문과 기본 링크를 읽을 수 있다.
4. **접근성**: 시맨틱 HTML, 키보드 포커스, 충분한 색상 대비와 축소 동작 설정을 제공한다.
5. **재현 가능성**: 같은 Markdown에서 빌드하면 같은 HTML이 만들어진다.
6. **유지보수성**: 표준 Python 라이브러리만 사용하는 빌더로 다시 생성할 수 있다.

## 정보 구조

### 홈 포털

`index.html`은 다음 순서로 구성한다.

1. 컬렉션 제목과 입문 자료 설명
2. 문서 수, 학습 수준, 주요 용어 수를 보여 주는 요약 지표
3. `all-in-one.html`로 이동하는 통합본 추천 카드
4. 권장 학습 순서를 유지한 01~09 장 카드
5. 용어 또는 질문으로 장을 찾는 로컬 검색 입력
6. Markdown `README.md`의 권장 학습 순서와 빠른 용어 찾기
7. 읽을 때 기억할 점과 관련 학습 자료

검색은 각 장의 제목, 소제목과 본문에서 추출한 일반 텍스트를 카드의 검색 데이터로 내장한다. 입력하면 장 카드와 빠른 용어 표의 행을 즉시 필터링한다. 검색 결과가 없으면 입력값을 포함한 빈 상태 메시지를 보여 준다.

### 장별 리더

장별 페이지는 다음 영역으로 구성한다.

- 상단 읽기 진행률 표시
- 홈 링크, 현재 장 번호, 테마 전환 버튼이 있는 상단 바
- 01~09와 통합본을 오갈 수 있는 장 탐색
- 제목, 메타데이터와 첫 인용문을 강조한 문서 헤더
- 변환된 Markdown 본문
- 현재 문서의 `h2`와 `h3`에서 만든 문서 목차
- 이전 장과 다음 장 링크

데스크톱에서는 장 탐색, 본문, 문서 목차를 나란히 배치한다. 좁은 화면에서는 탐색과 목차를 접을 수 있는 메뉴로 바꾸고 본문을 한 열로 표시한다.

첫 인용문은 문서 헤더에서 한 번만 표시하고 본문에서는 중복 출력하지 않는다. 인용문의 문장 자체는 그대로 유지한다.

## 시각 체계

### 방향

- 밝은 편집 문서 스타일을 기본으로 사용한다.
- 짙은 남색 본문과 옅은 회색·청색 배경으로 긴 글의 피로를 낮춘다.
- 인디고와 시안 계열을 주요 강조색으로 사용한다.
- 각 장은 구별 가능한 보조 강조색을 갖되 전체 팔레트는 일관되게 유지한다.
- 시스템 글꼴만 사용해 오프라인 환경에서도 한글이 자연스럽게 표시되게 한다.

### Markdown 요소 표현

- `h2`, `h3`: 명확한 위계, 충분한 위아래 간격과 앵커 링크
- 표: 헤더 강조, 교차 행 배경, 작은 화면의 가로 스크롤
- 인용문: 핵심 요약 카드
- `text` 코드 블록: 흐름도와 개념 구조를 위한 시각 패널
- 그 밖의 코드 블록: 복사하기 쉬운 고정폭 코드 패널
- 인라인 코드: 용어 칩
- 목록: 넉넉한 항목 간격과 읽기 쉬운 들여쓰기
- 링크: 본문과 구분되는 색, 밑줄과 명확한 포커스 상태

### 테마와 인쇄

기본은 밝은 테마이며 사용자가 어두운 테마로 전환할 수 있다. 선택은 `localStorage`에 저장하되 저장소를 사용할 수 없으면 현재 페이지에만 적용한다.

인쇄할 때는 탐색, 검색, 테마 버튼과 진행률을 숨긴다. 본문 폭과 표의 대비를 인쇄에 맞게 조정하고 링크 대상 URL은 본문을 방해하지 않도록 추가 출력하지 않는다.

## 변환 구조

### `build.py`

빌더는 변환 대상과 순서를 명시적으로 관리한다. 각 Markdown 파일에서 YAML 형태의 단순 front matter, 제목과 본문을 읽고 다음 블록을 변환한다.

- 제목
- 문단
- 순서 있는 목록과 순서 없는 목록
- 인용문
- fenced code block
- 표
- 수평선
- 굵게, 기울임, 인라인 코드와 링크

현재 문서 집합에서 사용하지 않는 Markdown 문법을 만났을 때 내용을 삭제하지 않는다. 안전하게 이스케이프한 일반 문단 또는 코드 텍스트로 남긴다.

빌더는 본문에서 `h2`와 `h3` 목차를 만들고, 중복 제목에도 충돌하지 않는 결정적 앵커 ID를 부여한다. 모든 텍스트는 HTML로 이스케이프한 뒤 허용한 Markdown 인라인 표현만 태그로 바꾼다.

### 링크 변환

- 변환 대상 `.md` 링크는 대응하는 `.html` 링크로 바꾼다.
- 같은 문서 안의 앵커와 다른 변환 문서의 앵커는 생성된 HTML 앵커를 가리킨다.
- 외부 `https://` 링크는 그대로 유지한다.
- 변환 범위 밖의 상대 링크는 원본 Markdown 파일을 기준으로 해석한 뒤 HTML 폴더에서 접근할 수 있는 상대 경로로 다시 계산한다.
- 존재하지 않는 변환 대상 링크가 있으면 빌드를 실패시킨다.

### `styles.css`

색, 간격, 타이포그래피, 반응형 배치, 문서 요소, 어두운 테마, 인쇄 스타일을 한 파일에서 관리한다. 각 HTML 페이지에는 문서별 인라인 스타일을 두지 않는다.

### `app.js`

다음 향상 기능만 담당한다.

- 밝은/어두운 테마 전환
- 읽기 진행률 계산
- 모바일 장 탐색과 문서 목차 열기·닫기
- 홈의 장 카드와 용어 표 필터링
- 현재 목차 항목 표시

JavaScript에서 본문 파일을 `fetch`하지 않는다. 모든 콘텐츠는 각 HTML에 이미 포함되어 있어야 한다.

## 오류 처리와 안전성

- 필수 Markdown 파일이 없으면 해당 경로와 함께 빌드를 중단한다.
- front matter 종료 구분자가 없으면 파일명을 포함한 오류를 낸다.
- 중복 출력 파일명 또는 중복 문서 식별자를 거부한다.
- 깨진 내부 변환 링크가 있으면 링크가 발견된 원본 문서를 표시한다.
- 사용자 검색어는 HTML로 삽입하지 않고 `textContent`로만 표시한다.
- 외부 스크립트 실행이나 원본 Markdown의 임의 HTML 실행을 허용하지 않는다.

## 검증

### 자동 검증

`html/tests/test_build.py`는 Python 표준 `unittest`로 다음을 확인한다.

1. 11개 원본이 11개 HTML 문서로 생성된다.
2. front matter가 본문에 노출되지 않고 메타데이터로 변환된다.
3. 표, 목록, 인용문, 코드 블록과 인라인 링크가 보존된다.
4. 변환 대상 `.md` 링크가 `.html`로 바뀐다.
5. 범위 밖 상대 링크가 올바른 위치를 가리킨다.
6. 한글 제목 앵커가 중복 없이 결정적으로 생성된다.
7. 위험한 원본 HTML과 스크립트 문자열이 실행 가능한 태그로 출력되지 않는다.
8. 누락된 입력과 깨진 내부 링크가 명확한 오류를 낸다.

### 생성 결과 검증

- `build.py`를 두 번 실행해 생성 결과가 달라지지 않는지 확인한다.
- 생성된 모든 로컬 링크와 파일 참조가 존재하는지 검사한다.
- `index.html`과 대표 장 페이지를 데스크톱·모바일 크기로 확인한다.
- JavaScript를 사용할 때와 사용하지 않을 때 모두 본문과 기본 이동이 가능한지 확인한다.
- 밝은 테마, 어두운 테마와 인쇄 미리보기의 대비와 넘침을 확인한다.

## 완료 기준

- `html/index.html`을 직접 열면 외부 요청 없이 홈 포털이 표시된다.
- 11개 Markdown 문서의 내용이 대응 HTML에 빠짐없이 존재한다.
- 장 카드, 용어 검색, 장 이동, 문서 목차, 진행률과 테마 전환이 동작한다.
- 360px 너비에서 본문을 읽을 수 있고 표는 페이지 전체를 깨뜨리지 않는다.
- 키보드만으로 모든 링크, 버튼과 메뉴를 사용할 수 있다.
- 모든 자동 검증과 로컬 링크 검사가 통과한다.
- 원본 Markdown과 작업 범위 밖 파일은 변경하지 않는다.
