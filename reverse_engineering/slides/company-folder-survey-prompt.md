# 도구별 폴더의 구성을 조사해 보고하는 작업 지시

> 이 파일은 도구별 폴더를 맡은 에이전트(pi)에게 주는 조사 지시다. 사람은 "`reverse_engineering/slides/company-folder-survey-prompt.md`를 읽고 그대로 실행해"라고만 말하면 된다. 에이전트는 아무것도 고치지 않고, 폴더의 **구성만** 적은 짧은 보고서 하나를 만든다.

## 왜 필요한가? (Why)

발표 deck에 사내 결과를 넣는 양식(`extra_template.json`)과 작업 지시(`company-results-prompt.md`)는 회사 밖에서 만들었다. 만든 쪽은 도구별 폴더의 `.md`가 어떤 모양인지 보지 못했다. 양식의 칸이 실제 기록과 맞는지 알아야 양식을 고칠 수 있다.

이 보고서는 **회사 밖으로 나간다**. 그래서 내용이 아니라 구성만 적는다. 이 조사에서 가장 중요한 규칙이다.

## 핵심 개념 (What)

### 조사 대상

`reverse_engineering/` 바로 아래 폴더 중 `slides`, `templates`를 뺀 모든 폴더. 사람이 폴더를 따로 말했으면 그 폴더만 본다.

### 보고서에 적어도 되는 것과 안 되는 것

| 적어도 된다 | 적지 않는다 |
|---|---|
| 파일 수, 줄 수, 그림 수 | 폴더 이름, 파일 이름 |
| 절 제목의 **종류**(예: 질문, 대상 식별, 결론) | 절 제목이나 본문의 원문 |
| 있음, 없음, 일부 있음 | 장비 이름, 제품 이름, 회사 이름, 사람 이름 |
| 대상의 일반 분류(네이티브 exe, 관리 .NET, 웹 앱 등) | 경로, 주소, 함수 이름, 문자열, 코드, 프롬프트 원문 |
| 쓰인 낱말의 종류(예: 등급을 "관찰, 추론"으로 적음) | 수치의 실제 값, Evidence ID의 실제 값 |

폴더는 폴더 이름 순서대로 `폴더 1`, `폴더 2`라고 부른다. 적어도 되는지 애매하면 적지 않고 "사람 확인 필요"에 "애매한 항목 있음"이라고만 적는다.

### 결과물

`slides/survey-report_사내용.md` 하나. 이름에 `_사내용`이 있어 git에서 제외된다. 60줄 이내로 쓴다. 다른 파일은 만들거나 고치지 않는다.

## 어떻게 사용하는가? (How)

### 1. 읽는다

1. 대상 폴더의 모든 `.md`를 읽는다. 하위 폴더도 본다.
2. `templates/investigation-log.md`를 읽는다. 분석 기록 양식이다(절 7개).
3. `slides/extra_template.json`을 읽는다. 슬라이드 여섯 칸이다.

### 2. 환경을 확인한다

`slides` 폴더에서 아래를 실행하고 결과를 적어 둔다. 실패해도 고치거나 설치하지 않는다.

```powershell
python --version
python -c "import pptx, lxml; print('ok')"
git log -1 --format=%cd --date=short
git status --short
```

### 3. 보고서를 쓴다

아래 양식을 그대로 복사해 `⟨ ⟩`를 채운다. 폴더마다 A절을 한 번씩 쓴다.

```markdown
# 도구별 폴더 조사 보고

## A. 폴더 ⟨번호⟩
- .md 파일 수: ⟨수⟩, 전체 줄 수: 약 ⟨수⟩, 그림 파일 수: ⟨수⟩, 하위 폴더: ⟨있음, 없음⟩
- 대상의 일반 분류: ⟨네이티브 exe, 관리 .NET, PyInstaller, Electron, 웹 앱, 기타, 여러 종류⟩
- 분석 기록 양식(절 7개)을 따른 파일: ⟨수⟩개 / 따르지 않은 파일: ⟨수⟩개
- 양식을 따르지 않은 파일의 절 구성(종류만): ⟨예: 배경, 시도한 것, 결과, 남은 일⟩
- 글의 언어: ⟨한국어, 영어, 섞임⟩ / 표가 많은가: ⟨예, 아니요⟩ / 코드 블록이 많은가: ⟨예, 아니요⟩

양식 여섯 칸에 넣을 내용이 있는가 (있음, 일부, 없음 중 하나와 한 줄 설명)
1. 무엇으로 만든 프로그램인가: ⟨⟩
2. 실제로 보낸 프롬프트(원문이 남아 있는가): ⟨⟩
3. 단서를 따라간 기록(화면, 문자열, 상호 참조, 함수, 의사 코드 순서): ⟨⟩ / 단계 수: ⟨수⟩
4. REA가 돌려준 결과: 관찰 ⟨⟩, 추론 ⟨⟩, 미확인 ⟨⟩, 한계 ⟨⟩, 커버리지 ⟨⟩
5. 질문별 답: 질문 수 ⟨수⟩, 답마다 등급이 붙어 있는가 ⟨모두, 일부, 없음⟩
6. 팀원이 가져다 쓸 자료: 프롬프트 ⟨수⟩, 호출 순서 ⟨수⟩, 막힌 곳과 해결 ⟨수⟩, 스크립트나 체크리스트 ⟨수⟩, 참고 문서 ⟨수⟩

기록 방식
- 등급을 적는 낱말: ⟨예: 관찰, 추론, 미확인 / 답함, 일부 답함, 미해결 / 없음⟩
- Evidence ID가 적혀 있는가: ⟨모두, 일부, 없음⟩
- 측정한 수치(걸린 시간, 함수 수)가 있는가: ⟨있음, 없음⟩
- 같은 내용이 파일마다 다르게 적힌 곳: ⟨있음(몇 군데), 없음⟩

## B. 양식에 맞지 않는 것
- 여섯 칸 어디에도 들어가지 않지만 발표할 만한 내용의 종류: ⟨예: 버전 간 비교, 설정 파일 구조, 실패한 시도. 없으면 없음⟩
- 글 분량의 한도를 넘을 것 같은 칸: ⟨칸 번호와 이유. 예: 5번, 질문이 12개⟩
- 한 폴더에 분석 대상이 여러 개인가: ⟨예(몇 개), 아니요⟩

## C. 환경
- python: ⟨버전, 또는 명령 없음⟩ / pptx, lxml: ⟨ok, 또는 오류 이름⟩
- slides 폴더의 마지막 커밋 날짜: ⟨날짜⟩
- git status에 대상 폴더가 Untracked로 보이는가: ⟨예, 아니요⟩
- slides 폴더에 extra_template.json, company-results-prompt.md가 있는가: ⟨예, 아니요⟩

## D. 사람 확인 필요
- ⟨적어도 되는지 애매해서 뺀 항목이 있으면 "애매한 항목 있음(몇 건)". 없으면 없음⟩
```

### 4. 스스로 검사한다

보고서를 저장하기 전에 처음부터 다시 읽고 아래를 확인한다. 하나라도 걸리면 그 부분을 지운다.

- 폴더 이름, 파일 이름, 장비나 제품 이름, 사람 이름이 없다.
- 경로, 주소, 함수 이름, 코드, 프롬프트 원문, 실제 수치가 없다.
- `.md`의 문장을 그대로 옮긴 곳이 없다.
- 60줄 이내다.

### 5. 끝낸다

보고서의 위치를 알리고 끝낸다. 커밋과 push를 하지 않는다. 대상 폴더의 `.md`와 `slides`의 다른 파일을 고치지 않는다.

사람은 보고서를 직접 읽어 위 검사 항목을 한 번 더 확인한 뒤에 회사 밖으로 가져간다.
