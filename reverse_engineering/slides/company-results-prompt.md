# 사내 분석 결과를 deck 두 벌에 넣는 작업 지시

> 이 파일은 에이전트(pi)에게 주는 작업 지시다. 사람은 에이전트에게 "`reverse_engineering/slides/company-results-prompt.md`를 읽고 그대로 실행해"라고만 말하면 된다. 에이전트는 이 파일을 처음부터 끝까지 읽고 순서대로 실행한다.

## 왜 필요한가? (Why)

회사 PC에서는 `reverse_engineering/` 아래 도구별 폴더에 REA로 얻은 분석 결과를 `.md`로 모아 둔다. 너(에이전트)는 그 내용을 양식 한 파일에 채워 발표 deck 두 벌(입문 deck, 팀 공유 deck)에 넣는다. 이 작업에서 깨지기 쉬운 것은 세 가지다.

- **근거**: 기록에 없는 내용을 짐작으로 채우거나, 추론을 관찰처럼 고쳐 쓴다.
- **기밀**: 장비 이름, 경로, 디컴파일 코드가 공개 저장소에 올라가는 파일에 섞인다.
- **범위**: 결과물이나 스크립트를 직접 고쳐서 다음 생성 때 사라지거나 공개 deck이 바뀐다.

## 핵심 개념 (What)

### 입력값

사람이 따로 말하지 않으면 아래 기본값을 쓴다. 사람이 말했으면 그 값을 쓴다.

| 입력 | 기본값 |
|---|---|
| 대상 폴더 | `reverse_engineering/` 바로 아래 폴더 중 `slides`, `templates`를 뺀 모든 폴더 |
| 도구 별칭 | 폴더 이름 순서대로 `도구 A`, `도구 B`, `도구 C`. 폴더 이름과 장비 이름은 별칭으로 쓰지 않는다 |
| 입문 deck에 넣을 장수 | 5 |

대상 폴더가 하나도 없거나 `.md`가 없으면 아무것도 만들지 않고 그 사실을 보고한 뒤 멈춘다.

### 파일

| 파일 | 역할 | 네가 할 일 |
|---|---|---|
| `slides/team-intro-editing-guide.md` | 항목의 뜻, 글 분량의 한도, 내용 규칙 | 읽는다 |
| `slides/extra_template.json` | 양식. 도구 하나에 슬라이드 여섯 칸. 채울 곳은 `⟨ ⟩`로 표시 | 읽는다. 고치지 않는다 |
| 대상 폴더의 `.md` | 분석 결과. 내용의 유일한 근거 | 읽는다. 고치지 않는다 |
| `slides/extra_사내용.json` | 양식을 채운 결과 | **만든다. 네가 쓰는 유일한 파일이다** |
| `slides/build_team_intro.py` | deck 생성 스크립트 | 실행한다. 고치지 않는다 |
| `slides/*_사내용.*` | 스크립트가 새로 만드는 결과물 네 개 | 직접 고치지 않는다 |
| `slides/re-rea-team-intro.*`, `slides/re-rea-team-share.bento.html` | 공개 deck. 스크립트가 읽기만 한다 | 고치지 않는다. 덮어쓰지 않는다 |

### 양식의 여섯 칸

| 순서 | 내용 | kind | 입문 deck에서 들어가는 자리 | deck 기본값 |
|---|---|---|---|---|
| 1 | 무엇으로 만든 프로그램인가 (판별 결과) | `table` | 12장 뒤 | `share` |
| 2 | 실제로 보낸 프롬프트 | `code` | 22장 뒤 | `share` |
| 3 | 단서를 따라간 기록 | `draw_chain` | 9장 뒤 | 둘 다 |
| 4 | REA가 돌려준 결과 (관찰, 추론, 미확인, 한계) | `draw_result` | 25장 뒤 | 둘 다 |
| 5 | 질문별 답과 등급 | `table` | 26장 뒤 | 둘 다 |
| 6 | 팀원이 가져다 쓸 자료 | `table` | 26장 뒤 | `share` |

### deck 항목

| 값 | 들어가는 곳 |
|---|---|
| 없음 또는 `"both"` | 입문 deck과 팀 공유 deck |
| `"intro"` | 입문 deck만 |
| `"share"` | 팀 공유 deck만 |

팀 공유 deck에서는 파일에 적힌 순서대로 마지막 슬라이드("시작하기") 앞에 한 절로 들어간다. 그래서 도구별로 여섯 칸을 이어서 적는다.

### 결과물은 새 파일로 나온다

`extra_사내용.json`이 있으면 스크립트는 이름에 `_사내용`이 붙은 새 파일 네 개만 만든다. 이미 있는 공개 deck 파일은 읽기만 하고 다시 쓰지 않는다. 실행 뒤 `git status`에 공개 deck 파일이 "modified"로 보이면 잘못된 것이므로 멈추고 보고한다. 결과를 공개 deck 파일 이름으로 복사하거나 저장하지 않는다.

### 팀원이 가져다 쓸 자료

여섯째 칸에는 분석 결과가 아니라 **다른 도구를 분석할 때 다시 쓸 수 있는 것**을 뽑는다. 대상 폴더의 `.md`에서 아래에 해당하는 것을 찾는다.

| 종류 | 예 |
|---|---|
| 다시 쓸 수 있는 프롬프트 | 대상과 질문만 바꾸면 되는 프롬프트 |
| 잘 통한 REA 도구와 호출 순서 | 어떤 도구를 어떤 순서로 불러서 답을 얻었는가 |
| 막힌 곳과 해결 방법 | 오류, 시간 초과, 도구의 제약과 돌아간 길 |
| 만든 스크립트, 체크리스트, 양식 | 복사해서 쓸 수 있는 것 |
| 참고한 문서 | 이 저장소의 문서나 사내 문서 이름 |

행마다 "어디에 쓰나"를 팀원의 상황으로 적는다(예: 설치 폴더를 처음 받았을 때). "있는 곳"에는 `.md` 파일 이름과 절 제목을 적어 팀원이 원문을 찾아가게 한다. 파일 이름에 장비 이름이 들어 있으면 적지 않고 "확인 필요"에 적는다. 특정 도구에만 맞고 다시 쓸 수 없는 것은 넣지 않는다.

### 스크립트가 검사하는 것

- `⟨ ⟩` 칸이 하나라도 남아 있으면 멈추고 그 슬라이드 제목을 알려 준다.
- `after`, `kind`, `deck` 값이 틀리면 멈춘다.
- 글이 상자를 넘치는지는 검사하지 않는다. 그래서 글 분량의 한도는 네가 지킨다.

## 어떻게 사용하는가? (How)

아래 순서대로 실행한다. 단계를 건너뛰지 않는다.

### 1. 읽는다

1. `slides/team-intro-editing-guide.md` 전체를 읽는다.
2. `slides/extra_template.json`을 읽는다.
3. 대상 폴더의 모든 `.md`를 읽는다. 읽은 파일의 목록을 적어 둔다.

### 2. 채운다

4. 대상 폴더마다 양식의 여섯 칸을 복사해 `slides/extra_사내용.json`의 배열 하나에 폴더 순서대로 이어 붙인다. 파일은 UTF-8(BOM 없음)으로 저장한다. 이미 있는 파일이면 새로 쓴다.
5. `⟨ ⟩`로 표시된 곳을 `.md`의 내용으로 바꾼다. `⟨ ⟩` 기호는 하나도 남기지 않는다. `after`, `kind`, `widths`, `tint`, 색 값은 바꾸지 않는다.
6. `notes`의 "근거:" 줄에 그 슬라이드의 내용이 나온 파일 이름과 절 제목을 적는다.
7. `deck`을 정한다. `deck`이 없거나 `"both"`인 슬라이드의 수가 "입문 deck에 넣을 장수"를 넘지 않게 하고, 나머지는 `"share"`로 둔다. 입문 deck에는 비전공자가 따라오기 쉬운 것(단서를 따라간 기록, REA가 돌려준 결과, 질문별 답)을 먼저 고른다.

### 3. 지킨다

- **`.md`에 적힌 것만 쓴다.** 근거가 없는 곳을 짐작으로 채우지 않는다.
    - 슬라이드 하나의 근거가 통째로 없으면 그 슬라이드를 지운다.
    - 표의 행이나 목록의 줄 하나만 근거가 없으면 그 행이나 줄을 지운다.
    - `draw_result`의 `rows` 4개와 `items` 3개는 개수를 유지하고, 해당 내용이 없으면 "기록에 없음"이라고 적는다.
- **등급을 바꾸지 않는다.** 관찰, 추론, 미확인은 `.md`에 적힌 그대로 옮긴다. 등급이 적혀 있지 않은 내용에는 등급을 지어내지 않는다. 그 행을 빼고 보고의 "확인 필요"에 적는다.
- **수치**(걸린 시간, 함수 수)는 `.md`에 있는 값만 쓴다.
- **가린다.** 장비 이름, 실제 파일 이름과 경로, 내부 시스템 주소, 사람 이름, 인증 정보를 적지 않는다. 도구는 별칭으로만 부른다. 디컴파일 코드는 설명에 필요한 몇 줄만 쓴다.
- **글 분량의 한도**(편집 지침 2절의 표)를 지킨다. 넘으면 문장을 줄이거나 같은 `after`, `kind`로 슬라이드를 둘로 나눈다.
- **문장 부호**: em dash와 가운데 점을 쓰지 않는다.
- **하지 않는 일**: `.py`, 공개 deck, 대상 폴더의 `.md`를 고치지 않는다. REA를 새로 실행하지 않는다. 커밋과 push를 하지 않는다.

### 4. 만든다

8. `slides` 폴더에서 실행한다.

    ```powershell
    cd reverse_engineering\slides
    python build_team_intro.py
    ```

9. 오류가 나면 `extra_사내용.json`만 고쳐서 다시 실행한다. 정상이면 아래 두 줄이 나온다.

    ```text
    NN slides -> re-rea-team-intro_사내용.pptx, .md, .bento.html  (git 제외, 올리지 않는다)
    +N slides -> re-rea-team-share_사내용.bento.html  (git 제외, 올리지 않는다)
    ```

10. `git status`를 실행한다. `_사내용` 파일이 보이면 안 되고, 공개 deck 파일이 "modified"로 보여도 안 된다. 대상 폴더가 "Untracked"로 보이면 보고에 적는다(`.gitignore`는 이름에 `_사내용`이 들어간 것만 제외한다).

### 5. 보고한다

아래 다섯 가지를 이 순서로 보고하고 끝낸다.

- **슬라이드별 표**: 도구 별칭, 제목, deck, 근거 파일과 절
- **지운 것**: 지운 슬라이드와 행, 그 이유
- **뽑은 자료**: 여섯째 칸에 넣은 자료의 목록, 그리고 후보였지만 뺀 것과 이유
- **확인 필요**: 사람이 판단해야 하는 것(등급이 없던 내용, 가릴지 애매한 이름, 한도 때문에 줄인 문장, 폴더와 별칭의 대응)
- **생성 결과**: 스크립트가 출력한 장수, `git status` 결과

사람은 보고를 읽은 뒤 `re-rea-team-intro_사내용.pptx`와 `re-rea-team-share_사내용.bento.html`을 열어 글이 넘치지 않는지 확인한다. 고칠 곳이 있으면 `extra_사내용.json`을 고치고 스크립트를 다시 실행한다.

## 배경 지식 (Context)

작업 중 판단이 필요할 때 참고한다. 위 지시와 어긋나면 위 지시가 우선이다.

### 환경

- 회사 PC는 Windows이고 셸은 PowerShell이다. 경로 구분은 `\`이고, JSON 안에서는 `\\`로 쓴다.
- 외부 인터넷과 외부 LLM API는 막혀 있다. 이 작업은 인터넷 없이 끝난다. 아래 참고 자료의 주소를 열려고 하지 않는다.
- 스크립트는 `python-pptx` 패키지를 쓴다. `ModuleNotFoundError: No module named 'pptx'`가 나오면 설치하지 않고 멈춘 뒤 보고한다. 회사 PC의 설치는 사람이 금지 목록과 라이선스를 확인한 뒤에 한다.
- 이 저장소는 GitHub 공개 저장소다. 이름에 `_사내용`이 들어간 파일만 git에서 제외된다. 그래서 사내 내용은 `extra_사내용.json`에만 적는다.

### deck 두 벌의 청중

| deck | 청중 | 분량 | 추가 슬라이드가 들어가는 방식 |
|---|---|---|---|
| 입문 deck (`re-rea-team-intro`) | 전기 공학, 컴퓨터 공학 전공이 아닌 팀원 | 본편 29장(60분), 부록 11장 | 관련 있는 공개 슬라이드 바로 뒤에 한 장씩 |
| 팀 공유 deck (`re-rea-team-share`) | 용어를 아는 팀원 | 23장 | 끝에서 두 번째 자리에 도구별로 묶어서 |

입문 deck용 슬라이드는 문장을 쉽게 쓴다. 새 용어가 나오면 `foot`에 한 줄로 푼다. 관찰, 추론, 미확인, Evidence, 커버리지는 공개 슬라이드(11장, 25장)가 이미 설명하므로 다시 풀지 않는다.

### 용어

| 용어 | 뜻 |
|---|---|
| 관찰 | REA가 직접 본 사실. 예: 어떤 함수가 어떤 문자열을 참조한다 |
| 추론 | 관찰을 묶어 내린 해석. 예: 그 함수가 저장 기능일 것이다 |
| 미확인 | 도구가 볼 수 없었거나 찾지 못한 것 |
| 한계 | 결과에 붙은 단서. 예: 간접 호출은 따라가지 못했다 |
| 커버리지 | 전체 중 어디까지 봤는지 |
| Evidence ID | REA 결과 한 건을 가리키는 이름. `.md`에 있으면 관찰 문장 끝에 붙인다 |

임포트 목록은 "호출할 수 있다"는 후보 단서이고 호출의 증명이 아니다. 디컴파일 결과는 추정이고 원본 소스가 아니다. `.md`가 이 둘을 관찰이라고 적지 않았으면 관찰로 올리지 않는다.

### 대상 폴더의 .md에서 찾을 곳

분석 기록이 `templates/investigation-log.md` 양식을 따랐다면 아래 절에서 찾는다. 양식을 따르지 않았으면 같은 뜻의 내용을 찾는다.

| 양식의 칸 | 분석 기록의 절 |
|---|---|
| 1 무엇으로 만든 프로그램인가 | 3. 대상 식별 |
| 2 실제로 보낸 프롬프트 | 2. 질문, 그리고 프롬프트를 적어 둔 곳 |
| 3 단서를 따라간 기록 | 4. 정찰 결과, 5. 정적 분석 경로 |
| 4 REA가 돌려준 결과 | 5. 정적 분석 경로, 6. 동적 확인 |
| 5 질문별 답과 등급 | 2. 질문, 7. 결론 |
| 6 팀원이 가져다 쓸 자료 | 모든 절. 프롬프트, 호출 순서, 막힌 곳을 적어 둔 곳 |

분석 기록의 "답함"은 관찰 근거가 있다는 뜻이고, "일부 답함"은 추론까지만 했다는 뜻이고, "미해결"은 근거가 없다는 뜻이다. 다섯째 칸(질문별 답)의 등급에는 이 표시가 아니라 `.md`에 적힌 등급(관찰, 추론, 미확인)을 쓴다. 표시만 있고 등급이 없으면 "확인 필요"에 적는다.

같은 내용이 여러 파일에 다르게 적혀 있으면 고르지 않는다. 둘 다 "확인 필요"에 적고 그 행을 뺀다.

### JSON을 쓸 때 자주 틀리는 것

- 주석과 끝 쉼표는 오류다. 지운 행의 앞 행 끝에 쉼표가 남지 않게 한다.
- 문자열 안의 큰따옴표는 `\"`, 백슬래시는 `\\`, 줄바꿈은 `\n`으로 쓴다.
- 굵은 글자는 `**글자**`로 쓴다. HTML 태그는 쓰지 않는다.
- 표의 모든 행은 `head`와 칸 수가 같아야 한다.
- 채운 모양의 예는 `slides/extra_example.json`에 있다.

### 스크립트 오류의 뜻

| 출력 | 원인 | 고칠 곳 |
|---|---|---|
| `채우지 않은 ⟨칸⟩이 남아 있다: 제목` | 그 슬라이드에 `⟨` 기호가 남았다 | 그 슬라이드를 채우거나 지운다 |
| `AssertionError: ('제목', kind, after, deck)` | `after`가 1~40 밖이거나 `kind`, `deck` 값이 틀렸다 | 양식의 값으로 되돌린다 |
| `json.decoder.JSONDecodeError` | JSON 문법 오류. 줄 번호가 함께 나온다 | 그 줄의 쉼표와 따옴표 |
| `KeyError: '항목'` | 그 kind에 필요한 항목을 지웠다 | 양식에서 그 항목을 다시 가져온다 |
| `FileNotFoundError` | `image` 경로의 그림이 없다 | 경로를 고치거나 그 슬라이드를 지운다 |

### 화면 캡처를 넣고 싶을 때

대상 폴더에 그림 파일이 있고 `.md`가 그 그림을 설명하고 있을 때만 넣는다. 그림을 `slides/img_사내용/`에 복사하고 `kind`가 `image`인 슬라이드를 추가한다(형식은 편집 지침 2절). 그림에 장비 이름이나 경로가 보이면 넣지 않고 "확인 필요"에 적는다.
