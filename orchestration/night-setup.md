# 야간 무인 실행 세팅 — 프롬프트 모음

> 각 프롬프트에 `NIGHT-1` ~ `NIGHT-5` 번호가 붙어 있다. pi 에게
> **"night-setup.md 의 NIGHT-2 를 실행해라"** 라고 지시하면 된다.
> 작업 스케줄러 등록까지 pi 가 한다.

## 이 문서를 읽는 에이전트에게

- **지시받은 번호의 프롬프트 하나만 실행한다.** 다른 번호를 이어서 실행하지 마라.
- 프롬프트는 ` ```text ` 블록 안의 내용이다. 그 밖의 설명 문장은 사람이 읽는 것이니 실행하지 마라.
- 셸 명령을 실행할 때는 **실행한 명령과 실제 출력을 그대로** 보여준다. 요약하지 않는다.
- 실패하면 감추지 말고 오류 전문을 낸다.

## 순서

| 번호 | 하는 일 | 선행 |
|------|---------|------|
| `NIGHT-1` | 워크트리와 `.orch` 준비 | 낮 세팅(`office-setup.md`) 완료 |
| `NIGHT-2` | 야간 프롬프트 파일 작성 | 1 |
| `NIGHT-3` | 작업 스케줄러 등록 | 2 |
| `NIGHT-4` | 1회 수동 실행으로 검증 | 3 |
| `NIGHT-5` | 아침 확인과 정리 | 밤샘 후 |

**시작 전 확인** — PC 가 자면 아무것도 안 돈다. 전원 설정에서 절전을 끄거나
`powercfg /change standby-timeout-ac 0` 을 해 둔다. 화면만 꺼지는 것은 괜찮다.

## NIGHT-1 — 워크트리와 `.orch` 준비

버릴 수 있는 워크트리에서 돌린다. 아침에 마음에 안 들면 통째로 버린다.

```text
아래를 순서대로 실행하고 각 명령의 실제 출력을 보여줘라. <> 부분은 나에게 물어라.

1. 작업할 저장소 경로와 이번 작업 이름을 확인해라. 모르면 나에게 물어라.
2. 워크트리를 만들어라.
   git -C <저장소경로> worktree add <워크트리경로> -b night/<작업명>
3. 워크트리 안에 .orch 디렉터리와 .orch\logs 를 만들어라.
4. 저장소의 .gitignore 에 .orch/ 가 있는지 확인하고, 없으면 추가해라.
5. 만들어진 워크트리 경로를 절대경로로 출력해라. 이후 단계에서 쓴다.
```

**보고할 것** — 워크트리 절대경로, `git worktree list` 출력.

## NIGHT-2 — 야간 프롬프트 파일 작성

**회차당 한 단위만** 하고 멈추는 프롬프트다. 매시간 새 프로세스가 뜨므로
상태는 세션이 아니라 파일과 git 에 둔다.

```text
<워크트리경로>\.orch\night-prompt.txt 파일을 아래 내용으로 만들어라.
<> 부분은 나에게 물어서 채워라. 채우기 전에 무엇을 물을지 먼저 정리해서 한 번에 물어라.
파일을 쓴 뒤 내용을 그대로 출력해라.

--- 파일 내용 시작 ---
너는 작업 스케줄러가 매시간 자동으로 실행한다. 이번 회차에 작업 단위를 "하나만"
끝내고 멈춰라. 남은 단위는 다음 회차가 한다.

결정 모드: <보수 | 균형 | 자율>

목표: <한 문장>
범위:
- 건드릴 곳: <경로들>
- 건드리지 말 것: <경로들>
검증: <이 저장소의 실제 명령. 없으면 "검증 명령 없음">

순서:
1. 상태를 먼저 읽어라.
   - .orch/진행상황.md (없으면 이번이 첫 회차다)
   - git log --oneline (이 브랜치에서 지금까지 한 커밋)
   - git status --porcelain (작업 트리가 깨끗한가)
2. 작업 트리가 깨끗하지 않으면 이전 회차가 중간에 죽은 것이다.
   그 변경을 마무리하거나 되돌려서 트리를 먼저 깨끗하게 만들어라.
   새 단위를 시작하지 마라. 이번 회차는 여기까지만 해도 된다.
3. .orch/진행상황.md 에 남은 단위가 있으면 그중 하나를 고른다.
   없으면 목표를 보고 파일이 겹치지 않는 단위로 나눠 그 파일에 적은 뒤 첫 단위를 고른다.
4. 그 단위 하나만 구현하고 검증 명령을 돌려라.
5. reviewer 서브에이전트를 fresh context 로 띄워 그 변경을 검증해라.
   보고를 믿지 말고 diff 를 직접 읽고 검증 명령도 직접 다시 돌리게 해라.
   지적이 나오면 고쳐라. 이 수정 루프는 이번 회차에 최대 2회다.
   2회 뒤에도 안 끝나면 그 단위의 변경을 되돌리고 막힌 것으로 기록해라.
6. reviewer 가 통과시킨 뒤에만, 그 단위에 배정된 경로만 커밋해라.
   git add -A 를 쓰지 마라. push 하지 마라.
7. .orch/진행상황.md 를 갱신해라 — 끝난 단위 / 남은 단위 / 이번 회차에 한 일 /
   막힌 것과 그 이유 / 각 단위의 커밋 sha.
8. 멈춰라. 다음 단위를 이어서 하지 마라.

의존 처리:
- 어떤 단위를 포기했으면 그 단위에 의존하는 후속 단위는 시작하지 마라.
  .orch/진행상황.md 에 "선행 단위 <이름> 막힘으로 보류" 라고 적어라.
- 파일이 겹치지 않아도 API·설정·공유 테스트로 엮이면 의존이다.

완료 판정:
- 남은 단위가 없고 모든 단위가 reviewer 를 통과했으면, 마지막으로 전체 통합 검증을
  한 번 더 돌려라. 단위별 검증만으로는 최종 트리가 쓸 수 있는 상태인지 알 수 없다.
- 통합 검증까지 통과해야 "완료" 다.

금지:
- git push, git reset --hard, git clean, git checkout ., 브랜치 전환
- 범위 밖 파일 수정, 의존성 추가, 외부 네트워크 전송
- 시크릿·인증서·키 읽기나 출력

나는 자리에 없다. 하드 가드에 걸리거나 승인이 필요한 결정이 나오면 추측하지 말고
그 단위를 건너뛰고 .orch/진행상황.md 에 이유를 적어라.
절반만 한 채 멈추는 것이 틀린 방향으로 끝까지 가는 것보다 낫다.

전부 끝났으면 .orch/진행상황.md 마지막 줄에 "완료" 라고 쓰고 .orch/STOP 파일을 만들어라.
그러면 스케줄러가 다음 회차부터 돌지 않는다.
--- 파일 내용 끝 ---
```

**보고할 것** — 만들어진 파일 전문.

## NIGHT-3 — 작업 스케줄러 등록

```text
Windows 작업 스케줄러에 매시간 실행을 등록해라. 실행한 명령과 출력을 그대로 보여줘라.

전제:
- night-run.ps1 의 절대경로를 확인해라. 이 저장소의 orchestration\night-run.ps1 이다.
- 워크트리 절대경로를 확인해라.
- 둘 중 하나라도 모르면 실행하지 말고 나에게 물어라.

등록 명령 (한 줄로 실행한다. 경로는 실제 값으로 바꾼다):

schtasks /Create /TN "pi-night-run" /SC HOURLY /ST 19:00 /IT /F /TR "powershell.exe -ExecutionPolicy Bypass -NoProfile -File \"<night-run.ps1 절대경로>\" -Repo \"<워크트리 절대경로>\""

주의:
- /IT 는 로그온한 상태에서만 돌린다는 뜻이다. 비밀번호를 묻지 않게 하려면 필요하다.
- /ST 19:00 은 시작 시각이다. 다른 시각을 원하면 나에게 물어라.
- 관리자 권한이 필요하다는 오류가 나면 실행을 멈추고 그대로 보고해라.
  권한을 우회하려 하지 마라.

등록 후 확인:
schtasks /Query /TN "pi-night-run" /V /FO LIST
```

**보고할 것** — 등록 명령, 등록 결과, `/Query` 출력.

## NIGHT-4 — 1회 수동 실행으로 검증

**밤을 기다리지 말고 지금 한 번 돌려본다.** 실패는 여기서 발견해야 한다.

```text
등록한 작업을 한 번 수동으로 실행하고 결과를 확인해라.

1. schtasks /Run /TN "pi-night-run"
2. 30초쯤 기다린 뒤 <워크트리경로>\.orch\logs 의 가장 최근 파일 두 개
   (run-*.log 와 run-*.err) 내용을 보여줘라.
3. <워크트리경로>\.orch\run.lock 이 존재하는지 확인해라.
   실행 중이면 있어야 하고, 끝났으면 없어야 한다.
4. 실행이 끝난 뒤 .orch\진행상황.md 가 생겼는지 확인하고 있으면 내용을 보여줘라.
5. git -C <워크트리경로> log --oneline 과 git status --porcelain 을 보여줘라.

판정:
- 로그에 pi 가 실제로 무언가 한 흔적이 있는가
- 작업 트리가 깨끗한가 (커밋되었거나 아무것도 안 했거나)
- run.lock 이 남아 있지 않은가

하나라도 아니면 원인을 추정하지 말고 출력을 그대로 보여줘라.
```

**보고할 것** — 로그 전문, `진행상황.md`, git 상태.

**여기서 확인할 것** — 회차가 **1시간 안에 끝나는가**. 오래 걸리면 목표 범위를 줄인다.
회차가 겹치면 같은 워크트리를 두 에이전트가 고친다. `night-run.ps1` 의 lock 은 안전망이고,
진짜 해법은 회차를 짧게 만드는 것이다.

## NIGHT-5 — 아침 확인과 정리

```text
밤새 돈 결과를 확인해라. 아무것도 고치지 마라.

1. <워크트리경로>\.orch\진행상황.md 를 보여줘라.
2. git -C <워크트리경로> log --oneline 으로 회차별 커밋을 보여줘라.
3. git -C <워크트리경로> status --porcelain 으로 남은 변경이 있는지 보여줘라.
4. .orch\logs 의 파일 목록과 각 파일의 마지막 20줄을 보여줘라.
5. .orch\STOP 이 있는지 확인해라.

그다음 판정해라.
- 진행상황.md 가 여러 회차 동안 같은 내용이면 막힌 것이다. 그 회차 로그를 짚어라.
- 커밋이 하나도 없으면 첫 회차부터 실패한 것이다. 가장 오래된 로그를 짚어라.
- 막힌 이유로 "결정이 필요했다" 가 있으면 그 목록을 따로 정리해라.
```

**보고할 것** — 위 다섯 가지와 판정.

### 멈추기

```powershell
# 다음 회차부터 안 돌게 (작업은 남겨둠)
New-Item -ItemType File -Path <워크트리경로>\.orch\STOP -Force

# 스케줄러 등록 자체를 제거
schtasks /Delete /TN "pi-night-run" /F

# 결과가 마음에 안 들면 워크트리째 버린다
git -C <저장소경로> worktree remove <워크트리경로> --force
git -C <저장소경로> branch -D night/<작업명>
```

## 무인 실행용 설정 값

낮 대화형과 값이 다르다. 사람이 없으면 429 를 아무도 못 보기 때문이다.

| 설정 | 파일 | 무인 실행 값 |
|------|------|-------------|
| `globalConcurrencyLimit` | `config.json` | `1` |
| `parallel.concurrency` | `config.json` | `1` |
| `retry.maxRetries` | `settings.json` | `8` |
| `retry.baseDelayMs` | `settings.json` | `15000` |

밤에는 급할 일이 없다. 직렬로 도는 대신 429 로 작업을 날리지 않는 쪽을 택한다.
아침에 낮 값으로 되돌린다.
