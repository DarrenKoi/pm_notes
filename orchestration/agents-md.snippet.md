# 작업 저장소의 `AGENTS.md` 에 넣을 것

> 빌트인 역할 4종은 모두 `inheritProjectContext: true` 다. **작업 대상 저장소**의 `AGENTS.md`
> (또는 `CLAUDE.md`)는 모든 자식 세션에 그대로 전달된다. 역할별 프롬프트를 따로 관리하는 것보다
> 여기 한 곳에 두는 편이 낫다 — 대화형이든 무인이든 항상 붙기 때문이다.

pm_notes 가 아니라 **에이전트가 일할 저장소**에 넣는다.

```markdown
## 에이전트 작업 규칙

### 범위
- 배정받은 파일 밖은 수정하지 않는다. 밖을 고쳐야 하면 고치지 말고 보고에 적는다.
- 요청하지 않은 리팩터링·추상화·설정 파일·의존성을 만들지 않는다.
- 여러 에이전트가 동시에 일할 수 있다. 내 단위 밖의 변경을 되돌리거나 덮어쓰지 않는다.

### 탐색 (scout 포함 모든 역할)
- 탐색은 **지정받은 경로 아래로 한정**한다. `find /`, 저장소 루트에서의 `find .`·`grep -r` 을 하지 않는다.
  루트 전체 탐색은 `node_modules`·`.git`·빌드 산출물까지 훑어 도구 타임아웃(`toolTimeoutMs`)을 그대로 태운다.
- 경로를 지정받지 못했으면 먼저 `ls` 로 최상위 구조만 보고, 대상이 있을 법한 디렉터리를 고른 뒤 그 안에서만 찾는다.
- `find`·`grep` 에는 항상 `.git`, `node_modules`, `venv`, `dist`, `build` 를 제외 조건으로 건다.
  가능하면 `rg` 나 `git ls-files | grep` 을 쓴다 — 둘 다 `.gitignore` 대상을 자동으로 건너뛴다.

### Git
- `git push`, `git reset --hard`, `git clean`, `git checkout .`, 브랜치 전환을 하지 않는다.
- 커밋할 때 `git add -A` 를 쓰지 않는다. 내 단위의 경로만 명시해서 올린다.
- 변경 확인은 `git add -A -N && git diff` 로 한다. 그냥 `git diff` 는 새 파일을 보여주지 않는다.

### 검증
- 검증 명령: <이 저장소의 실제 명령. 예: pytest, npm run typecheck, npm test>
- 돌리지 않았으면 돌렸다고 쓰지 않는다. 없는 명령을 지어내지 않는다.
- 실패하면 출력을 그대로 붙이고, 이번 변경 때문인지 원래 깨져 있었는지 구분한다.

### 보고
- 결론이 아니라 근거를 남긴다: `파일:줄`, 실행한 명령과 실제 출력.
- 확인하지 않은 것을 확인했다고 쓰지 않는다. 모르면 모른다고 쓴다.

### 리뷰
- 리뷰할 때는 상대의 보고를 믿지 않는다. 코드를 직접 읽고 검증 명령을 직접 다시 돌린다.
- 코드를 고치지 않는다. 지적만 한다. 스타일 취향은 지적하지 않는다.

### 보안
- `.env`, 인증서, 개인 키를 읽거나 출력하지 않는다.
- 사내 HCP 게이트웨이 외 외부 네트워크로 코드·로그를 보내지 않는다.
```

## 왜 `AGENTS.md` 인가

| 방식 | 대화형에 적용 | 무인에 적용 | 유지보수 |
|------|-------------|-----------|---------|
| 역할 파일 직접 정의 | 빌트인을 통째로 복제해야 함 | 같음 | 4벌 |
| 원샷 프롬프트에만 기술 | **안 됨** | 됨 | 1벌 |
| **작업 저장소 `AGENTS.md`** | **됨** | **됨** | **1벌, 저장소별** |

저장소마다 검증 명령이 다르므로 규칙도 저장소에 있는 편이 맞다. 원샷 프롬프트에는 그 실행에만
해당하는 것(목표·범위·결정 모드·보고 경로)만 남긴다.

## 주의

- 자식은 **스킬을 상속하지 않는다**(`inheritSkills: false`). 스킬에 의존하는 규칙을 쓰지 않는다.
- `AGENTS.md` 는 프로젝트 신뢰를 거절해도 로드될 수 있다. 신뢰하지 않는 저장소에서는 내용을 먼저 확인한다.
- 여기 적은 규칙은 **프롬프트 수준**이다. 강제가 아니다 — 실제 경계는 컨테이너/VM 이다.
