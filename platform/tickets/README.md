## 에이전트에게 티켓을 줄 때

티켓 파일 **하나만** 주고, 그 안의 "시작 파일"과 "설계 근거" 경로를 읽게 한다. 저장소 전체를 훑게 하지 않는다.
완료 보고는 티켓 하단의 양식으로 받는다.

---

## 의존성 순서

```
PLAT-L0-001 (저장소 스켈레톤)
   │
   ├── PLAT-L1-001 (ArtifactStore 계약) ── PLAT-L1-002 (MinIO 구현)
   │
   ├── PLAT-L5-001 (OIDC 토큰 검증) ─────────────┐
   │                                             │
   └── PLAT-L2-001 (카탈로그 스키마 계약)         │
          │                                      │
          └── PLAT-L2-002 (카탈로그 저장소)       │
                 ├── PLAT-L2-003 (상태 전이·불변성)
                 ├── PLAT-L2-004 (소유권 튜플·인가 판정) ── PLAT-L5-002 (FastAPI 결합)
                 └── PLAT-L2-005 (teams 스키마)
                        └── PLAT-L2-006 (Org Sync 배치)
                               └── PLAT-L2-007 (개편 유형 추론)
```

**실행 물결(wave)** — 같은 물결 안의 티켓은 서로 다른 디렉터리를 쓰므로 동시에 진행해도 충돌하지 않는다.

| 물결 | 티켓 | 성격 |
|---|---|---|
| **0** | `L0-001` | 단독 선행. 이것만 끝나면 나머지가 열린다 |
| **1** | `L1-001` · `L2-001` · `L5-001` · `L7-001` | **계약 확정.** 전부 병렬 |
| **2** | `L1-002` · `L2-002` · `L7-002` · `L7-003` · `L3-001` · `L6-001` · `L8-001` | 기본 구현과 2차 계약 |
| **3** | `L2-003` · `L2-004` · `L2-005` · `L3-003` · `L6-002` · `L6-003` · `L6B-001` | 계층별 핵심 로직 |
| **4** | `L2-006` · `L3-002` · `L5-002` · `L6B-002` · `L6B-004` · `L8-002` | 결합과 비동기 경로 |
| **5** | `L2-007` · `L3-004` · `L6B-003` · `L6B-005` | 상태·호출 경로 |
| **6** | `L8-003` | 최종 집계 |

**물결 1이 전부 계약 티켓인 것이 핵심이다.** 계약이 굳기 전에 구현을 병렬로 돌리면, 나중에 계약이 바뀌면서 여러 에이전트의 작업이 동시에 무효가 된다.

물결 안에서도 **소유 경로가 겹치지 않는지** 티켓의 "건드리면 안 되는 것" 절로 확인한 뒤 배정한다.
